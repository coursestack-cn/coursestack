# 数据库：组员3联调提案

数据库总体设计由组员1统筹。这里提供让组员3可以独立启动与验证的结构提案，尚未代表全组已经确定的正式表结构。正式接入时应协调命名、字段和既有迁移，避免在共享库重复建立账号或资料模块的表。

| 位置 | 用途 |
| --- | --- |
| `migrations/0001_shared_contract.sql` | 组员1/4模块的最小联调契约：用户、会话、学期、授课、修读、资料及版本 |
| `migrations/0002_member3.sql` | 课程、问答评论、投票、采纳、加分流水、举报、审查记录、事务事件与可见性视图 |
| `seeds/local.sql` | 虚构身份、两门课程、学期关系及文件版本元数据；仅用于本地 |
| `schema/index.ts` | 指向后端的 Drizzle 字段映射，便于组员1审阅、后续归并 |

SQL 迁移是本提案的运行依据，包含完整外键、CHECK、唯一索引、视图和触发器。Drizzle 字段映射不是独立迁移生成器，未用于 `drizzle-kit generate`；正式 Drizzle schema 和后续增量由组员1协调，需保留这些约束与触发器。

在 `backend/` 执行：

```powershell
pnpm db:migrate:local
pnpm db:seed:local
```

两条命令明确使用 `--env local --local --persist-to .wrangler/state`。重复迁移不会重建已有表；种子 `INSERT OR IGNORE` 保留个人修改。全部本地状态位于 `backend/.wrangler/state/`，已由根目录忽略规则排除。

## 关键约束

`contents` 按 `kind` 区分问题、回答和评论。回答必须属于同课程的可见问题；评论必须属于可见资料、问题或回答；回复必须属于同一评论目标。身份、类型、课程和目标关联不可通过编辑迁移。文件版本跨课程、下架或不存在时不能新建关联；旧版本不可用后讨论保留。

`votes` 使用 `(content_id,user_id)` 主键，单次值只有 `-1/1`；撤销删除自己的投票行。净赞数直接聚合，避免冗余计数漂移。

每个问题只存一个 `accepted_answer_id`。采纳通过带权限、可见性和 `revision` 条件的单条 UPDATE 完成。触发器在同一事务中写加分流水和业务事件，任一步失败整体回滚。删除/下架被采纳答案会更新问题并触发冲销；问题不可见时也取消采纳。

`bonus_ledger` 不允许 UPDATE/DELETE。奖励与冲销按 `(acceptance_id,operation)` 唯一，金额使用整数百分之一分；改分记录旧奖励冲销和新奖励，保留原学期。恢复内容不会自动恢复采纳。

`public_contents` 统一排除下架/删除内容，并检查回答、评论的上级可见性。普通列表、个人空间和内部搜索文档均使用该视图。

具体奖分、撤回及学期归属仍是业务提案，见[待确认规则](../docs/member3/联调与规则说明.md)。本地样例数据和迁移不能直接当作生产初始化脚本。
