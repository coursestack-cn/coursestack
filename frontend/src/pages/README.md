# 页面接入约定

页面地址以 [前端路由](../../../docs/前端路由.md) 为准。新增地址先登记文档，再在 `src/lib/router/routes.ts` 中登记路径、动态导入、登录要求和标题。页面放入相应模块目录，命名为 `<Name>Page.svelte`。统一管理页面和共享弹窗放在 `pages/manage/`，`ManageNav` 只向管理员显示账号管理、课程管理与学期设置切换。

## 页面属性与布局

- 页面接收 `PageProps` 中的 `params: Record<string, string>`。参数已按路径段解码；课程页面使用 `params.courseCode`，其他业务 ID 仍按不透明字符串处理。拼接链接和 API 路径时使用 `encodeURIComponent`。
- 普通页面根节点使用 `PageLayout`，它提供必需的 `h1`、可选 `subtitle`、`breadcrumbs`、`actions` snippet、`width="page" | "prose"` 和 `loading`。标题或面包屑要等数据返回后才知道名称时传入 `loading`，期间两者显示占位，避免先显示通用名称再替换；这类页面同时在路由中设置 `dynamicHeading: true`，路由出口在页面代码加载期间也显示占位，而不是路由标题。可用 `heading` snippet 替换默认标题区，但须提供一个 `h1`。不要再嵌套 `main` 或另建全局 Toaster。
- 课程主页、课程资料列表、课程问答列表和资料上传页在路由中声明 `layout: "course"`，由路由出口提供 `CourseLayout` 和 `CourseNav`。这些页面只渲染正文，不再嵌套 `PageLayout` 或重复查询课程信息；初始化时通过 `CourseLayout.svelte` 导出的 `getCourse()` 读取共享的课程资源。独立的提问表单仍使用自己的布局。课程名称作为唯一 `h1` 显示，管理入口只依据当前用户的服务端权限。
- 首页在会话确认后按登录态切换：未登录复用 `CourseListPage`，已登录使用 `MyCoursesPage` 展示本人的课程与动态，按账号 ID 重新挂载以隔离不同账号的数据。首页通过 `setTitle()` 更新浏览器标题。
- 路径变化时正文页面重新挂载；同一课程的页面切换保留课程布局、导航节点与课程数据，只有首次进入或更换课程时显示导航骨架。只变更查询参数或锚点时保留页面实例。

`CourseListPage` 通过 `GET /api/courses` 获取课程，搜索与分页参数见[前端路由](../../../docs/前端路由.md#查询参数)。卡片使用 `currentTeachers` 展示本学期多位教师的公开昵称，`offeredInCurrentTerm` 区分尚未开设与已开设但暂无教师，不据此推导管理权限。请求通过 `resource` 取消过期加载并保留刷新中的旧结果；页面覆盖空课程、搜索无结果、失败重试与页码超界回退。教师的“加入课程”和管理员的“新建课程”入口只负责导航，写入权限由对应接口校验。

`SearchPage` 通过 `GET /api/search` 获取全站结果；关键词、类型、课程、标签、排序和页码均由 URL 驱动。复用 `Tabs`、`Pagination` 与 `/api/courses` 课程选择器，筛选改变后回到第1页；请求取消并按查询键隔离旧结果，覆盖空关键词、校验错误、无结果、失败重试与页码超界。`HighlightedText` 只将服务器区间切为文本和 `mark`，不渲染 HTML；回答复用中转路由定位到详情锚点。数据与回填契约见[全站搜索](../../../docs/全站搜索.md)。

`MyCoursesPage` 的本学期和历年分类通过 `GET /api/me/courses` 获取本人修读或授课课程，收藏分类复用 `FavoriteList coursesOnly`，通过统一收藏接口读取。历史记录按课程去重并展示本人参与的学期；正式关系只有一个参与学期时直达学期页，多个历史学期或收藏课程进入公共页。`CourseFeed` 独立读取 `/api/me/feed`，范围为本学期关系与课程收藏的并集。分类和分页参数见[前端路由](../../../docs/前端路由.md#浏览)。

`FavoritesPage` 复用 `FavoriteList` 提供类型计数、课程筛选、取消与分页；`FavoriteButton` 用在课程、资料和问题详情中。`favorites.svelte.ts` 合并同次渲染的状态查询（每批最多 50 项），按账号与对象协调待处理操作，并用 BroadcastChannel 及焦点事件刷新。访客点击收藏进入带返回地址的登录页，登录后不自动执行收藏写入；不可用项只允许取消。服务端仍是收藏、权限与通知的最终依据。

`CourseLayout` 以课程号与可选路径 termId 读取 `/api/courses/:id/entry`，获取课程、所选学期教师、本人参与学期及 canManageContent、canManageCourse 两项权限。同一课程与同一学期上下文内切换不重复请求，更换学期重新加载布局，资料与问答筛选仅重载统一内容列表；当前用户变化时刷新课程资源，离开课程布局后释放资源。

```svelte
<script lang="ts">
    import PageLayout from "$lib/components/shell/PageLayout.svelte";
    import { router } from "$lib/router/router.svelte.js";
    import type { PageProps } from "$lib/router/types";

    let { params }: PageProps = $props();
    const sort = $derived(router.query.get("sort") ?? "active");
</script>

<PageLayout title="页面标题">
    <!-- 在这里实现页面内容；params 与 sort 均随路由变化。 -->
</PageLayout>
```

## 请求与页面状态

`api` 位于 `src/lib/api/client.ts`，仅接受 `/api/...` 相对地址，自动使用同源 Cookie。`get<T>(path, options?)`；其余 `post/put/patch/delete<T>(path, body?, options?)`。JSON 请求体自动序列化。`options` 支持 `signal`、`headers` 和 `rawBody`；传原始请求体时将 `body` 设为 `undefined`，按接口约定提供 Content-Type。不要同时传 JSON 和原始请求体。

成功返回响应中的 `data`；204 或正文为空（包括只有空白）的成功响应返回 `undefined`，无返回值的接口使用 `api.post<void>` 等类型。失败统一抛出 `ApiError`，含 `status`、`code`、`message`，其中 message 只用于调试。网络失败为 `0 / NETWORK_ERROR`，主动取消为 `0 / ABORTED`。请求不自动重试，也不自行跳页。

组件初始化时调用 `resource<T>((signal) => Promise<T>)`，从 `src/lib/api/resource.svelte.js` 引入。返回响应式 `status`、`data`、`error`、只读 `refreshing` 和 `reload()`。加载函数在第一个 `await` 前读取 `params` 或 `router.query`；Svelte 会跟踪这些依赖，变化时取消旧请求并重载。把 `signal` 传给 API 请求；组件销毁时同样取消，已过期的结果不会覆盖新数据。

首次加载为 `loading`。已有成功结果后重载时保留旧数据，`status` 仍为 `ready`、`refreshing` 为 `true`；成功后替换数据并结束刷新，失败则清空数据、结束刷新并进入 `error`，不让旧条件的结果冒充新条件的结果。路径变化重新挂载页面时，从首次加载开始。

```svelte
<ResourceState status={result.status} error={result.error} refreshing={result.refreshing} reload={result.reload}>
    {#if result.data}
        <!-- 成功内容 -->
    {/if}
</ResourceState>
```

`ResourceState` 首次加载延迟 200ms 显示进度，刷新时保留内容并设置 `aria-busy`。所有资源共用 `AppShell` 中固定在视口顶部的细进度条，不占布局高度；首次加载不再预留加载占位。并行加载全部结束或对应组件卸载后隐藏进度条。它将 401、403、404 映射为登录要求、无权限、页面未找到，其他错误通过 `userMessage` 展示前端文案与重试。401 的登录链接自动带回当前地址。问答页面通过模块内的 `ContentState` 将 `404 CONTENT_UNAVAILABLE` 映射为不可用状态；普通未知地址仍显示 404。

## 导航与页面标题

从 `src/lib/router/router.svelte.js` 引入：

- `router.route / params / query / hash / pathname / href / navigationId`：响应式当前地址信息。`hash` 保留开头的 `#`；`href` 包含路径、查询与锚点。将 `query` 视为只读，不直接调用它的 `set/delete`。
- `navigate(href, { replace?, scroll?: "top" })`：站内导航，返回 `Promise<boolean>`；取消离开时返回 `false`。
- `updateQuery(changes, { replace?, scroll?: "top" })`：保留路径与锚点，只更新指定查询参数。`null` 删除键，`undefined` 保留原值，字符串数组保留重复键。
- `setTitle(title)`：设置动态标题，自动附加 ` - 课栈`。在数据就绪后更新，并让 `PageLayout` 的标题与内容保持一致。

导航使用地址表中已登记的地址，不自行拼接未登记页面。优先使用通用组件的 `href`；路由在 `document` 上统一拦截同源链接。Ctrl、Meta、Shift、Alt、中键、新窗口、下载、API 和文件链接继续使用浏览器原生行为。通用组件无需导入路由。

以规范化后的 `pathname` 是否改变区分导航：路径变化才询问未保存内容，新页面回到顶部（带锚点时定位目标），渲染完成后默认聚焦 `h1`。顶栏搜索传入 `focusHeading: false`，保留提交时的焦点。首次加载不抢焦点。

只改查询参数时保留页面、滚动位置和焦点，不询问离开，也不覆盖动态标题。同页切换锚点时定位并聚焦目标；不可聚焦的目标临时设置 `tabindex="-1"`，焦点移出后移除，已有 tabindex 不改动。查询变化但锚点未变时不会重新定位该锚点。

前进、后退优先恢复目标历史项保存的位置，即使地址含锚点也不覆盖读者最后的滚动位置；只有路径变化才询问离开并聚焦新页 h1，同页历史切换不移动焦点。翻页等场景可调用 `updateQuery({ page: 2 }, { scroll: "top" })` 显式回顶，同页焦点仍保持；显式回顶优先于锚点定位。页面组件加载失败时由路由出口提供整页重新加载操作。

## 错误提示

界面只显示前端维护的文案，不能直接渲染 `ApiError.message` 或把它传给 Toast。请求客户端使用 `console.warn` 输出状态、错误码及后端原文，方便调试；主动取消不记录警告，也不展示给用户。

从 `src/lib/api/errors.ts` 引入 `userMessage(error, overrides?)` 和 `isAborted(error)`。默认文案覆盖网络、400、401、403、404、409、413、429、5xx 及无法识别的响应；未知错误也使用通用提示，不插入后端原文。

```ts
if (!isAborted(error)) {
    toast.error(userMessage(error, {
        STATE_CONFLICT: "内容状态已变化，刷新后重试。",
        429: "尝试次数过多，请稍后再试。",
        default: "保存失败，请稍后重试。"
    }));
}
```

覆盖优先级为错误码、状态码。`default` 覆盖该场景其余文案，但网络错误继续使用默认网络提示，除非显式覆盖 `NETWORK_ERROR` 或状态 0；`ABORTED` 始终忽略。文案说明发生了什么和怎么办，不用“请”、感叹号及面向用户的技术术语。

建号、重置密码、修改密码等表单先在前端检查输入，后端错误只作兜底。密码规则以[账号与权限](../../../docs/账号与权限.md#登录与会话)为准：自行改密的新密码为 8-64 个 Unicode 字符（按码点计数），界面提示“8-64 字符”；管理员建号与重置允许非空短密码，最多 64 个字符。登录与旧密码校验兼容旧规则下的已有密码。登录页保留统一的凭据错误文案，不向用户暴露密码规则或具体哪个字段不正确。

## 会话与权限

从 `src/lib/session.svelte.js` 引入 `session`，读取 `status`、`user`，调用 `login(schoolNumber, password, signal?)`、`adminLogin(password, signal?)`、`logout()`、`hasRole(role)`。App 启动时调用一次 `initialize()`。启动请求因网络或服务器错误失败时，身份仍保持待确认，`error` 暴露原因，`retry()` 可重试；不要把连接故障当成已退出登录。

个人设置通过 `GET /api/me/profile` 读取本人资料，身份、学工号、姓名、院系、专业、年级和最近登录时间只读展示。`session.changeNickname(nickname, signal?)` 只向 `PATCH /api/me/profile` 提交昵称，保存成功后同步当前会话中的昵称；完整学籍资料只保留在设置页。昵称去首尾空白，最多 80 个字符，留空保存为 null；未保存修改由统一离开确认保护。修改密码继续进入 `/settings/password`，成功后注销全部会话。

个人设置中的 `AvatarEditor` 负责选图、强制正方形裁切、上传和移除；只有确认裁切后才调用 `session.changeAvatar(blob)`，删除传 null。前端输出 512×512 PNG，通过 API 客户端的 `rawBody` 发送至 `PUT /api/me/avatar`，不发送原图或 FormData。图片处理与限制见[账号与权限](../../../docs/账号与权限.md#本人资料与头像)。上传失败保留裁切状态，成功后同步账号头像，不重新加载整份资料以覆盖尚未保存的昵称。

登录态只存在内存和服务端 HttpOnly Cookie 中，不读取或持久化令牌。头像地址为 `/api/profiles/:id/avatar`；头像组件同时传入 `accountId` 和 `src`，通过共享头像状态同步该账号的最新地址或删除状态，并更新地址版本以触发重新加载。`Avatar` 负责加载失败时的首字回退。已删除作者不传入 accountId，避免旧页面中的头像更新覆盖删除占位。

路由只按 `requiresAuth` 拦截匿名访问。角色仅用于入口展示，资源权限及操作权限仍由服务端验证。登录 `next` 使用 `src/lib/router/urls.ts` 中的 `safeNext()` 校验；登录页使用 `loginDestination()` 同时避免回跳到登录页形成循环。未授权响应会同步会话状态，但请求层不跳转页面。

## 未保存内容

组件初始化时从 `src/lib/router/leave.svelte.js` 引入并调用 `onBeforeLeave(callback)`。回调返回 `true` 表示可以离开，`false` 表示有未保存修改；路由统一使用 `ConfirmDialog` 询问，不在页面中重复创建对话框。注册项在组件销毁时自动清理，也可调用返回的函数提前注销。

```ts
onBeforeLeave(() => !dirty);
```

改变路径的站内链接、程序导航和前进后退均经过确认；同页查询或锚点变化保留草稿，不询问。关闭标签页、刷新和离开站点使用浏览器原生 `beforeunload` 提示，其文案和展示条件由浏览器控制。会话失效时的登录重定向立即生效。位于回答分页内的编辑和评论表单使用 `onBeforeLeave(callback, { samePage: true })`，在查询参数或锚点变化可能替换分页内容时也确认未保存修改；其他页面保持默认只检查路径变化。评论区收起后仍保留其表单。

## 内容 ID 与课程页

页面 URL 的 UUID 使用 32 位无横杠格式，生成路径和锚点时用 `lib/router/ids.ts` 的 `urlId`。路由匹配将 ID 参数转换回接口格式；手动解析锚点时用 `entityId`。内容视图的 DOM ID 同样使用无横杠格式，接口请求与业务比较继续使用 DTO 中的原始 ID。旧 URL 的规范化保留查询与锚点，不修改正文保存的历史链接。

课程公共页与 `/courses/:courseCode/terms/:termId` 共用 `CoursePage`，修读或授课学期下拉框改变路径；内容学期下拉框只改变查询参数。公共页默认全部学期，学期页默认路径学期，显式空 termId 可在学期页查看全部。学期详情读取失败时不回退到当前学期。历史页只展示加分历史入口，打开时预选路径学期，当前加分规则仍由公共页与当前学期页提供。

课程页从共享课程布局取得课程号，由 `CourseContents` 请求 `/api/courses/:id/contents`，统一显示资料与问答，共用标题、标签、发布人筛选和分页；发布人由 `CourseAuthorFilter` 调用 `/api/courses/:id/content-authors` 搜索及分页，默认“全部”，选择账号后以 authorId 写入网址，已选项独立查询回显，候选请求取消过期响应；只有 kind=question 提供解决状态和净赞数排序。`CourseNav` 显示课程名称和有权限时的管理入口；课程公共页与学期页在标题右侧横向显示修读（教师为授课）学期标签及下拉框，通过其中的“课程公共页”选项返回，不再另设公共页按钮。窄屏时这组控件换到标题下方，标签与下拉框仍横向排列。其他课程子页保留返回课程入口。

回答和评论锚点在内容加载后定位，目标不在首页时分页查找，取消旧请求；父级链由 /api/contents/:id 逐级读取。当前接口没有直接返回目标排名，长讨论的深分页定位会产生多次只读请求。问答与资料页使用同一定位逻辑，资料评论始终属于整份资料。

正文校验使用 shared/rich-text，编辑器绑定值为 null 或 onstatechange.valid=false 时不可提交。表单拒绝空白正文。问题、回答、评论和资料介绍支持 Markdown 图片、URL 和本地图片。提交时编辑器上传正文中的本地文件，并将二进制地址写入提交的 JSON。资料、问题和回答的评论共用精简工具栏，包含加粗、斜体、删除线、行内代码、链接、图片、代码块和公式。

点击评论的“回复”后，编辑器在目标评论下方展开，只显示“回复＋昵称”，不引用原文；再次点击同一条评论的“回复”收起回复框，普通评论与编辑评论仍使用列表底部的编辑器。回复框复用同一编辑器实例，排序、翻页及定位不清空草稿，目标不在当前页时暂回列表底部；收起回复框、切换回复对象或取消时沿用未提交内容确认。

## 教师主页

教师公开主页位于 `pages/teachers/`，使用 `/teachers/:teacherId`，教师 ID 保持原值。`TeacherPage` 并行加载公开头像昵称与五类 counts；`TeacherActivity` 只对当前选项卡请求 activity 分页，使用 kind 标识避免快速切换时混入上一类结果。选项卡数量来自 counts，已加载分类用分页 total 校正；无结果、失败重试和页码超界分别处理。

课程项显示授课学期；资料、问题、回答、评论均整项链接，不添加“查看讨论”操作。回答和评论使用服务端批量返回的 root 与 quote 展示一层上下文，不逐项请求原文，原引用不可用时显示占位。课程页教师名称及详情作者可进入教师主页；`AuthorSignature` 通过 linkTeacher 显式启用教师名称链接，已有整项链接中的作者保持不可点击以免嵌套链接。

## 问答接入

`pages/questions/` 的 `data.ts` 定义 DTO 适配、权限视图、分页定位和创建请求的幂等键。相同提交失败后重试复用键，改变请求内容或账号则更换；成功后清空表单。组件中的能力开关只控制入口，服务端继续授权。

详情页按当前课程入口的 canManage 控制采纳与下架，普通提问者不能采纳。问题评论与回答评论分别加载，删除评论保留有回复的占位。直接评论问题、回答或资料说明时不显示“回复某人”；评论之间的回复引用保留链接，在当前页面定位并短暂高亮目标。目标已在当前评论页时不重新加载列表，跨页或重复定位时由评论区查找目标页，保留页面、文件预览与评论草稿。

## 资料接入

`pages/materials/data.ts` 负责资料 DTO、无横杠 UUID 与上传申请适配。详情与表单按接口 permissions 展示操作，服务端继续鉴权。介绍可为空，文件名是所有版本共用的公开名称，原始文件名与存储键不参与公开路径。

资料介绍与问答共用 DiscussionBlock 和 ContentBlock。资料详情容器最大宽度为 1280px，左侧为文件卡和预览；文件卡显示文件名、类型、大小、版本、上传时间，在主色下载按钮左侧提供“在新标签页打开”，版本操作放在下方。介绍卡片位于评论区上方。宽度不小于 1024px 时，右栏宽度为 24rem，文件卡、预览、介绍和评论共用一个 sticky 双栏容器：顶部避开 65px 站点导航栏并留白 24px，底部留白 24px，高度为 100dvh 减去上述空间；两栏分别内部滚动，到达顶部或底部后继续同方向滚动时接续整页滚动，无需移动鼠标；边界接续由滚轮处理补足，栏内及嵌套可滚动内容仍优先使用原生滚动，横向滚动与带修饰键的滚轮操作保持原行为。资料页底部内边距同为 24px，保证滚到页面底部时容器仍完整可见。更窄时取消固定高度和 sticky，介绍与评论依次排在预览之后。介绍卡片通过通用组件的 showCommentsButton=false 隐藏“评论”按钮，下方评论区常驻显示。只有一个版本时不显示版本选择。版本切换保留评论区和草稿，历史版本分页加载。不存在的版本明确显示不可用，不自动替换。最后一个版本不可单独删除，页面解释应删除整份资料；其他版本可删除，版本号不复用。所有者删除内容根据服务端 canDelete 控制，管理者在审查页填写原因删除内容或指定版本。

上传适配器按单次尝试冻结资料信息和幂等键，通用上传控制器支持 pending 票据及 published 重放结果。每次只选一个文件，首次上传可用本地文件名预填资料文件名。PUT 只发送原始文件，浏览器负责 Content-Length；确认失败重试不会重复 PUT，已发布的申请重放直接进入详情，不再传文件。上传表单在可重试期间锁定原信息，移除后允许重新选择。

## 课程管理接入

`/manage/courses?new=1` 根据身份打开弹窗：管理员填写课程号、名称、简介创建长期课程，不要求当前学期或教师；教师只选择管理员已安排开设的当前学期课程，直接加入自己的教学班。当前学期未配置、空列表、请求失败分别反馈。创建或加入成功后清除搜索和页码，刷新列表。

管理员可以编辑课程名称和简介及安排开课；课程号只在新建时输入，普通编辑不能改号。管理员可以删除教学班，再撤销对应学期的开课安排。课程页“管理课程”和管理列表“教学班”进入 `CourseClassesPage`，教师只看到自己当前学期的班，管理员可以按学期筛选并查看历史班。

`CourseClassesPage`、`ClassStudentsPage` 和单门课程的 `CourseReportsPage` 使用独立的 `PageLayout`，面包屑按对象命名：“课程管理 → 课程名称 → 学期 · 教师”或“课程管理 → 课程名称 → 内容审查”，课程名称指向该课程的教学班列表。教学班列表以课程名称为标题、课程号为副标题，学生名单页以“学期 · 教师”为标题；两页在数据返回前显示标题与面包屑占位。层级导航只由面包屑提供，页首右侧只放作用于当前对象的操作；教学班列表另保留跳到课程公共页的“课程主页”。学生名单页按路径中的课程、学期、教师标识直接请求班级详情，无需列表临时状态；三个标识都保持接口原值，仅做路径段编码，教师账号 ID 不压缩或展开为 UUID。名单和积分流水分为两个选项卡（`tab=ledger` 打开流水，选项卡上显示各自总数），均使用完整表格，名单在操作前显示该学生在本教学班的净积分（totalPoints，无记录为 0）；添加学生、调整积分和六项加分规则使用小弹窗。三个列表每页 20 条，学期筛选及分页写入查询参数；学生名单使用 page，流水使用 ledgerPage，超出范围替换为最后一页。旧课程管理概览、名单路由由 `CourseManagePage` 替换跳转到教学班列表。

添加学生弹窗使用多行学号输入，支持从 Excel 复制一列，每行一个，忽略空行、去除首尾空白并显示重复数量；非空项超过500个时禁止提交。单个和批量输入均调用 `POST 班级路径/students/import`，学号保持字符串。结果显示新增、已在本班、失败及重复数量，失败列表展示学号与原因，可复制失败学号或通过“修改失败项”回到输入；成功及结果未确认时均刷新名单和班级人数。已在本班的跳过，跨教师冲突保留原归属，重复提交不重复添加。导入期间禁止再次提交和关闭弹窗，未提交输入参与离开保护。

积分调整对同一未确认请求复用幂等键，成功或结果未确认时同步刷新学生名单积分和积分流水，关闭弹窗重开前应核对流水。教师可移除本人当前班的学生。管理员在学生名单中为学生转班，在教学班列表删除整班，两项操作均支持历史学期。转班保留该次修读的积分与流水，移除学生或删班清除对应修读和积分。共享资料与讨论仍使用课程页面，不按教学班复制。

## 账号导入接入

`ManageAccountsPage` 页首提供“下载CSV模板”和“CSV导入”，使用 `AccountImportDialog`，不增加路由或查询参数。`shared/accounts/import.ts` 统一表头、字段规范化、CSV 解析与导出；模板只有表头，不包含会被误导入的示例账号。UTF-8 文件最多 2 MiB、500 条，解析后调用管理员预检接口，分页显示可创建、已存在、重复及错误行，密码不显示在预览表格。

确认后最多两个并发创建请求，每行固定请求键、密码和首次改密要求。遇到结果待确认时暂停派发并提供原请求重试；完成一轮后刷新账号列表。成功凭据和失败记录分别下载，失败文件可修改后再次上传；待确认项优先在当前弹窗重试，以恢复原请求凭据。明文密码只在内存中，关闭后清除；导入中禁止关闭，未下载成功凭据时关闭须确认，未处理行和未下载凭据参与离开保护。字段、权限及幂等约定见[账号与权限](../../../docs/账号与权限.md#csv-批量创建账号)。

## 学期设置接入

`/manage/terms` 使用独立的 `ManageTermsPage`，仅管理员可访问，管理导航选中“学期设置”。页面展示全部学期和当前学期状态，新建、重命名使用小弹窗，不新增子路由或查询参数；学期编号创建后不可修改。切换与清除当前学期直接在页面内操作，保留历史资料与积分。

读取使用 `GET /api/terms`，新建和重命名使用 `PUT /api/terms/:termId`，切换与清除使用 `PUT /api/terms/current`。写入后重新读取列表，请求失败保留表单并显示错误；前端校验编号、名称及新建时重复编号，写入权限仍由服务端校验。未保存的表单及待完成操作接入离开保护。课程管理页保留各课程的开设学期操作，不再提供全站学期设置弹窗。

## 所有者维护、审查与通知

`OwnedContentPanel` 展示私有内容、管理原因和维护操作。status 表示自身状态，isPublic 同时考虑所属祖先；编辑保持原状态。删除按钮服从服务端 canDelete，存在回答、评论或采纳时提示联系管理者。普通操作菜单只给所有者编辑和满足条件的删除，完整管理删除在内容审查页进行。

`CourseReportsPage` 在课程或全部授权课程中列出举报与内容；ContentReview 展示原文、审查文件及管理记录，支持上下架、连带删除及非最后版本的删除。举报 PATCH 以 action=none/hide/delete 原子处理，删除另有明确确认。奖励重算与撤回均由服务端完成。

`NotificationsPage` 展示互动、采纳、内容管理、收藏更新和他人操作产生的积分通知，默认未读，支持已读/全部筛选、每批20条加载更多及固定 ID 上限的全部已读。每次轮询合并第一批和已加载旧条目的当前状态，保留不可查看条目并隐藏标题；新通知超过一批形成空缺时提示查看最新。页头在其他页面只读取总数；通知页与页头共享当前标签页的数字，每个可见标签页独立每60秒轮询，账户切换时取消请求并清空旧状态。积分 toast 只展示 operatorId 等于本人产生的流水，收藏更新文案由 `notification-list.ts` 按事件类型生成；审查通知进入个人内容页，其余按服务端 href 跳转。
