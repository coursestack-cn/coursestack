## 课程、学期与教学班目标设计

本节记录 2026-11-02 确认并实现的设计。表结构、数据库规则、课程与教学班接口、演示脚本和管理页面采用同一契约；`0004_teaching_classes.sql` 在隔离测试库中验证，本次未应用到用户的本地持久库或远程数据库。

### 数据层实现与接续范围

- 已实现课程号主键、课程学期、教学班、学生唯一归属、教学班独立积分配置及流水班级外键；已移除旧 enrollments、course_bonus_rules 和课程 updated_by 字段。完整字段见下表。
- 数据库允许管理员建立无教师、无学期的课程；课程学期记录可没有教师。教师加入和学生新增关系要求当前学期、正确身份及已有父关系；班级身份不能直接改写。开设安排的管理员授权仍需由业务接口校验，不能仅靠外键判断请求身份。
- 默认积分配置随教学班创建；六项自动奖励按学生所属班级计算，转班携带原流水，撤回按原分值，上架恢复按内容原学期所属教学班的现行规则计算。当前教师共同管理与本人教学班管理已有独立权限表达式；现有积分查询、汇总和手工调分已接入班级范围，公开内容的教师标识已改读 teaching_classes。
- 迁移按旧课程 ID 到课程号映射内容、上传会话和流水，保留文件对象键、版本计数、上传草稿及租约、原流水 ID、金额和撤回链。旧课程最新积分规则复制到各既有教学班，不推测已丢失的历史规则版本。
- 旧成员身份不合法、某课程学期的教师缺失或不唯一、旧课程规则缺失时，迁移通过具名 CHECK 中止并回滚。旧模型未记录教师交接历史，回填依据现存授课关系；不能从课程学期之外猜测教师。
- 课程路由、教学班接口、资料课程号处理、演示脚本、测试夹具、OpenAPI 和前端消费者已同步到目标设计，不保留旧课程级规则或教师建课契约。迁移、后端及新前端须作为同一次集成发布；不能单独发布数据结构改动。

全量后端测试及浏览器联调覆盖完整迁移历史与源定义一致性、空课程与开设安排、多教师与学生排他归属、六项班级奖励、跨班采纳、权限隔离、学期切换、课程 ID 交叉映射、历史文件和积分保留，以及迁移前置失败和复制后的事务回滚。运行命令见[后端迁移说明](../backend/README.md#数据库结构与迁移)。

### 实体与约束

课程长期存在；管理员安排某课程在某学期开设；教师加入该课程学期后建立自己的教学班。教学班表示一位教师在一个学期内管理的该课程学生集合，不是行政班。当前范围内，同一教师在同一课程学期只有一个教学班。

下表列出本次调整的课程、成员和积分表的完整目标字段，不省略审计或请求幂等字段。主外键、权限和积分归属沿用已确认的方案；字段按本次反馈精简。

| 实体 | 完整目标字段 | 约束与用途 |
| --- | --- | --- |
| 课程 `courses` | `id`, `name`, `introduction`, `created_by`, `created_at`, `updated_at`, `request_key`, `request_hash` | id 直接使用课程号；移除原 UUID id、独立 code 及无业务依赖的 updated_by。管理员创建课程时无需指定教师或学期；保留 `(created_by, request_key)` 唯一约束 |
| 学期 `terms` | `id`, `name`, `current` | id 为主键；current 仅允许 0、1，全库至多一条 current=1 的记录 |
| 课程学期 `course_terms` | `course_id`, `term_id` | 联合主键 `(course_id, term_id)`；分别引用课程和学期。记录管理员确定的开设安排，可以尚无教师加入；不保存 created_by、created_at |
| 教学班 `teaching_classes` | `course_id`, `term_id`, `teacher_id` | 联合主键 `(course_id, term_id, teacher_id)`；前两列复合外键指向课程学期，teacher_id 引用 accounts.id。允许多个教师分别加入，每个教学班只有一位教师 |
| 学生归属 `class_students` | `course_id`, `term_id`, `student_id`, `teacher_id` | 联合主键 `(course_id, term_id, student_id)`；`(course_id, term_id, teacher_id)` 复合外键指向教学班，student_id 引用 accounts.id，确保学生不能跨教师重复归属 |
| 积分规则 `class_bonus_rules` | `course_id`, `term_id`, `teacher_id`, `points_question`, `points_answer`, `points_acceptance`, `points_comment`, `points_material`, `points_material_version` | 前三列为联合主键及教学班复合外键，与教学班一一对应；六项分值为非负整数，默认均为 0，创建教学班时同时初始化 |
| 积分流水 `bonus_ledger` | `id`, `course_id`, `term_id`, `teacher_id`, `student_id`, `delta_points`, `source_kind`, `source_id`, `operator_id`, `reason`, `reverses_id`, `request_hash`, `created_at` | 保留自增整数主键 id；新增 teacher_id，与 course_id、term_id 组成指向教学班的复合外键，记录该次修读所属的教学班，转班时同步更新 teacher_id。保留奖励来源唯一性、撤回唯一性和手工请求幂等约束 |

字段类型沿用当前约定：积分流水 id、reverses_id、时间、current 和分值为 INTEGER，其余字段为 TEXT。仅流水的 reason、reverses_id、request_hash 可为 NULL，其余上述字段均为 NOT NULL；courses.introduction 默认空字符串。流水的类型、金额、来源和撤回约束继续沿用现有规则。teacher_id、student_id、created_by、operator_id 引用对应账号；流水 reverses_id 引用原流水。

审计字段逐项取舍如下；不因“常规审计”默认增加字段，也不将有实际业务用途的字段一并删除：

| 字段 | 处理 | 依据 |
| --- | --- | --- |
| `course_terms.created_by`, `course_terms.created_at` | 不增加 | 开设安排由管理员维护，当前需求只需要课程与学期的对应关系 |
| `teaching_classes.created_at` | 不增加 | 当前不需要按加入时间排序、限制资格或计算积分 |
| `class_students.added_by`, `class_students.added_at` | 不增加 | 当前仅管理学生归属，没有名单变更审计或按入班时间计算的需求 |
| `class_bonus_rules.updated_by`, `class_bonus_rules.updated_at` | 不增加 | 当前没有规则修改记录需求；已发生积分由流水保存金额，不靠修改时间还原 |
| `courses.updated_by` | 删除 | 当前只记录最后修改人，没有权限、排序、供数或幂等逻辑依赖 |
| `courses.created_by`, `courses.request_key`, `courses.request_hash` | 保留 | 按请求账号划分幂等键并核对重试参数；created_by 不表示课程所有者 |
| `courses.created_at` | 保留 | 课程接口通过 `createdAt` 返回创建时间 |
| `courses.updated_at` | 保留 | 课程 DTO 和内容供数接口使用更新时间；迁移后仅随课程资料字段更新，不随教学班积分配置更新 |
| `bonus_ledger.operator_id`, `bonus_ledger.created_at` | 保留 | 记录实际积分操作者和发生时间；operator_id 还参与手工调分请求幂等，不能用所属班级的 teacher_id 替代 |

共享内容表和资料版本表保持现有字段，仅将课程引用切换为课程号。contents.course_id 仍指向长期课程，不增加学期或教学班归属；资料与问答跨教师、跨学期保留。流水引用教学班和学生账号。0012 迁移为修读关系添加触发器，转班时同步更新流水的教师归属，移除修读时清除该次积分及其通知。删除教学班会一并移除班级规则和剩余修读记录。

教师加入时，服务端同时校验教师身份、目标学期是当前学期、管理员已建立课程学期开设安排。加入不需要审核，重复提交返回已有教学班。学生名单导入校验已有学生账号和教学班归属，同班重复记录不重复添加，遇到其他教师的同课程同学期名单时报告冲突，不自动转班。并发重复由唯一约束兜底。

课程已开设但暂无教师，与课程本学期未开设是两个不同状态。DTO 和 UI 需分别表达开设状态与教师集合，不能用 `currentTeacher=null` 推断未开设；查询多位教师时须避免课程列表出现重复行或分页数量错误。

### 内容与教学班权限

- 管理员维护课程目录和课程学期开设安排，教师的操作入口为“加入课程”，不再向教师提供创建课程操作。
- 本学期加入该课程的教师共同管理整门课程的资料、问答、采纳和内容审查；共享管理范围包括该课程历年积累的内容。
- 教学班的学生名单、必要学籍信息、积分规则和学生积分独立管理。教师只能操作本人当前学期教学班，不能因同课共同管理身份获得其他班的名单、规则修改或手工调分权限。管理员可跨班操作。
- 学期结束不删除教学班、修读关系和内容。往届教师失去整门课程的管理权限，保留本人内容的作者权限；历史名单和积分由管理员管理。
- 课程开设状态不改变共享内容原有访问规则：游客可浏览共享信息，发布、互动和预览下载等继续按对应功能校验；加入课程任教、正式修读与课程收藏分别处理。

迁移后不再用单一的课程级 `canManage` 覆盖所有操作，至少分别校验课程共享内容管理、本人教学班学生管理、本人教学班积分管理、管理员课程及学期安排权限。

### 积分归属

六项自动奖励规则由每位教师按教学班独立配置。计分时，以获得奖励的学生在该课程、当前学期所属的唯一教学班选择规则；教师和没有正式修读关系的学生参与共享内容仍不自动计分。

例如：教师甲采纳了教师乙班级学生的回答，采纳作为共享内容管理操作允许发生；奖励按乙教学班的规则计算。甲不因此获得对乙班学生手工调分或修改乙班规则的权限。

学生转班只改变修读关系和该次积分流水的 teacher_id。每笔流水的编号、金额、来源、操作者、说明、时间、幂等键及撤回关系全部保留。原班停止统计该生，新班接收原净积分，后续奖励使用新班的规则。移除修读时删除对应流水和积分通知。跨学期恢复过的奖励保留其他学期的分值和流水编号，并接续到仍存在的上一笔记录。

### 界面与操作流程

- 管理员从“管理端”默认进入账号管理；课程管理中分别提供课程目录维护和按学期安排开设课程的操作。创建课程只填写课程号、名称和简介，不要求任课教师；开设安排由管理员选择课程与学期。
- 教师从“管理课程”查看本人的本学期教学班，通过“加入课程”弹窗查询管理员已开设的本学期课程。已加入项显示已加入，不再创建第二个教学班；其他教师已经加入不影响本人加入。
- 教师加入后进入本教学班的学生名单和积分配置；同一课程的资料与问答仍使用共享课程页面。班级操作区应明确课程、学期和所属教师，避免将本班配置误认为整门课程统一配置。
- 教师加入界面应区分没有配置当前学期、本学期没有已开设课程、搜索无结果或已经全部加入。未开设的旧课程仍可浏览已有内容，但不能从普通浏览页绕过开设安排加入。

## 课程、学期与成员

课程由管理员建立，`POST /api/courses` 只接受 `id`（课程号）、`name` 和可选 `introduction`。不需要当前学期，也不创建教学班。`PATCH /api/courses/:id` 仅管理员可用，只修改提交的名称和简介；课程号不提供普通改号接口。

课程 DTO 为 `id`、`name`、`introduction`、`currentTerm`、`offeredInCurrentTerm`、`currentTeachers`、`createdAt`、`updatedAt`。`currentTerm` 可空；开设安排由 course_terms 判断，不用教师人数推断。`currentTeachers` 为公开的 `{id, nickname, isDeleted}[]`，不返回教师学工号或学籍信息，不包含课程级积分规则。

`GET /api/courses` 支持 `q` 按名称或课程号搜索、`id` 精确过滤、`termId` 过滤已安排开设的课程，结果按课程号升序分页。课程路径直接使用经 `encodeURIComponent` 编码的课程号；不再通过 code 查询内部 UUID，也不压缩或展开课程号。

`GET /api/courses/:id/entry` 支持可选 `termId`，选择已开设的课程学期；无此安排返回 404，省略则为课程公共入口。响应新增 `term`（所选学期或 null）、`teachers`（所选学期教师，公共入口为当前学期教师）、`terms`（用于内容筛选的全站学期）及 `myTerms`（仅当前会话本人的修读或授课学期，游客为空）。原 course DTO 与内容管理权限含义不变。

### 学期、开课安排与教师加入

| 方法、路径 | 权限与行为 |
| --- | --- |
| `GET /api/terms` | 公开学期列表，当前学期优先 |
| `PUT /api/terms/:termId` | 管理员以 `{name}` 建立或重命名学期，termId 不可为保留字 current |
| `PUT /api/terms/current` | 管理员以 `{termId}` 原子切换当前学期，null 清除；不存在的学期返回 404，旧标记不变 |
| `GET /api/courses/:id/terms` | 公开该课程已安排开设的学期 |
| `PUT /api/courses/:id/terms/:termId` | 管理员安排开课，重复调用不新增记录 |
| `DELETE /api/courses/:id/terms/:termId` | 管理员可撤销任意学期的安排。有教学班时返回 409，先删除这些班即可撤销 |
| `PUT /api/courses/:id/terms/:termId/teachers/me` | 教师直接加入管理员已开设的当前学期课程；重复加入返回同一教学班；其他教师已加入不影响加入 |
| `GET /api/teaching-classes` | 教师仅查询本人当期教学班；管理员可查询全部。支持 courseId、termId 与分页 |

下文用 **班级路径** 指 `/api/courses/:id/terms/:termId/teachers/:teacherId`。路径中的身份是被管理的教学班，不是操作者；操作者只能来自会话。教学班详情 `GET 班级路径` 返回 courseId、termId、teacherId、course、term、teacher、studentCount、bonusPolicy。

`GET 班级路径/students` 返回分页的 studentId、nickname、status、schoolNumber、name、department、major、grade、totalPoints，只允许本人当期教师和管理员读取。totalPoints 汇总该学生在路径指定课程、学期、教师教学班的全部积分流水，包含奖励、扣分和撤回，无记录为 0，可为负数，不受名单或流水分页影响。`POST 班级路径/students` 接受 `{schoolNumber}`，仅匹配未删除的已有学生账号，加入当前学期教学班并返回 `{studentId}`。同班重复添加返回原归属；跨教师重复返回 409，不能覆盖或创建账号。查询和写入均在最终 SQL 中复核班级权限与当前学期。

`POST 班级路径/students/import` 接受 `{schoolNumbers: string[]}`，数组包含1–500项，请求体上限128 KiB。服务端去除首尾空白、忽略空项并按首次出现顺序去重，学号按字符串保留前导零；全空、类型错误或数组超限返回400。每个学号最多80字符，超长项逐项失败，其余项继续处理。权限与单个添加相同，教师只能操作本人本学期教学班，管理员也只能向当前学期教学班导入。

业务校验允许部分成功，HTTP 200 的 data 返回 addedCount、existingCount、failedCount、duplicateCount 和去重后的 items。每项包含 schoolNumber 和 status（added、existing、failed）；失败项另含 code 和 message。INVALID_SCHOOL_NUMBER 表示学号超长，STUDENT_NOT_FOUND 表示账号不存在、已删除或不是学生，STUDENT_ASSIGNMENT_CONFLICT 表示已属于同课程同学期其他教学班。同班重复跳过，跨班不转移，不返回其他班学生的身份资料。

权限、当前学期、批量写入及结果查询在同一事务复核，状态变化时返回409 CLASS_IMPORT_UNAVAILABLE，数据库异常整批回滚；并发与重试由现有修读关系唯一约束保证不重复添加。结果未确认时可安全重试，重试已成功写入的学号计入 existingCount。导入只建立修读关系，不创建账号、不回补历史积分，也不需要数据库迁移；前端使用新增批量接口，原单个添加接口保留。

| 方法、路径 | 权限与结果 |
| --- | --- |
| `DELETE 班级路径/students/:studentId` | 教师可从本人当前教学班移除学生，管理员可操作任意学期。清除该生此次修读、积分流水及对应积分通知。学生已转走时，旧班重复请求不会清除新班数据。 |
| `PUT 班级路径/students/:studentId/transfer` | 管理员提交 `{targetTeacherId}`，目标教师账号须未删除，且在同课程同学期已有教学班。返回 `{studentId, teacherId}`。已在目标班时重试成功，转到第三个班返回 409，目标班或修读已不存在返回 404。 |
| `DELETE 班级路径` | 管理员删除任意学期的教学班、规则及留班学生的修读和积分。需要交接时先转走学生，再删除原班。共享内容继续归课程。 |

管理员也可以查询历史教学班并给在册学生调分。教师只能访问本人当前学期的名单及积分。

### 本人的课程

`GET /api/me/courses` 只按当前会话账号的 teaching_classes 或 class_students 查询授课或修读关系，不接受指定他人账号。`scope=current|history` 默认 current，可选 q 去首尾空白后最多 100 字；过滤在服务端分页前完成，课程按课程号排序，同一课程在每个分类内只出现一次。

响应包含 items、page、pageSize、total、scope 与可空的 currentTerm，每项为 `{course, terms}`，terms 为本人参与的 `{id, name, current}` 学期记录。无当前学期时，本学期列表为空、历史关系仍可读取；管理员不会自动获得所有课程。收藏课程通过 `GET /api/me/favorites?type=course` 独立获取；首页动态按本学期关系与课程收藏的并集取数，见[收藏与动态](./收藏与动态.md)。

## 内容、文件引用与可见性

`contents` 统一保存 material、question、answer、comment，字段包括课程、发布学期、作者、标题、正文、标签、状态和时间。资料简介使用 body。回答以 target_id 指向问题；评论的 target_id 只指向资料、问题或回答。问题、资料的 target_id 为 null。评论的 reply_to_id 可空，自引用被回复的同评论区评论，仅表示回复引用，不参与所属级联；这样删除或下架评论不会影响其他评论。所属类型由目标记录的 kind 查询，不重复存储。

`contents.term_id` 引用 terms，可空，在首次发布的写入语句内读取当时的当前学期，接口以 `termId` 返回；资料以确认发布时为准，回答和评论各自记录发布学期，不继承父内容学期。编辑、追加资料版本、下架和恢复不改变此字段，客户端不能指定或改写。未设置当前学期时保留 null；0005 增量迁移不推测旧内容学期，原有记录为 null。所有内容仍归属长期课程，跨学期链接、访问与积分规则不变。

统一内容列表和问题列表支持 `termId` 精确筛选，在服务端分页前执行；省略表示全部学期（包含 null）。资料按首次发布学期筛选，不因新版本或后续讨论移动到另一个学期。前端学期页默认值见[前端路由](./前端路由.md#查询参数)。资料、问答及内部供数消费者需要接受新增的可空 termId；0005 迁移须先于新后端上线。

`target_id` 和 `reply_to_id` 均为不可改写的自引用外键。触发器校验所属类型、同课程、父级可见及回复目标属于同一个评论区。HTTP 响应的 targetKind/targetId 表示归一化后的所属对象，replyTo 表示回复目标。评论 POST 仍允许用 targetKind=comment 和 targetId 指定要回复的评论，服务端保存其所属对象并另存回复引用。GET 按问题/回答/资料查询整个同级评论区，按评论查询直接回复引用。示例：

```json
{
  "targetKind": "comment",
  "targetId": "父评论ID",
  "body": {
    "type": "doc",
    "content": [
      {
        "type": "paragraph",
        "content": [
          {
            "type": "text",
            "text": "正文"
          }
        ]
      }
    ]
  }
}
```

标签长度按 Unicode 码点计数，最多 8 个标签、每个 30 字；举报和管理理由选填，同样按码点计算，最多 1000 字，省略或留空时保存为空字符串，与前端控件一致。只有 question / material 可设置 tags 数组；空数组归一化为 null，回答和评论固定为 null，PATCH 省略 tags 则保持原值。

`contents.edited_at` 为可空 INTEGER（Unix 秒），默认 null 表示从未编辑。只有所有者通过 `PATCH /api/contents/:id` 实际修改 title、body 或 tags 时才写当前时间；省略字段、提交相同值均不改变它。比较采用校验后的 JSON 结构及字段值。赞踩、采纳、调分、上下架、删除及资料新版本均不改变 edited_at；updated_at 仍按相应操作更新。

公开内容详情、问答评论列表和个人空间的 `author` 返回 `id`、`nickname`、`avatarUrl`、`isDeleted`、`isTeacher`、`isCourseTeacher`。`avatarUrl` 为当前头像的同源 `/api/profiles/:id/avatar` 地址；未设置头像、账号禁用或删除时为 null，不暴露 R2 键。头像读取继续由账号模块校验；前端作者组件直接使用该字段，不逐项请求个人资料。

公开详情、列表、个人空间及删除占位统一提供以下元数据，内部内容详情沿用相同字段：

| 字段 | 约定 |
| --- | --- |
| editedAt | number 或 null；前端仅用 `editedAt !== null` 显示“已编辑”，不得从 updatedAt 推断 |
| replyTo | 回答返回所属问题摘要，评论返回回复目标摘要 `{ id, author: { nickname, isDeleted }, isDeleted }`；回复评论时该 id 与 targetId 不同。问题和资料为 null；作者删除显示“已删除”，内容删除与作者删除分别表示，不包含原文 |
| answerCount | 仅问题返回；统计仍可见的回答，与回答列表 total 一致 |
| commentCount | 问题、回答和资料统计其评论区的可见评论；评论本身统计直接回复引用，不递归计数。问题不合并回答评论区。列表 total 另包含有可见直接回复的删除占位 |

数据库 `contents.body` 为可空 TEXT，CHECK 为 `body IS NULL OR json_valid(body)`；删除占位另有约束，要求 title、body、tags 均为 NULL。发布和编辑接口的 body 必须是根节点 `type: "doc"` 的 JSON 对象，不能发送 Markdown、HTML 字符串或重复序列化的 JSON 字符串。后端写库时序列化，查询详情、列表、审查及内部内容接口时解析；公开内容的 format 为 `prosemirror`。

前后端通过 `shared/rich-text/index.ts` 共用严格的节点、标记与属性白名单。正文最多 30000 个语义 Unicode 码点，紧凑 JSON 的 UTF-8 大小最多 368 KiB，列表与引用沿祖先链累计最多 16 层；发布问题、回答、评论及编辑正文的请求整体最多 384 KiB。链接和图片均可使用完整 HTTP(S) 地址或安全的站内路径；详细格式与样例见[正文契约](../frontend/src/lib/rich-text/README.md)。PATCH 省略 body 保持原值；删除操作清空正文，其他元数据按现有删除流程保留或更新。

资料或版本引用保存在链接 mark 的 `attrs.href` 中，不建立内容与文件的数据库关系，地址格式与版本规则见[资料与文件](./资料与文件.md#内容与版本)。本地图片的上传、归属、读取权限和清理规则见[正文图片](./资料与文件.md#正文图片)。

| 状态 | 对外行为 |
| --- | --- |
| visible | 按权限正常读取与操作 |
| deleted | 清空 title、body、tags，保留标识、归属、状态、时间及幂等信息，不可恢复。沿所属树连带删除回答、评论与资料版本；评论回复引用不参与级联 |
| hidden | 保留正文并关闭所属分支的公开入口。子对象自身状态保留，因此父对象上架不会覆盖对子对象单独作出的下架决定；所有者仍可私下维护，但删除继续受讨论及采纳条件约束 |

`/api/contents/:id` 对已删除评论返回占位。已删除的问题、资料、回答及其下内容，以及自身或祖先为 hidden 的内容，均返回 `404 CONTENT_UNAVAILABLE`，`/api/questions/:id` 同理；例外是未删除内容的所有者仍可读取自己在隐藏分支中的内容，不因此获得读取其他作者内容的权限。评论列表按时间平铺，已删除评论只在其下仍有可见回复时以占位出现。公开列表、搜索、动态和文件访问须遵循相同状态；下架恢复后重新检查子分支。

资料的编辑、删除、赞踩、举报和下架复用 contents 通用接口；上传、版本与文件访问见[资料与文件](./资料与文件.md)。

## 投票与内容管理

资料、问题、回答和评论均允许赞踩，每人每项至多一票，可切换或撤销，不允许自投，重试不累加。投票接口不按内容类型限制，只允许对公开可见内容操作。资料投票以整份资料为对象，不按文件版本区分。采纳答案置顶，其余按净赞数和稳定顺序排序，教师身份不改变排序。

`votes.created_at` 记录投票行的创建时间；切换赞踩或重复提交保持原时间，撤销会删除该行，重新投票产生新的创建时间。

内容所有者是 author_id 对应账号，仅所有者可以编辑正文和上传版本。所有者 DELETE 要求没有未删除的所属回答或评论、且没有采纳关系；隐藏讨论也算存在，回复引用不算子对象。DTO 的 canDelete 给出当前所有者是否可直接删除。管理者是本学期课程的任一任课教师或管理员，跨教学班共享采纳、举报审查、上下架及完整删除权限，但不能编辑别人的正文或上传版本。管理者删除走 moderation 接口，原因选填，仍须满足最后版本不能单独删除的结构约束。学籍、班级规则和手工调分继续按教学班授权。

下架保留所有者编辑权限，删除使用同一组讨论与采纳限制；上级内容下架时，所有者仍可维护自己的未删除内容。所有者通过外部沟通联系管理者复核。管理者通过 `/api/moderation/contents` 分页查看内容；hidden 筛选包含因祖先下架而不可公开的内容，visible 只返回实际公开内容。`/api/moderation/contents/:id` 提供原文、上下架与删除记录；`/api/me/contents/:id` 供所有者查看自己的内容和管理原因，已删除原文不可恢复。

举报 PATCH 接受 `{action: "none" | "hide" | "delete", resolution}`，resolution 选填。none 保持内容状态并将举报记为 dismissed；hide 在同一事务下架、撤分、写入管理记录并记为 resolved；delete 在同一事务连带删除、撤分、写入管理记录并记为 deleted。已删除内容只可维持现状。直接管理接口接受 hide/restore/delete 及可选 reason，均写入管理记录；删除不可上架恢复。

管理记录触发所有者站内通知，不暴露举报者；未填写原因时不显示原因。管理者下架、上架或连带删除时，为分支内受影响的每个内容记录事件，从而通知各自所有者。下架和上架跳过已被单独下架的子内容及其下内容；子内容的这类记录只表示所属分支被处理，其自身状态不变，因此上级上架不会覆盖单独下架的决定。`moderation_actions.version` 为可空 INTEGER：非空表示被删除的资料版本号，保留它是为了在版本行和文件删除后仍能显示审查依据，故不外键关联已删除版本；null 表示整项内容操作。统一通知接口和已读状态见[站内通知](#站内通知)；旧 `moderation_notification_reads` 仅为迁移兼容保留，不再写入新回执。收藏事件复用统一通知表，见[收藏与动态](./收藏与动态.md)。

## 采纳与加分

当前课程教师或管理员可采纳、取消、更换答案，管理员可跨课程采纳、取消和调分；每个问题同时至多一个采纳答案，提问者身份不授予采纳权限。

积分按“课程、学期、教师、学生”保存和汇总整数分，与成绩无关，由教师说明折算标准。配置和名单均以教学班为单位，见[积分归属](#积分归属)。

| 项目 | 模型与规则 |
| --- | --- |
| 班级配置 | `class_bonus_rules` 以 course_id、term_id、teacher_id 为联合主键并引用教学班；points_question、points_answer、points_acceptance、points_comment、points_material、points_material_version 均为非负整数，默认 0；加入教学班时自动建立规则记录，0 表示该项不奖励 |
| 自动奖励 | 按操作发生时的当前学期及学生唯一所属教学班的配置判断；教师和未正式修读的学生可参与，但不自动加分；没有当前学期时不产生自动积分 |
| 奖励叠加 | 回答奖励与采纳奖励独立。例如回答 +25，采纳再 +50；取消采纳只撤回 50 |
| 资料奖励 | 文件版本记录插入时奖励上传者，资料元数据本身不奖励；首次上传（版本 1）仅加 points_material，后续每个新版本仅加 points_material_version，两项分别计分 |
| 采纳关系 | `acceptances` 以 question_id 为主键，保存 answer_id、operator_id、created_at；不存积分，contents 不包含采纳或奖励字段 |
| 流水 | `bonus_ledger` 保存课程、学期、教师、学生、delta_points、来源、操作者、可空 reason 和时间。转班仅变更教师归属，移除修读时清除该次流水 |
| 撤回与恢复 | 删除、下架或取消采纳撤回对应奖励；上架按内容原学期的教学班规则重算；取消后重新采纳同一回答仍按原记录恢复。reverses_id 关联上一笔状态变更，同一笔只能接续一次 |
| 手工加减 | 指定教学班、班内学生及非零整数增减值，reason 可省略或为 null；可为负分，独立于自动奖励，不随内容上下架撤回 |
| 一致性 | 原始奖励对来源唯一；内容或采纳状态、奖励流水同事务提交或回滚；幂等键防止手工调分重试重复记账 |

修改规则本身不追溯。删除或下架撤回受影响所属分支（回答、评论、采纳及资料版本）的全部自动奖励，手工调分保留；评论回复不是所属分支。上架只重算重新公开的来源：每条内容使用自身 term_id，采纳使用答案的 term_id，文件版本使用资料的 term_id；学期结束也记回原学期，按该学期学生所属教学班的现行规则计算。缺少 term_id 的旧数据只在原奖励能证明学期时使用该学期。规则为0则不发分；仍下架的子对象不恢复，重复上架不重复记账。

取消后跨学期重新采纳同一答案仍恢复已有奖励的原学期。删除父对象会连带删除其所属子对象并撤回全部相应自动奖励；已因下架撤回的奖励不再重复扣除，也不会因删除而补回。

下架仅暂停采纳的公开可见性，`acceptances` 行保留；问题或被采纳答案删除时移除采纳关系。公开 DTO 的 acceptedAnswerId、solved 和 isAccepted 从可见采纳关系计算。

流水的 sourceKind 为 question / answer / acceptance / comment / material / manual；sourceId 分别为内容 ID、被采纳答案 ID、`materialId@version` 或手工请求幂等键。来源 ID 不设外键，文件版本物理删除后仍保留原流水和撤回记录。版本删除使用 updated_by 归属操作者；删除接口在同一 batch 先设置 updated_by 再 DELETE。

自动积分的 reason 为 null，展示说明由 sourceKind、sourceId、deltaPoints 和 reversesId 渲染。sourceKind=manual 表示手工调整；其他来源中，reversesId=null 表示原始奖励，非空且 deltaPoints<0 表示撤回，非空且 deltaPoints>0 表示恢复奖励。撤回追加原分值的相反数，上架追加重新计算的正值（可与原金额不同），不改写旧流水；reversesId 保证同一笔只接续一次。手工调整可附加说明，省略 reason 与显式 null 等价；提供文本时为 1–500 字符。流水和汇总仅本人或授权教师、管理员可读。账户删除或身份切换保留原 ID 的采纳和流水，不自动冲销，也不转给新身份。

| 方法、路径 | 输入或返回 |
| --- | --- |
| `PUT 班级路径/bonus-policy` | pointsQuestion、pointsAnswer、pointsAcceptance、pointsComment、pointsMaterial、pointsMaterialVersion 六项整数规则；教学班 DTO 返回嵌套 bonusPolicy |
| `PUT /api/questions/:id/acceptance` | 仅 answerId，null 表示取消；返回内容详情及 changed，不接收分值 |
| `POST 班级路径/bonus-adjustments` | studentId、deltaPoints，以及可选 reason，须带 Idempotency-Key；201 返回该笔流水；历史学期仅管理员可调整 |
| `GET 班级路径/bonus-ledger` | 本人当期教学班教师或管理员读取，支持分页 |
| `GET 班级路径/bonus-summary` | 同权限；按 studentId、termId、teacherId 返回整数 totalPoints 和可空 nickname |
| `GET /api/me/bonus-ledger` | 本人流水，可按 courseId、termId 筛选；返回分页记录及筛选范围内的 totalPoints 净积分 |
| `GET /api/me/bonus-policy?courseId=课程号` | 仅学生读取本人当前学期的规则；返回 courseId、可空 currentTerm、可空 membership（公开 teacher 与 bonusPolicy），不返回班级名单 |
| `GET /api/me/bonus-events` | 本人积分增量；省略 afterId 只返回当前游标，携带非负整数 afterId 后按流水 ID 升序读取；pageSize 默认 20、最多 50，返回 items、nextCursor、hasMore |

流水响应包含 id、courseId、termId、teacherId、studentId、studentNickname、deltaPoints、sourceKind、sourceId、operatorId、reason、reversesId、createdAt。教师调分统一使用 `bonus-adjustments`。规则修改只写该教学班的配置，不改课程元数据或历史流水。完整请求和响应见 OpenAPI。

个人流水与积分增量额外返回 courseName、termName；totalPoints 汇总全部匹配记录，不能用当前页求和代替。三个本人接口均以会话账号为准，不接受切换查询对象；未正式修读或未配置当前学期时，规则接口返回空归属，不猜测其他教师的规则。学生仍可查询原有历史流水。

课程简介的“加分规则”弹窗展示本学期本人教学班的六项规则；同一区域的“加分历史”按钮打开本人历史弹窗，支持学期筛选和每页 10 条记录。来源区分首次上传、新版本、采纳、手工加减及撤回、补回，手工说明和发生时间一并保留。

学生会话在可见页面每 15 秒读取积分增量，重新聚焦或恢复联网时立即检查。自动奖励、手工调整、撤回与补回共用积分流水；只有 `operatorId` 等于本人时才产生积分 toast，同次读取的同课程、同学期变动合并展示，点击“查看历史”打开对应课程与学期的历史弹窗。他人操作的流水仍推进游标并刷新历史，但通过站内通知提醒。首次在该浏览器访问时只记录当前位置，不弹出所有旧积分；后续使用按账号隔离的本地游标续读，存储不可用时退回当前页面内存。支持 Web Locks 的浏览器协调积分增量读取，退出或切换账号会取消在途请求并移除原账号提示。此游标不表示跨设备已读状态，也不修改站内通知的已读状态。

站内通知复用积分流水 ID 作为去重来源，积分与对应通知在同一事务提交。采纳或管理通知与积分通知分别保存；收藏通知使用内容事件去重，不产生课程加分。积分计分规则和流水结构不变。

## 站内通知

`notifications` 保存自增 `id`、接收者 `account_id`、操作者 `actor_id`、类型 `kind`、来源 `source_id`、可空 `content_id`、可空 `event_id`、`created_at` 和可空 `read_at`。按接收者和 ID 建立索引，并为未读、已读筛选分别建立部分索引。`(account_id, kind, source_id)` 唯一，重试不重复产生通知；`(account_id, event_id)` 额外保证同一内容事件最多通知一次；业务变动与通知由数据库触发器原子提交。

| kind | 接收者与来源 |
| --- | --- |
| answer / comment / reply | 新回答或评论所属内容的作者，以及被回复评论的作者；同一接收者只发一条，回复优先；source_id 为 event:加内容事件 ID，event_id 指向 content_events；迁移前通知保留原来源 |
| accepted / unaccepted | 答案作者，不依赖是否有积分；每次实际采纳变更独立生成内容事件，取消后重新采纳仍是新事件 |
| moderation | 管理事件对应内容的作者；source_id 为 moderation_actions.id；所属级联每项内容一条 |
| favorite | 收藏问题的新回答、采纳变化及收藏资料的新版本；与直接互动按同一事件去重，直接互动文案优先 |
| bonus | 发生积分变化的学生，且 operator_id 不等于该学生；source_id 为 bonus_ledger.id |

新事件排除操作者本人和已删除接收者。收藏更新仅覆盖问题新回答、采纳变化和资料新版本，不包含编辑或评论；取消收藏只停止后续通知，不补发历史事件。组员 1 协调表、索引和迁移；组员 3 的内容、采纳、管理及积分写入通过触发器接入；组员 4 维护通知查询及收藏事件去重；组员 2 使用下列接口。后续新增通知类型需要同步表约束、DTO、OpenAPI 和前端文案。

| 方法、路径 | 输入与返回 |
| --- | --- |
| `GET /api/notifications/count` | 返回 viewer 和 unreadCount，供非通知页轮询 |
| `GET /api/notifications` | status=unread/read/all，默认 unread；pageSize 默认且最多 20；beforeId 为上一批 nextCursor；返回 viewer、items、unreadCount、nextCursor、hasMore、readThroughId |
| `GET /api/notifications/state?ids=1,2` | 每次 1–20 个 ID，只返回当前账号拥有的条目及当前阅读状态、可见性，不受列表筛选限制 |
| `PUT /api/notifications/:id/read` | 幂等写入首个 readAt，返回 id、read、readAt、unreadCount；不能标记他人的通知 |
| `PUT /api/notifications/read` | 请求 `{throughId}`；只标记该账号 ID 不大于上限的未读项，返回 throughId、changed、unreadCount |

列表按通知 ID 降序读取，ID 同时用于同秒事件的稳定游标和“全部已读”的固定上限。点击“全部已读”时取当前已显示列表的最大 ID，包含此前尚未加载的未读项，之后到达的事件不受影响。仅加载列表不视为已读，标记已读不删除记录。旧页码参数不再适用，完整 DTO 见 OpenAPI。

通知不保存标题或正文副本。每次读取都检查当前内容与祖先可见性；无权查看时返回 available=false、title=null，普通内容链接为 null，通知仍保留并计入未读。所有者可通过私有入口查看未删除的隐藏内容，管理通知跳转所有者维护页；积分通知跳转对应课程、学期的加分历史。status 表示当时管理事件结果，contentStatus 和 isPublic 表示当前自身及实际公开状态：子内容解除下架限制但祖先仍隐藏时，文案不能声称已经公开。

通知页每次轮询都获取第一批，并分批复查已加载旧条目；未读总数不变也更新，例如一条新通知与另一条已读同时发生。新到达条目超过一批、与当前列表间存在未加载区间时，提示“查看最新”重新加载，不跨过空缺直接拼接。每个可见标签页独立每 60 秒轮询，恢复可见、聚焦或联网时补查；通知页外只读总数。标签页间不传递通知状态、不共享通知缓存，其他标签页和设备在下一次轮询更新。退出或换账号复用现有会话同步，取消在途请求并清空当前账号的通知状态。

`0008_notifications.sql` 将旧管理事件和已读回执迁入统一表，保留管理通知 ID 与 readAt；旧回执表保留，但所有新读写走 notifications。不回放历史回答、评论、采纳或积分。新接口依赖该迁移，需与前端一起更新。

## 接口通用约定

- 内容写请求上限 384 KiB，其余讨论 JSON 上限 128 KiB。响应格式与同源要求见[请求与联调](./架构与开发.md#请求与联调)。
- 创建课程、内容或举报返回 201 与 `{data: {id}}`，Location 指向详情；手工积分调整返回 201 与该笔流水。
- 课程、内容、举报创建及手工积分调整须带 8–100 位 `Idempotency-Key`，同一键重试须保持请求内容一致；课程与内容创建在数据库中记录 request_key / request_hash。课程、内容编辑按最终写入顺序生效，PATCH 只覆盖提交字段；删除内容不需要请求体。
- 普通列表为 `{data: {items, page, pageSize, total}}`，默认每页 20、最大 50；时间为 Unix 秒，学期字段为 termId。
- 作者使用可空 nickname、isDeleted；教师与本课程教师标识独立，已删除作者的教师标识为 false。公开 DTO 不包含学籍、会话、请求指纹或奖励内部字段。
- 课程入口的 `permissions.canManageContent` 和 `permissions.canManageCourse` 分别控制内容与课程元数据操作；教学班权限单独校验，不能从共同内容管理权限推导，最终权限由服务端决定。会话快照及在途写入规则见[请求准入与权限](./账号与权限.md#请求准入与权限)。

## 搜索与内容供数

`/api/internal/*` 使用独立 Bearer 凭据 `INTERNAL_API_TOKEN`，至少 24 字符；未配置或过短返回 503，普通会话不能访问。本地参考 `backend/.dev.vars.example` 配置被忽略的 `.dev.vars`，云端使用 Worker Secret。该凭据不放入前端，与 Cloudflare 管理 Token 分开。

| 接口 | 契约 |
| --- | --- |
| `GET /api/internal/documents` | 分页读取当前可见课程、资料、问题和回答；返回 items、nextCursor、hasMore |
| `GET /api/internal/contents/:id` | 复查当前可见性，不可用返回 `{data: {id, available:false}}` |

文档分页每页读取当时的可见数据，不提供跨页一致快照、增量变更或事件重放，分页期间可能发生新增、修改和删除。公开[全站搜索](./全站搜索.md)已由 `GET /api/search` 直接查询 D1，不经过内部供数接口，也不向浏览器提供内部凭据；已接入的通知范围见[站内通知](#站内通知)，收藏通知与首页发布动态见[收藏与动态](./收藏与动态.md)。

文档中，课程简介的 body 为普通字符串、format=text；资料、问题和回答的 body 为 ProseMirror JSON 对象或 null、format=prosemirror。搜索提取节点的 text 字段，不把序列化 JSON 当作正文全文。展示和跳转仍须检查当前内容及祖先可见性。

`GET /api/courses/:id/activity` 直接查询当前可见内容，每项内容出现一次，按 updatedAt、contentId 降序排列，返回 contentId、kind、title、createdAt、updatedAt。下架内容及其子分支、已删除内容及已删除问题、资料、回答之下的内容均不出现在列表；个人空间查询本人未删除的内容，包含下架内容和受上级状态影响的私有内容，以 status 和 isPublic 区分。
