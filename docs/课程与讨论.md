# 课程与讨论

当前后端提供课程、问答评论、赞踩采纳、加分、举报审查、本人动态以及当前可见文档供数接口。源码分别位于 `backend/src/courses/`、`discussions/`、`moderation/`、`integration/`；启动与检查见[后端开发说明](../backend/README.md)。

接口参数与响应见仓库根目录的 [OpenAPI](../openapi/openapi.json)，它是前后端共用的接口契约，同时覆盖资料接口；账号接口见[账号与权限](./账号与权限.md)。规范的导出与检查见[后端开发说明](../backend/README.md#openapi)。

## 课程、学期与教学班目标设计

本节是 2026-11-02 确认的目标设计，数据库、接口和页面尚未迁移；后续各节描述当前实现。

### 实体与约束

课程长期存在；管理员安排某课程在某学期开设；教师加入该课程学期后建立自己的教学班。教学班表示一位教师在一个学期内管理的该课程学生集合，不是行政班。当前范围内，同一教师在同一课程学期只有一个教学班。

下表列出本次调整的课程、成员和积分表的完整目标字段，不省略审计或请求幂等字段。主外键、权限和积分归属沿用已确认的方案；字段按本次反馈精简。

| 实体 | 完整目标字段 | 约束与用途 |
| --- | --- | --- |
| 课程 `courses` | `id`, `name`, `introduction`, `created_by`, `created_at`, `updated_at`, `request_key`, `request_hash` | id 直接使用课程号；移除原 UUID id、独立 code 及无业务依赖的 updated_by。管理员创建课程时无需指定教师或学期；保留 `(created_by, request_key)` 唯一约束 |
| 学期 `terms` | `id`, `name`, `current` | id 为主键；current 仅允许 0、1，全库至多一条 current=1 的记录 |
| 课程学期 `course_terms` | `course_id`, `term_id` | 联合主键 `(course_id, term_id)`；分别引用课程和学期。记录管理员确定的开设安排，可以尚无教师加入；不保存 created_by、created_at |
| 教学班 `teaching_classes` | `course_id`, `term_id`, `teacher_id` | 联合主键 `(course_id, term_id, teacher_id)`；前两列复合外键指向课程学期，teacher_id 引用 accounts.id。允许多个教师分别加入，每个教学班只有一位教师 |
| 学生归属 `class_students` | `course_id`, `term_id`, `student_id`, `teacher_id` | 联合主键 `(course_id, term_id, student_id)`；`(course_id, term_id, teacher_id)` 复合外键指向教学班，student_id 引用 accounts.id，确保学生不能跨教师重复归属 |
| 积分规则 `class_bonus_rules` | `course_id`, `term_id`, `teacher_id`, `points_question`, `points_answer`, `points_acceptance`, `points_comment`, `points_material`, `points_material_version` | 前三列为联合主键及教学班复合外键，与教学班一一对应；六项分值为非负整数，默认均为 0，创建教学班时同时初始化 |
| 积分流水 `bonus_ledger` | `id`, `course_id`, `term_id`, `teacher_id`, `student_id`, `delta_points`, `source_kind`, `source_id`, `operator_id`, `reason`, `reverses_id`, `request_hash`, `created_at` | 保留自增整数主键 id；新增 teacher_id，与 course_id、term_id 组成指向教学班的复合外键，固定积分发生时的班级。保留奖励来源唯一性、撤回唯一性和手工请求幂等约束 |

字段类型沿用当前约定：积分流水 id、reverses_id、时间、current 和分值为 INTEGER，其余字段为 TEXT。仅流水的 reason、reverses_id、request_hash 可为 NULL，其余上述字段均为 NOT NULL；courses.introduction 默认空字符串。流水的类型、金额、来源和撤回约束继续沿用现有规则。teacher_id、student_id、created_by、operator_id 引用对应账号；流水 reverses_id 引用原流水。

审计字段逐项取舍如下；不因“常规审计”默认增加字段，也不将有实际业务用途的字段一并删除：

| 字段 | 处理 | 依据 |
| --- | --- | --- |
| `course_terms.created_by`, `course_terms.created_at` | 不增加 | 开设安排由管理员维护，当前需求只需要课程与学期的对应关系 |
| `teaching_classes.created_at` | 不增加 | 当前不需要按加入时间排序、限制资格或计算积分 |
| `class_students.added_by`, `class_students.added_at` | 不增加 | 当前仅管理学生归属，没有名单变更审计或按入班时间计算的需求 |
| `class_bonus_rules.updated_by`, `class_bonus_rules.updated_at` | 不增加 | 当前没有规则修改记录需求；已发生积分由流水保存金额，不靠修改时间还原 |
| `courses.updated_by` | 删除 | 当前只记录最后修改人，没有权限、排序、供数或幂等逻辑依赖 |
| `courses.created_by`, `courses.request_key`, `courses.request_hash` | 保留 | 按请求账号划分幂等键并核对重试参数；created_by 不表示课程所有者 |
| `courses.created_at` | 保留 | 现有课程列表按创建时间排序 |
| `courses.updated_at` | 保留 | 课程 DTO 和内容供数接口使用更新时间；迁移后仅随课程资料字段更新，不随教学班积分配置更新 |
| `bonus_ledger.operator_id`, `bonus_ledger.created_at` | 保留 | 记录实际积分操作者和发生时间；operator_id 还参与手工调分请求幂等，不能用所属班级的 teacher_id 替代 |

共享内容表和资料版本表保持现有字段，仅将课程引用切换为课程号。contents.course_id 仍指向长期课程，不增加学期或教学班归属；资料与问答跨教师、跨学期保留。流水引用教学班和学生账号，不引用可变的学生归属行，避免名单变化破坏积分历史；存在学生、规则或流水引用时不级联删除教学班。

教师加入时，服务端同时校验教师身份、目标学期是当前学期、管理员已建立课程学期开设安排。加入不需要审核，重复提交返回已有教学班。学生名单导入校验已有学生账号和教学班归属，同班重复记录不重复添加，遇到其他教师的同课程同学期名单时报告冲突，不自动转班。并发重复由唯一约束兜底。

课程已开设但暂无教师，与课程本学期未开设是两个不同状态。DTO 和 UI 需分别表达开设状态与教师集合，不能用 `currentTeacher=null` 推断未开设；查询多位教师时须避免课程列表出现重复行或分页数量错误。

### 内容与教学班权限

- 管理员维护课程目录和课程学期开设安排，教师的操作入口为“加入课程”，不再向教师提供创建课程操作。
- 本学期加入该课程的教师共同管理整门课程的资料、问答、采纳和内容审查；共享管理范围包括该课程历年积累的内容。
- 教学班的学生名单、必要学籍信息、积分规则和学生积分独立管理。教师只能操作本人当前学期教学班，不能因同课共同管理身份获得其他班的名单、规则修改或手工调分权限。管理员可跨班操作。
- 学期结束不删除教学班、修读关系和内容。往届教师失去整门课程的管理权限，保留本人内容的作者权限；历史班级的只读报表及必要更正权限另行确定。
- 课程开设状态不改变共享内容原有访问规则：游客可浏览共享信息，发布、互动和预览下载等继续按对应功能校验；加入课程任教、正式修读与主动关注分别处理。

迁移后不再用单一的课程级 `canManage` 覆盖所有操作，至少分别校验课程共享内容管理、本人教学班学生管理、本人教学班积分管理、管理员课程及学期安排权限。

### 积分归属

六项自动奖励规则由每位教师按教学班独立配置。计分时，以获得奖励的学生在该课程、当前学期所属的唯一教学班选择规则；教师和没有正式修读关系的学生参与共享内容仍不自动计分。

例如：教师甲采纳了教师乙班级学生的回答，采纳作为共享内容管理操作允许发生；奖励按乙教学班的规则计算。甲不因此获得对乙班学生手工调分或修改乙班规则的权限。

积分流水需要记录奖励发生时的教学班归属，保留原有分值、幂等和撤回关系，不能仅靠学生当前归属反推历史流水。撤回或恢复仍使用原奖励的金额、学期和教学班；新规则不追溯重算。学生转班后的统计、历史记录访问及教师交接行为另行确定。

### 界面与操作流程

- 管理员从“管理端”默认进入账号管理；课程管理中分别提供课程目录维护和按学期安排开设课程的操作。创建课程只填写课程号、名称和简介，不要求任课教师；开设安排由管理员选择课程与学期。
- 教师从“管理课程”查看本人的本学期教学班，通过“加入课程”弹窗查询管理员已开设的本学期课程。已加入项显示已加入，不再创建第二个教学班；其他教师已经加入不影响本人加入。
- 教师加入后进入本教学班的学生名单和积分配置；同一课程的资料与问答仍使用共享课程页面。班级操作区应明确课程、学期和所属教师，避免将本班配置误认为整门课程统一配置。
- 教师加入界面应区分没有配置当前学期、本学期没有已开设课程、搜索无结果或已经全部加入。未开设的旧课程仍可浏览已有内容，但不能从普通浏览页绕过开设安排加入。

## 课程、学期与成员

本节描述迁移前的当前实现。

- `terms.current=1` 标记当前学期，全库至多一个；空库可未配置，此时禁止建课。切换时在同一事务先清除旧标记，再设置新标记，历史关系保留。
- `enrollments(course_id, term_id, account_id)` 统一授课与修读，按 `accounts.role` 区分师生，不保存关系创建时间。每个课程实例恰好一位教师，可无学生；每门课程至少有一个有教师的实例，只能新建当前学期实例。
- 教师建课由本人任教；管理员必须传 `teacherId`，不因此取得教师身份，也不能传 `termId` 新建其他学期实例。课程编号非空且唯一，创建人、修改人、更新时间及创建幂等字段必填。
- 课程 DTO 的 `currentTeacher` 为当前学期任课教师 `{id, nickname, isDeleted}`，已删除身份的昵称为“已删除”；未设置当前学期或本学期未开课时为 null。
- `GET /api/courses` 的可选 `code` 按唯一课程编号精确过滤，与 `q` 同时提供时取交集；前端课程页用它把地址中的编号解析为内部 ID。
- 建课在同一 D1 batch 中开启 `PRAGMA defer_foreign_keys=ON`，先插入教师关系再插入课程；课程、关系和默认积分规则一起提交或回滚。
- 替换教师通过一次 UPDATE 修改原教师行，不能先删后加；有学生时不能删除唯一教师，也不能删除整门课程最后的教师关系。已删除账户的历史关系仍保留，但不授予管理权限。
- 课程教师权限同时依赖教师身份、当前学期与本课程关系；管理员可跨课程管理。正式修读仅参与奖励资格判断，不限制共享内容浏览、提问和回答。

名单导入、学期管理及教师加入接口尚未实现，教师加入按上文目标设计实现。成员约束由 `schema.ts` 与 `rules.sql` 共同定义。

### 本人的课程

`GET /api/me/courses` 需要登录，只按当前会话账号的 `enrollments` 查询授课或修读关系，不接受指定他人账号。`scope=current|history` 默认 current，分别查询当前学期或非当前学期；可选 `q` 按课程名称或编号匹配，去首尾空白后最多 100 字，过滤在服务端分页前完成。沿用 `page`、`pageSize` 分页，课程按编号、ID 升序稳定排列，同一课程在每个分类内只出现一次。教师的统一课程管理页使用 `scope=current`。

响应包含 `items`、`page`、`pageSize`、`total`、`scope` 与可空 `currentTerm: {id, name}`。每项为 `{course, terms}`：course 复用公开课程 DTO，terms 为本人在该分类中参与的 `{id, name, current}` 学期记录。无当前学期时，本学期为空、历史关系仍可读取；管理员不会自动获得所有课程。关注课程尚未实现，不在此接口中。

## 内容、文件引用与可见性

`contents` 统一保存 material、question、answer、comment，字段包括课程、作者、标题、正文、标签、状态和时间。资料简介使用 body。回答以 `target_id` 指向问题；评论指向 material / question / answer / comment 的直接父级。问题、资料的 target_id 为 null。父级类型由父记录的 kind 查询得出，不在子内容中重复存储。

`target_id` 是自引用外键，触发器校验回答的父级必须为问题、父子同课程及父级可见性，父级不能改写。HTTP 响应返回查询得出的 `targetKind`；评论读写提交 `targetKind`、`targetId`，服务端核验类型与目标记录一致。评论列表递归包含指定目标下的评论与回复，例如回复评论提交：

```json
{
  "targetKind": "comment",
  "targetId": "父评论ID",
  "body": {
    "type": "doc",
    "content": [
      {
        "type": "paragraph",
        "content": [
          {
            "type": "text",
            "text": "正文"
          }
        ]
      }
    ]
  }
}
```

标签长度按 Unicode 码点计数，最多 8 个标签、每个 30 字；举报和下架理由同样按码点计算 3–1000 字，与前端控件一致。只有 question / material 可设置 tags 数组；空数组归一化为 null，回答和评论固定为 null，PATCH 省略 tags 则保持原值。

`contents.edited_at` 为可空 INTEGER（Unix 秒），默认 null 表示从未编辑。只有作者或管理者通过 `PATCH /api/contents/:id` 实际修改 title、body 或 tags 时才写当前时间；省略字段、提交相同值均不改变它。比较采用输入校验后的值：标题及标签沿用去空白等归一化规则，正文按 JSON 结构比较，对象键顺序无关、数组顺序保留。赞踩、采纳、调分、上下架、删除及资料新版本均不改变 edited_at；updated_at 仍按现有操作规则更新。

公开内容详情、问答评论列表和个人空间的 `author` 返回 `id`、`nickname`、`avatarUrl`、`isDeleted`、`isTeacher`、`isCourseTeacher`。`avatarUrl` 为当前头像的同源 `/api/profiles/:id/avatar` 地址；未设置头像、账号禁用或删除时为 null，不暴露 R2 键。头像读取继续由账号模块校验；前端作者组件直接使用该字段，不逐项请求个人资料。

公开详情、列表、个人空间及删除占位统一提供以下元数据，内部内容详情沿用相同字段：

| 字段 | 约定 |
| --- | --- |
| editedAt | number 或 null；前端仅用 `editedAt !== null` 显示“已编辑”，不得从 updatedAt 推断 |
| replyTo | 回答和评论返回直接父内容的 `{ id, author: { nickname, isDeleted }, isDeleted }`；问题和资料为 null。作者删除后昵称为“已删除”，未设置昵称时为 null；内容是否删除与作者是否删除分别表示，不包含父内容正文 |
| answerCount | 仅问题返回；统计仍可见的回答，与回答列表 total 一致 |
| commentCount | 每种内容均返回，统计该评论区各层可见评论和回复。问题不合并回答下面的评论区；不计删除占位，仍计其可见子回复，下架整个分支不计。评论列表的 total 另包含仍有可见回复的删除占位，因此可能大于 commentCount |

数据库 `contents.body` 为可空 TEXT，CHECK 为 `body IS NULL OR json_valid(body)`；删除占位另有约束，要求 title、body、tags 均为 NULL。发布和编辑接口的 body 必须是根节点 `type: "doc"` 的 JSON 对象，不能发送 Markdown、HTML 字符串或重复序列化的 JSON 字符串。后端写库时序列化，查询详情、列表、审查及内部内容接口时解析；公开内容的 format 为 `prosemirror`。

前后端通过 `shared/rich-text/index.ts` 共用严格的节点、标记与属性白名单。正文最多 30000 个语义 Unicode 码点，紧凑 JSON 的 UTF-8 大小最多 368 KiB，列表与引用沿祖先链累计最多 16 层；发布问题、回答、评论及编辑正文的请求整体最多 384 KiB。链接只允许完整 http(s) 地址或站内路径，图片只允许站内路径；详细格式与样例见[正文契约](../frontend/src/lib/rich-text/README.md)。PATCH 省略 body 保持原值；删除操作清空正文，其他元数据按现有删除流程保留或更新。

资料或版本引用保存在链接 mark 的 `attrs.href` 中，不建立内容与文件的数据库关系，地址格式与版本规则见[资料与文件](./资料与文件.md#内容与版本)。正文图片上传接口仍待文件服务提供。

| --- | --- |
| visible | 按权限正常读取与操作 |
| deleted | 将 title、body、tags 置 NULL，保留 ID 关系、类型、删除状态及时间、请求幂等信息，不能恢复正文。评论删除后保留占位，其下回复仍可读取；问题、资料、回答删除后，其下回答和评论一并不可读取 |
| hidden | 保留正文但隐藏整个子分支；普通详情返回 `404 CONTENT_UNAVAILABLE`，原文仅授权审查接口可读 |

`/api/contents/:id` 对已删除评论返回占位。已删除的问题、资料、回答及其下内容，以及自身或祖先为 hidden 的内容，均返回 `404 CONTENT_UNAVAILABLE`，`/api/questions/:id` 同理。评论列表按时间平铺，已删除评论只在其下仍有可见回复时以占位出现。公开列表、搜索、动态和文件访问须遵循相同状态；下架恢复后重新检查子分支。

资料的编辑、删除、举报和下架复用 contents 通用接口；上传、版本与文件访问见[资料与文件](./资料与文件.md)。

## 投票与内容管理

问题、回答和评论允许赞踩，每人每项至多一票，可切换或撤销，不允许自投，重试不累加。采纳答案置顶，其余按净赞数和稳定顺序排序，教师身份不改变排序。

`votes.created_at` 记录投票行的创建时间；切换赞踩或重复提交保持原时间，撤销会删除该行，重新投票产生新的创建时间。

作者可维护自己的内容，课程教师与管理员在授权范围内审查。当前采用发布后审查，最终审核模式待确认。资料、问题、回答、评论均可举报；下架、恢复及举报处理保留审计。下架／恢复原因直接写 `moderation_actions.reason`，与内容状态修改同事务提交，不通过内容字段传递。

## 采纳与加分

当前课程教师或管理员可采纳、取消、更换答案，管理员可跨课程采纳、取消和调分；每个问题同时至多一个采纳答案，提问者身份不授予采纳权限。

积分按“课程、学期、学生”汇总整数分，与成绩无关，由教师说明折算标准。下表是迁移前的课程级规则与接口，已通过隔离 D1 测试；目标设计改为教学班独立规则和权限，见[积分归属](#积分归属)。

| 项目 | 模型与规则 |
| --- | --- |
| 课程配置 | `course_bonus_rules.id` 为主键并引用 `courses.id`；points_question、points_answer、points_acceptance、points_comment、points_material、points_material_version 均为非负整数，默认 0；建课时自动建立规则记录，0 表示该项不奖励 |
| 自动奖励 | 按操作发生时的当前学期、课程配置及学生正式修读关系判断；教师和未正式修读的学生可参与，但不自动加分；没有当前学期时不产生自动积分 |
| 奖励叠加 | 回答奖励与采纳奖励独立。例如回答 +25，采纳再 +50；取消采纳只撤回 50 |
| 资料奖励 | 文件版本记录插入时奖励上传者，资料元数据本身不奖励；首次上传（版本 1）仅加 points_material，后续每个新版本仅加 points_material_version，两项分别计分 |
| 采纳关系 | `acceptances` 以 question_id 为主键，保存 answer_id、operator_id、created_at；不存积分，contents 不包含采纳或奖励字段 |
| 流水 | `bonus_ledger` 保存课程、学期、学生、delta_points、来源、操作者、可空 reason 和时间；禁止改写和删除 |
| 撤回与恢复 | 删除、下架或取消采纳撤回对应奖励；恢复可见性或重新采纳同一回答，按原金额、原学期补回。reverses_id 指向被抵消的前一笔，同一笔只能被抵消一次 |
| 手工加减 | 指定课程、学期、正式修读学生及非零整数增减值，reason 可省略或为 null；可为负分，独立于自动奖励，不随内容上下架撤回 |
| 一致性 | 原始奖励对来源唯一；内容或采纳状态、奖励流水同事务提交或回滚；幂等键防止手工调分重试重复记账 |

改规则不追溯修改历史奖励：原先为 0 的操作不会因后来提高分值而补发；已获奖来源恢复时仍使用原值，不按新规则重新计算。取消后跨学期重新采纳同一答案，也恢复原奖励学期。下架父内容撤回隐藏分支内的奖励；恢复时仍下架的子内容不会补回。删除问题、资料或回答后其下内容不再公开，但其下内容已得的独立奖励保留，不随删除撤回。

下架仅暂停采纳的公开可见性，`acceptances` 行保留；问题或被采纳答案删除时移除采纳关系。公开 DTO 的 acceptedAnswerId、solved 和 isAccepted 从可见采纳关系计算。

流水的 sourceKind 为 question / answer / acceptance / comment / material / manual；sourceId 分别为内容 ID、被采纳答案 ID、`materialId@version` 或手工请求幂等键。来源 ID 不设外键，文件版本物理删除后仍保留原流水和撤回记录。版本删除使用 updated_by 归属操作者；删除接口在同一 batch 先设置 updated_by 再 DELETE。

自动积分的 reason 为 null，展示说明由 sourceKind、sourceId、deltaPoints 和 reversesId 渲染。sourceKind=manual 表示手工调整；其他来源中，reversesId=null 表示原始奖励，非空且 deltaPoints<0 表示撤回，非空且 deltaPoints>0 表示补回。撤回保留原记录并追加相反分值，以便跨学期、规则调整后仍按原值补回；reversesId 保证同一笔只被抵消一次。手工调整可附加说明，省略 reason 与显式 null 等价；提供文本时为 1–500 字符。流水和汇总仅本人或授权教师、管理员可读。账户删除或身份切换保留原 ID 的采纳和流水，不自动冲销，也不转给新身份。

| 方法、路径 | 输入或返回 |
| --- | --- |
| `PUT /api/courses/:id/bonus-policy` | pointsQuestion、pointsAnswer、pointsAcceptance、pointsComment、pointsMaterial、pointsMaterialVersion 六项整数规则；课程 DTO 返回嵌套 bonusPolicy |
| `PUT /api/questions/:id/acceptance` | 仅 answerId，null 表示取消；返回内容详情及 changed，不接收分值 |
| `POST /api/courses/:id/bonus-adjustments` | studentId、termId、deltaPoints，以及可选 reason，须带 Idempotency-Key；201 返回该笔流水，可调整指定历史学期 |
| `GET /api/courses/:id/bonus-ledger` | 当前课程教师或管理员读取，支持 termId 筛选 |
| `GET /api/courses/:id/bonus-summary` | 同权限；按 studentId、termId 返回整数 totalPoints 和可空 nickname |
| `GET /api/me/bonus-ledger` | 本人流水，可按 courseId、termId 筛选 |

流水响应包含 id、courseId、termId、studentId、deltaPoints、sourceKind、sourceId、operatorId、reason、reversesId、createdAt。教师调分统一使用 `bonus-adjustments`。规则修改与课程修改人、更新时间在同一事务提交。完整请求和响应见 OpenAPI。

## 接口通用约定

- 内容写请求上限 384 KiB，其余讨论 JSON 上限 128 KiB。响应格式与同源要求见[请求与联调](./架构与开发.md#请求与联调)。
- 创建课程、内容或举报返回 201 与 `{data: {id}}`，Location 指向详情；手工积分调整返回 201 与该笔流水。
- POST 创建及手工积分调整须带 8–100 位 `Idempotency-Key`，同一键重试须保持请求内容一致；课程与内容创建在数据库中记录 request_key / request_hash。课程、内容编辑按最终写入顺序生效，PATCH 只覆盖提交字段；删除内容不需要请求体。
- 普通列表为 `{data: {items, page, pageSize, total}}`，默认每页 20、最大 50；时间为 Unix 秒，学期字段为 termId。
- 作者使用可空 nickname、isDeleted；教师与本课程教师标识独立，已删除作者的教师标识为 false。公开 DTO 不包含学籍、会话、请求指纹或奖励内部字段。
- 课程入口的 `permissions.canManage` 可用于显示按钮，最终权限由服务端决定。会话快照及在途写入规则见[请求准入与权限](./账号与权限.md#请求准入与权限)。

## 搜索与内容供数

`/api/internal/*` 使用独立 Bearer 凭据 `INTERNAL_API_TOKEN`，至少 24 字符；未配置或过短返回 503，普通会话不能访问。本地参考 `backend/.dev.vars.example` 配置被忽略的 `.dev.vars`，云端使用 Worker Secret。该凭据不放入前端，与 Cloudflare 管理 Token 分开。

| 接口 | 契约 |
| --- | --- |
| `GET /api/internal/documents` | 分页读取当前可见课程、资料、问题和回答；返回 items、nextCursor、hasMore |
| `GET /api/internal/contents/:id` | 复查当前可见性，不可用返回 `{data: {id, available:false}}` |

文档分页每页读取当时的可见数据，不提供跨页一致快照、增量变更或事件重放，分页期间可能发生新增、修改和删除。搜索与通知尚未实现，同步与通知触发方式待确定。

文档中，课程简介的 body 为普通字符串、format=text；资料、问题和回答的 body 为 ProseMirror JSON 对象或 null、format=prosemirror。搜索提取节点的 text 字段，不把序列化 JSON 当作正文全文。展示和跳转仍须检查当前内容及祖先可见性。

`GET /api/courses/:id/activity` 直接查询当前可见内容，每项内容出现一次，按 updatedAt、contentId 降序排列，返回 contentId、kind、title、createdAt、updatedAt。下架内容及其子分支、已删除内容及已删除问题、资料、回答之下的内容均不出现在列表；个人空间同样查询本人当前可见内容。
