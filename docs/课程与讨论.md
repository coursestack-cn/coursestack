# 课程与讨论

当前后端提供课程、问答评论、赞踩采纳、加分、举报审查、本人动态以及事件和搜索供数接口。源码分别位于 `backend/src/courses/`、`discussions/`、`moderation/`、`integration/`；启动与检查见[后端开发说明](../backend/README.md)。

接口参数与响应见仓库根目录的 [OpenAPI](../openapi/openapi.json)，它是前后端共用的接口契约。运行时入口为 `/api/openapi.json`，返回标准 OpenAPI 3.1 文档，不包 data；目前覆盖课程与讨论的 34 个业务方法，账号接口见[账号与权限](./账号与权限.md)。

## 课程、学期与成员

- `terms.current=1` 标记当前学期，全库至多一个；空库可未配置，此时禁止建课。切换时在同一事务先清除旧标记，再设置新标记，历史关系保留。
- `enrollments(course_id, term_id, account_id)` 统一授课与修读，按 `accounts.role` 区分师生，不保存关系创建时间。每个课程实例恰好一位教师，可无学生；每门课程至少有一个有教师的实例，只能新建当前学期实例。
- 教师建课由本人任教；管理员必须传 `teacherId`，不因此取得教师身份，也不能传 `termId` 新建其他学期实例。课程编号非空且唯一，创建人、修改人、更新时间及创建幂等字段必填。
- 建课在同一 D1 batch 中开启 `PRAGMA defer_foreign_keys=ON`，先插入教师关系再插入课程；课程、关系与触发器生成的事件一起提交或回滚。
- 替换教师通过一次 UPDATE 修改原教师行，不能先删后加；有学生时不能删除唯一教师，也不能删除整门课程最后的教师关系。已删除账户的历史关系仍保留，但不授予管理权限。
- 课程教师权限同时依赖教师身份、当前学期与本课程关系；管理员可跨课程管理。正式修读仅参与奖励资格判断，不限制共享内容浏览、提问和回答。

加入已有课程、教师替换、名单导入和学期管理接口尚待实现。成员约束由 `schema.ts` 与 `rules.sql` 共同定义，当前只支持[空库初始化](../backend/README.md#数据库结构与迁移)。

## 内容、文件引用与可见性

`contents` 统一保存 material、question、answer、comment，字段包括课程、作者、标题、正文、标签、状态和时间。资料简介使用 body。回答以 `target_kind=question` 指向问题；评论指向 material / question / answer / comment 的直接父级。问题、资料的 target 字段为 null。

`target_id` 是自引用外键，触发器校验父级类型、同课程与可见性，父级不能改写。HTTP 只使用 `targetKind`、`targetId`，不提供 questionId、replyToId、fileVersionId 或 file 关联字段。评论列表递归包含指定目标下的评论与回复，例如回复评论提交：

```json
{
  "targetKind": "comment",
  "targetId": "父评论ID",
  "body": {
    "type": "doc",
    "content": [
      {
        "type": "paragraph",
        "content": [
          {
            "type": "text",
            "text": "正文"
          }
        ]
      }
    ]
  }
}
```

只有 question / material 可设置 tags 数组；空数组归一化为 null，回答和评论固定为 null，PATCH 省略 tags 则保持原值。编辑器采用 Tiptap；正文使用 ProseMirror JSON，前端负责编辑、预览及安全渲染。

数据库 `contents.body` 为可空 TEXT，CHECK 为 `body IS NULL OR json_valid(body)`；删除占位另有约束，要求 title、body、tags 均为 NULL。发布和编辑接口的 body 必须是根节点 `type: "doc"` 的 JSON 对象，不能发送 Markdown、HTML 字符串或重复序列化的 JSON 字符串。后端写库时序列化，查询详情、列表、审查及内部内容接口时解析；公开内容的 format 为 `prosemirror`。

正文 JSON 序列化后最多 30000 字符，内容节点最多嵌套 64 层，讨论请求整体仍限 128 KiB。接口检查通用节点、标记及属性结构；完整的节点类型、嵌套规则和渲染属性由后续前后端统一的 Tiptap 扩展配置决定，目前不锁定扩展清单。PATCH 省略 body 保持原值；删除操作清空正文，其他元数据按现有删除流程保留或更新。

前端可使用 Tiptap 的 `editor.getJSON()` 获取正文、通过编辑器 content 恢复，见 [Tiptap JSON 文档](https://tiptap.dev/docs/guides/output-json-html)。资料或版本引用保存在链接 mark 的 attrs.href 中，不新增内容与文件的数据库关系。当前只完成数据和接口约定，编辑器界面尚未接入。

`file_versions.material_id` 引用 material 内容，版本使用 `(material_id, version)` 复合主键，version 为正整数；对外版本标识为 `materialId@version`，例如 `100@2`，不另存 UUID。版本状态为 visible / hidden，物理删除时不保留 deleted 行；保留上传人 `uploaded_by`、操作人 `updated_by` 及创建时间。资料主页承载评论，版本不设评论区。正文链接的 href 使用 `/materials/material-a/versions/1` 等文件页面地址，创建、编辑和筛选不接受 fileVersionId；文件下架不会自动隐藏引用它的问题。

| 状态 | 对外行为 |
| --- | --- |
| visible | 按权限正常读取与操作 |
| deleted | 将 title、body、tags 置 NULL，保留 ID 关系、类型、删除状态及时间、revision、请求幂等信息；已有回答、评论仍可读取，不能恢复正文 |
| hidden | 保留正文但隐藏整个子分支；普通详情返回 `404 CONTENT_UNAVAILABLE`，原文仅授权审查接口可读 |

`/api/contents/:id` 与 `/api/questions/:id` 对 deleted 返回占位，对自身或祖先 hidden 返回不可用。公开列表、搜索、动态和文件访问须遵循相同状态；恢复后重新检查子分支，不能把 deleted 当作 hidden 向下传播。

资料元数据、详情、编辑、删除、举报及下架可复用 contents 通用接口。资料发布、文件上传、预签名、确认、预览下载尚待实现，必须同时检查资料及具体版本状态；发布资料也须写入 request_key/request_hash。

## 投票与内容管理

问题、回答和评论允许赞踩，每人每项至多一票，可切换或撤销，不允许自投，重试不累加。采纳答案置顶，其余按净赞数和稳定顺序排序，教师身份不改变排序。

作者可维护自己的内容，课程教师与管理员在授权范围内审查。当前采用发布后审查，最终审核模式待确认。资料、问题、回答、评论均可举报；下架、恢复及举报处理保留审计。下架／恢复原因直接写 `moderation_actions.reason`，与内容状态修改同事务提交，不通过内容字段传递。

## 采纳与加分

当前课程教师或管理员可采纳、取消、更换答案，每个问题同时至多一个采纳答案；提问者身份不授予采纳权限。管理员跨课程采纳、取消和调分已确认。

积分按“课程、学期、学生”汇总整数分，与成绩无关，由教师说明折算标准。以下规则已实现并通过隔离 D1 测试；主站界面与云端联调仍待完成。

| 项目 | 模型与规则 |
| --- | --- |
| 课程配置 | questionPoints、answerPoints、acceptancePoints、commentPoints、materialPoints 均为非负整数，默认 0；0 表示该项不奖励，materialPerVersion 默认 false |
| 自动奖励 | 按操作发生时的当前学期、课程配置及学生正式修读关系判断；教师和未正式修读的学生可参与，但不自动加分；没有当前学期时不产生自动积分 |
| 奖励叠加 | 回答奖励与采纳奖励独立。例如回答 +25，采纳再 +50；取消采纳只撤回 50 |
| 资料奖励 | 文件版本记录插入时奖励上传者，资料元数据本身不奖励；materialPerVersion=false 仅版本 1 获奖，为 true 时每个新版本各奖励一次 |
| 采纳关系 | `acceptances` 以 question_id 为主键，保存 answer_id、operator_id、created_at；不存积分，contents 不再包含采纳或奖励字段 |
| 流水 | `bonus_ledger` 保存课程、学期、学生、delta_points、来源、操作者、原因和时间；operation 为 award / revoke / restore / manual，禁止改写和删除 |
| 撤回与恢复 | 删除、下架或取消采纳撤回对应奖励；恢复可见性或重新采纳同一回答，按原金额、原学期补回。reverses_id 指向被抵消的前一笔，同一笔只能被抵消一次 |
| 手工加减 | 指定课程、学期、正式修读学生及非零整数增减值，原因必填；可为负分，独立于自动奖励，不随内容上下架撤回 |
| 一致性 | 原始奖励对来源唯一；内容或采纳状态、奖励流水与相应业务事件同事务提交或回滚；幂等键防止手工调分重试重复记账 |

改规则不追溯修改历史奖励：原先为 0 的操作不会因后来提高分值而补发；已获奖来源恢复时仍使用原值，不按新规则重新计算。取消后跨学期重新采纳同一答案，也恢复原奖励学期。下架父内容撤回隐藏分支内的奖励；恢复时仍下架的子内容不会补回。删除父内容保留可见的子内容，其独立奖励保留。

下架仅暂停采纳的公开可见性，`acceptances` 行保留；问题或被采纳答案删除时移除采纳关系。公开 DTO 的 acceptedAnswerId、solved 和 isAccepted 从可见采纳关系计算。采纳不修改内容 revision，采纳事件使用独立事件 ID。

流水的 sourceKind 为 question / answer / acceptance / comment / material / manual；sourceId 分别为内容 ID、被采纳答案 ID、`materialId@version` 或手工请求幂等键。来源 ID 不设外键，文件版本物理删除后仍保留原流水和撤回记录。版本上下架使用 updated_by 归属操作者；其他用户代为删除版本时，需在同一 batch 先设置 updated_by 再 DELETE。上传服务必须为新版本分配新的版本号，不能复用已删除版本的链接标识。

原因直接写 `bonus_ledger.reason`；流水和汇总仅本人或授权教师、管理员可读。账户删除或身份切换保留原 ID 的采纳和流水，不自动冲销，也不转给新身份。

| 方法、路径 | 输入或返回 |
| --- | --- |
| `PUT /api/courses/:id/bonus-policy` | revision 与全部六项规则；课程 DTO 返回嵌套 bonusPolicy |
| `PUT /api/questions/:id/acceptance` | 仅 answerId，null 表示取消；返回内容详情及 changed，不接收 revision 或分值 |
| `POST /api/courses/:id/bonus-adjustments` | studentId、termId、deltaPoints、reason，须带 Idempotency-Key；201 返回该笔流水，可调整指定历史学期 |
| `GET /api/courses/:id/bonus-ledger` | 当前课程教师或管理员读取，支持 termId 筛选 |
| `GET /api/courses/:id/bonus-summary` | 同权限；按 studentId、termId 返回整数 totalPoints 和可空 nickname |
| `GET /api/me/bonus-ledger` | 本人流水，可按 courseId、termId 筛选 |

流水响应包含 id、operation、courseId、termId、studentId、deltaPoints、sourceKind、sourceId、operatorId、reason、reversesId、createdAt。积分不使用百分之一分单位。旧的采纳调分接口已删除，教师调分统一使用课程 bonus-adjustments。课程配置、资料上传、管理界面、积分报表和事件消费方应使用以上字段，完整请求和响应见 OpenAPI。

## 前端接口约定

- 主站业务位于 `/api`，使用现有同源 Cookie 与代理。写请求要求匹配 Origin，讨论 JSON 上限 128 KiB；账号 8 KiB、头像 2 MiB 限制独立。
- 成功返回 `{data: ...}`，失败返回 `{error: {code, message}}`。创建课程、内容或举报为 201、`{data: {id}}`，Location 指向详情；手工积分调整为 201、`{data: 流水}`。
- POST 创建及手工积分调整带 8–100 位 `Idempotency-Key`；课程、内容编辑删除及审查带最新 revision。采纳关系独立写入，不带 revision。同一键重试必须保持请求内容一致。
- 普通列表为 `{data: {items, page, pageSize, total}}`，默认每页 20、最大 50；时间为 Unix 秒，学期字段为 termId。
- 作者使用可空 nickname、isDeleted；教师与本课程教师标识独立，已删除作者的教师标识为 false。公开 DTO 不包含学籍、会话、请求指纹或奖励内部字段。
- 课程入口的 `permissions.canManage` 可用于显示按钮，最终权限由服务端决定。会话快照及在途写入规则见[请求准入与权限](./账号与权限.md#请求准入与权限)。

主站讨论页面仍待真实接口联调，详情、回答与评论中转按[前端路由](./前端路由.md)实现。

## 事件、搜索与通知供数

`/api/internal/*` 使用独立 Bearer 凭据 `INTERNAL_API_TOKEN`，至少 24 字符；未配置或过短返回 503，普通会话不能访问。本地参考 `backend/.dev.vars.example` 配置被忽略的 `.dev.vars`，云端使用 Worker Secret。该凭据不能放入前端，也不能与 Cloudflare 管理 Token 混用。

| 接口 | 契约 |
| --- | --- |
| `GET /api/internal/events?after=0&limit=50` | 按 seq 升序返回 `{data: {items, nextCursor, hasMore}}` |
| `POST /api/internal/events/ack` | 标记处理，可重试，不删除事件，也不代替消费方事务 |
| `GET /api/internal/documents` | 可见课程、资料、问题、回答的快照；返回 items、nextCursor、hasMore、watermark |
| `GET /api/internal/contents/:id` | 复查当前可见性，不可用返回 `{data: {id, available:false}}` |

消费方以 eventId 持久化去重，自己的索引／通知操作成功后再推进游标。事件含课程、内容、操作者、作者、直接父级 targetKind / targetId / targetAuthorId 和新旧采纳答案作者 ID；资料使用 material.created、material.updated、material.hidden 等事件。

通知消费方沿直接父级查找根讨论与订阅对象，排除操作者，合并订阅后按 `(eventId, recipientId)` 去重，并核对收藏关系的有效状态。当前提供拉取协议，不运行通知消费进程，收藏、通知和搜索消费者存储尚待实现。

搜索快照中，课程简介的 body 为普通字符串、format=text；资料、问题和回答的 body 为 ProseMirror JSON 对象或 null、format=prosemirror。索引消费者按节点提取 text 字段，不把序列化 JSON 当作正文全文。

初始化搜索时记录**第一页** watermark，完成所有分页后重放大于该值的事件，不能采用最后一页的新 watermark 跳过期间变更。处理下架、恢复时复查整个子分支；删除父内容仅移除父文档，保留仍可见子内容。通知展示和跳转同样复查可见性，不缓存下架原文。

课程动态和个人空间不公开原始事件载荷，避免从历史事件泄露下架内容。事件暂保留供重放，清理策略待设计。
