## 待全组确认的规则提案

原提案尚未确定加分撤回、学期归属、教师加入课程的确认流程和审核模式。以下是为了运行与验证而采用的明确实现选择，**不是已达成的团队结论**：

1. 加分默认关闭，默认金额2分；允许0–100分、最多两位小数。课程教师显式启用后才自动奖励。
2. 采纳归采纳时的当前学期；自动奖励只给当期正式修读该课程、账号有效的学生。教师或旁听者答案仍可采纳，但不奖励。
3. 取消、更换采纳，删除/下架答案，或删除/下架问题时，立即全额冲销旧奖励，并保留记录。跨学期冲销仍归原奖励学期。
4. 课程加分配置变化不追溯历史奖励。显式调分需理由，保留旧额冲销和新额奖励。内容恢复只恢复可见性，重新采纳由教师决定。
5. 当前学期由组员1维护的 `semesters.status='active'` 决定；历史教师失去该课程管理权限。管理员可跨课程维护。
6. 创建课程的教师自动登记为该课程当前学期教师。加入已有课程、邀请/审批其他教师的接口归组员1协调。
7. 采用发布后审查，软删除保留占位。父评论删除后回复保留，回复列表只带不可用父评论ID；下架原文只在授权审查接口可见。
8. 正文先使用 Markdown。前端负责编辑器、预览和安全渲染；图片上传、文件访问权限和版本生命周期归组员4。

规则调整应先协调需求，再追加迁移/修改相应策略和定向测试。云端尚未迁移这些提案。

## 与组员1对接

共享表最小契约见 `database/migrations/0001_shared_contract.sql`。账号仅读取公开名称、身份、有效状态，不保存或公开邮箱、学号或真实学籍信息。会话适配器位于 `backend/src/auth.ts`：默认读取 `sessions(token_hash,user_id,expires_at)`，使用 SHA-256 哈希和 UTC ISO 时间；接入真实登录方案时在此统一替换。

当前课程管理必须同时满足教师身份、当前学期和该课程授课关系。写入 SQL 会重新检查这些条件，不仅依靠请求开始时的检查。正式修读仅用于加分资格，不限制共享内容浏览、提问和回答。

课程创建时会写 `course_teachers`，这是一个需要与组员1对齐的跨模块写入点；触发器保证课程、授课关系和事件一起提交或回滚。名单导入、学期切换、人员管理和真实登录不在本交付中实现。

## 与组员2对接

`GET /` 在 local+回环地址提供独立的可操作验收页，源码位于 `backend/src/local-demo.ts`，使用当前会话调用真实业务接口。dev/生产不提供此界面。它便于组员3验收和演示后端，不修改组员2的前端工程。页面通过课程入口的 `permissions.canManage` 显示管理按钮，不在浏览器自行认定管理权限。

所有主站业务接口位于 `/api`，使用现有 Vite 代理，不硬编码后端主机地址。成功创建返回201和 `{id}`；`Location` 指向详情。POST 创建带8–100位 `Idempotency-Key`，编辑/删除/采纳/审查带最新 `revision`。409 表示界面需要刷新状态。

详情只返回公开 DTO，不返回请求指纹、会话、学籍或奖励内部字段。教师标记和“本课程教师”标记分开，和采纳状态也分开。加分流水只允许本人或授权教师/管理员读取。

文件链接返回 `file: {id,available:false}` 时显示“关联版本不可用”，继续显示讨论。已删除内容的通用详情 `/api/contents/:id` 返回无正文占位；下架和上级不可见时返回404及 `CONTENT_UNAVAILABLE`，界面显示不可用状态。

本地身份切换工具用于联调 Cookie，不是正式登录实现。它只在 local+回环地址启用，dev/生产返回404。本地 Cookie 名为 `coursestack_session`，无生产域名绑定；正式 Cookie 名为 `__Host-coursestack_session`，由组员1的登录接口按安全属性签发。

## 与组员4对接

资料与版本只读取 `id/course_id/author_id/status`、`material_id/filename/version/status` 契约。新关联要求资料和具体版本都可见、归属同课程；旧问题保留原版本ID，旧文件下架不隐藏问题。`FILES` 绑定已预留，本交付不接管资料上传、预签名、确认、预览、下载、收藏或通知列表。

内部接口需要独立的 `INTERNAL_API_TOKEN`，至少24字符。未配置时返回503；普通用户令牌不能使用。将 `.dev.vars.example` 复制为 `.dev.vars` 可本地配置，实际值不提交。内部凭据与 Cloudflare 管理 token 是两回事，不能混用。

`GET /internal/events?after=0&limit=50` 按 seq 升序返回事务事件。消费者以 `eventId` 做持久化去重，在自己的通知/索引操作成功后推进游标，可调用 `/internal/events/ack` 标记已处理。ack不删除事件，也不替代消费者的事务。当前接口是拉取协议，本交付不运行通知消费进程。

事件携带课程、内容、操作者、作者、问题作者、评论目标作者、回复作者以及新旧采纳答案作者ID，便于计算直接通知对象和收藏订阅对象。消费者排除操作者，合并多种订阅后按 `(eventId,recipientId)` 去重；收藏关系以消费时/约定时的有效状态核对。

搜索初始化使用 `/internal/documents`，只包含可见课程、问题和回答。记录第一页的 `watermark`，全部分页结束后重放大于该值的事件，关闭分页期间的变更窗口。不要用最后一页的新 watermark 跳过中间事件。

消费事件时通过 `/internal/contents/:id` 复查当前可见性；不可用返回 `{id,available:false}`。问题下架/删除还应移除以该问题为父级的回答搜索文档，恢复时重查其仍可见的回答，避免只更新问题文档而遗留子项。通知展示和跳转同样遵循当前可见性，不缓存下架原文。

课程近期活动和个人空间不会直接公开 outbox 原始载荷，避免内容下架后从历史事件泄露。事件表先保留供重放，清理策略留给后续共同设计。

## 部署与资源

2026-10-26起，部署只走 main 的 GitHub Actions。个人分支的首次草稿提交不触发部署。合入main后dev会自动运行测试、应用远程D1迁移和发布；生产需手动运行与审批。

本分支只保留本地配置，尚未合并main的统一账号、共享schema和部署入口。不能将本分支的联调契约迁移应用到远程库，也不能修改已应用的共享迁移。本地旧管理token读取工具已从提交内容中移除。

本地私有CSV是历史联调材料，不随源码提交；其中旧管理token已被组长撤销。后续member凭据只通过临时环境变量使用，云端部署凭据保留在GitHub Environment Secret。
