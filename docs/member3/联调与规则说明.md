## 当前实现与待调整规则

以下记录当前代码行为。操作人已提出按（课程，学期，学生）计整数分、按提问／回答／采纳／评论／资料及版本配置规则、手工加减分，以及下架撤回、恢复按原值补回的新方案；积分模型尚待单独实现，下列第 1～4 项描述的仍是原移植行为。教师加入／替换的管理流程和审核模式另行明确。

1. 加分默认关闭，默认金额2分；允许0–100分、最多两位小数。课程教师显式启用后才自动奖励。
2. 采纳归采纳时的当前学期；自动奖励只给当期正式修读该课程、账号有效的学生。教师或旁听者答案仍可采纳，但不奖励。
3. 取消、更换采纳，删除/下架答案，或删除/下架问题时，立即全额冲销旧奖励，并保留记录。跨学期冲销仍归原奖励学期。
4. 课程加分配置变化不追溯历史奖励。显式调分需理由，保留旧额冲销和新额奖励。内容恢复只恢复可见性，重新采纳由教师决定。
5. 当前学期由 `terms.current=1` 决定，数据库限制至多一个；历史教师失去该课程管理权限。切换标记保留历史关系，管理员可跨课程维护。
6. 只能新建当前学期课程实例，每个实例恰好一位教师，可以没有学生；每门课程至少有一个有教师的实例。教师建课由本人任教，管理员建课须传 teacherId。加入已有课程、替换教师的管理接口归组员1协调。
7. 采用发布后审查。删除内容时清空标题、正文和标签，标记 deleted 并保留关联占位，已有回答和评论仍可访问；hidden 下架保留正文并隐藏整个子分支，下架原文只在授权审查接口可见。
8. 正文先使用 Markdown。前端负责编辑器、预览和安全渲染；图片上传、文件访问权限和版本生命周期归组员4。

本次 0012 落实学期、成员关系、标签及操作原因存储调整，不改变积分算法。云端尚未应用这些迁移。

## 与组员1对接

正式结构见 `backend/src/db/schema.ts` 和 `backend/migrations/`。账号引用 `accounts.id`，公开昵称读取 `nickname`；单个 accounts.role 为 student、teacher 或独立 admin。账户的姓名、学工号、院系、专业、年级仍只可受控读取。删除或切换身份保留所有业务记录；旧作者显示“已删除”，切换后的新 ID 不接管旧记录。认证中间件 `backend/src/auth/middleware.ts` 复用 `auth/service.ts` 的 `readSession`，使用 Cookie、会话 SHA-256 摘要、整数 Unix 秒到期时间及凭据版本，不使用独立用户表或临时会话模型。

当前课程管理必须同时满足教师身份、当前学期和该课程授课关系。入口验证会话、到期时间、凭据版本及账号状态，保存角色和 dataGeneration 快照；写入 SQL 检查该代身份仍有效以及当前课程条件。普通退出、改密、禁用或到期允许已获准请求完成，身份退役后旧请求不能再写入。正式修读仅用于加分资格，不限制共享内容浏览、提问和回答。

授课和修读统一为 `enrollments(course_id,term_id,account_id)`，通过 accounts.role 区分师生，无 created_at。教师行代表课程实例，触发器检查唯一教师及新建时的当前学期条件；替换教师更新原行的 account_id，不能先删后加。删除账号时保留旧关系和角色，已删除身份不再获得权限。

课程创建使用同一个 D1 batch：开启 `PRAGMA defer_foreign_keys=ON`，先写当前学期教师 enrollments，再写 courses；事件由课程触发器写入。课程、关系和事件一起提交或回滚。管理员必须指定 teacherId，且不会自动获得教师身份。名单导入、学期切换和人员管理接口仍待完成。迁移0012拒绝多教师、无教师课程或无教师学生名单，不自动选教师或删关系。

`contents.change_reason` 已删除。下架／恢复的说明直接写 moderation_actions.reason，显式调分的说明直接写 bonus_ledger.reason，两者分别与对应内容修改在同一事务中提交；自动冲销按状态变化记录原因，不再通过内容行传递。既有历史原因保留。

## 与组员2对接

本次移植复用主站和正式登录入口，未移植组员3原有的本地验收页、身份切换或版本选择器。前端可通过课程入口的 `permissions.canManage` 显示管理按钮，最终权限由服务端判断。

OpenAPI 3.1 规范见 [openapi.json](./openapi.json)，服务入口为 `/api/openapi.json`。规范本身按 OpenAPI 标准返回，不包 data；规范只描述本模块的34个业务方法。

所有主站业务接口位于 `/api`，使用现有 Vite 代理，不硬编码后端主机地址。所有业务成功响应为 `{data: ...}`，失败为 `{error: {code, message}}`。成功创建返回201和 `{data: {id}}`；`Location` 指向详情。POST 创建带8–100位 `Idempotency-Key`，编辑/删除/采纳/审查带最新 `revision`。409 表示界面需要刷新状态。

详情只返回公开 DTO，不返回请求指纹、会话、学籍或奖励内部字段。教师标记和“本课程教师”标记分开，和采纳状态也分开。加分流水只允许本人或授权教师/管理员读取。

内容 DTO 只用 `targetKind`、`targetId` 表示直接父内容，不再返回 `questionId`、`replyToId`、`fileVersionId` 或 `file`。回复评论提交 `{targetKind:"comment",targetId:"父评论ID",body:"正文"}`；评论列表按指定目标递归包含其评论和回复。回答的父内容为问题，问题和资料的两个 target 字段均为 null。

tags 可为 null，只有 question/material 能设置 JSON 数组；回答和评论固定为 null。创建或编辑时传入空数组会归一化为 null，省略 PATCH 的 tags 保持原值。POST /api/courses 的教师默认本人任教；管理员必须提供 teacherId，不能传入 termId 指定其他学期。

引用直接写入 Markdown 正文，例如 `[讲义第1版](/materials/material-a/versions/version-a1)`。创建、编辑和筛选不再接受 `fileVersionId`。`/api/contents/:id` 与 `/api/questions/:id` 对已删除内容返回无正文占位（含 courseId 和直接父级），已有回答及评论仍能读取；下架内容或具有下架祖先的内容返回404及 `CONTENT_UNAVAILABLE`。

普通接口只认 `coursestack_session` Cookie，所有环境使用同一名称；写请求要求 Origin 与请求 URL 同源。Cookie 为 HttpOnly、SameSite=Strict，HTTPS 下带 Secure，不设置 Domain。不接受普通用户 Bearer，不使用 CORS 或 ALLOWED_ORIGIN。

普通列表返回 `{data: {items, page, pageSize, total}}`，默认每页20、最大50；时间均为 Unix 秒整数，作者字段为 nickname，附 isDeleted；退役作者的教师标识为 false。加分汇总也使用 nickname，保留旧 ID 的流水。学期字段为 termId。讨论 JSON 请求体上限128 KiB；原账号 JSON 上限8 KiB和头像2 MiB限制独立保留。`X-Request-Id` 在响应头中，错误正文不增加 requestId。

## 与组员4对接

资料存入 `contents`，`kind=material`；使用统一的 course_id、author_id、title、body（资料简介）、tags、status 和修改时间。`materials` 表已删除。`file_versions.material_id` 外键引用 `contents.id`，触发器只允许指向 material 行；文件版本的其他字段本次保持原样。资料主页承载评论，版本没有独立评论区。

回答以 `target_kind=question` 指向所属问题，评论指向 material/question/answer/comment 中的直接父内容；target_id 是 contents 自引用外键，插入触发器校验类型、同课程和可见性，父级不可改写。资料的详情、元数据编辑、删除、举报与下架可使用现有 contents 通用接口；赞踩仍只开放问题、回答、评论。发布资料及文件上传、预签名、确认、预览、下载仍由组员4实现，文件访问须检查资料及版本状态。问题只保存 Markdown 引用，不因链接文件下架而隐藏。

内部接口需要独立的 `INTERNAL_API_TOKEN`，至少24字符。未配置时返回503；普通用户令牌不能使用。将 `.dev.vars.example` 复制为 `.dev.vars` 可本地配置，实际值不提交。内部凭据与 Cloudflare 管理 token 是两回事，不能混用。

`GET /api/internal/events?after=0&limit=50` 返回 `{data: {items, nextCursor, hasMore}}`，按 seq 升序返回事务事件。消费者以 `eventId` 做持久化去重，在自己的通知/索引操作成功后推进游标，可调用 `/api/internal/events/ack` 标记已处理。ack不删除事件，也不替代消费者的事务。当前接口是拉取协议，本交付不运行通知消费进程。

内容事件携带课程、内容、操作者、作者，以及直接父级 targetKind、targetId、targetAuthorId 和新旧采纳答案作者ID。资料使用 material.created/material.updated/material.hidden 等同类事件。历史事件在0011中同步转换载荷字段，eventId、seq 和确认状态保留；消费者据直接父级查找根讨论及收藏订阅对象。消费者排除操作者，合并多种订阅后按 `(eventId,recipientId)` 去重；收藏关系以消费时/约定时的有效状态核对。

搜索初始化使用 `/api/internal/documents`，只包含可见课程、资料、问题和回答。返回 `{data: {items, nextCursor, hasMore, watermark}}`。记录第一页的 `watermark`，全部分页结束后重放大于该值的事件，关闭分页期间的变更窗口。不要用最后一页的新 watermark 跳过中间事件。

消费事件时通过 `/api/internal/contents/:id` 复查当前可见性；不可用返回 `{data: {id,available:false}}`。内容下架时应重新检查整个子分支并移除不可见搜索文档，恢复时重查。删除父内容只移除该内容的文档，保留仍可见子内容；不能把 deleted 当作 hidden 传播。通知展示和跳转同样遵循当前可见性，不缓存下架原文。

课程近期活动和个人空间不会直接公开 outbox 原始载荷，避免内容下架后从历史事件泄露。事件表先保留供重放，清理策略留给后续共同设计。

## 部署与资源

2026-10-26起，部署只走 main 的 GitHub Actions。个人分支的首次草稿提交不触发部署。合入main后dev会自动运行测试、应用远程D1迁移和发布；生产需手动运行与审批。

本次保留 `backend/wrangler.json` 的现有环境配置，迁移追加为0006（单身份约束）、0007（讨论表和课程追加列）、0008（视图和触发器）。不复制原独立 database 迁移，不创建第二套 users 或 sessions。旧课程空编号允许并存，已设非空编号保持唯一；旧课程更新时间回填创建时间，无操作者时不伪造课程事件。历史账号有多个身份时0006会拒绝执行，需先由组员1确认处理。后续 0010 将账户合表，保留历史外键和业务数据；名单关系改为直接引用 accounts 并由触发器校验新关系身份。0011 合并 materials 到 contents，统一直接父级字段，并将旧问题的文件关联追加为正文 Markdown 链接；资料原 ID 与文件版本记录保留，ID 碰撞会整笔拒绝。旧资料没有正文和时间字段，正文初始化为空、创建和修改时间记录迁移时刻，不补造上传历史或创建事件。旧资料的 request_key/request_hash 为 null，正常发布接口仍要求幂等键。当前只进行了隔离本地验证，尚未部署或应用远程迁移。

本地私有CSV是历史联调材料，不随源码提交；其中旧管理token已被组长撤销。后续member凭据只通过临时环境变量使用，云端部署凭据保留在GitHub Environment Secret。
