# 组员3从哪里开始

你负责的是课程与问答互动后端。可以理解为：前端显示页面，你的后端接收“提问、回答、投票、采纳”等请求，检查权限并读写数据库。

**GitHub 用来交代码，Cloudflare 用来运行代码。** 拿到 Cloudflare token 不等于要把 token 上传到 GitHub，也不等于现在就必须部署。组长的新交接明确要求先完成本地联调。

## 目录怎么认

| 目录 | 放什么 | 主要负责人 |
| --- | --- | --- |
| `backend/` | 接口和业务逻辑，以及后端自己的依赖配置 | 组员1、3、4按业务协作 |
| `frontend/` | 主站页面 | 组员2 |
| `admin/` | 人员、名单与权限管理页面 | 组员1 |
| `database/` | 建表、迁移、初始化数据及共享结构 | 组员1统筹 |
| `docs/` | 分工、需求、联调与使用说明 | 全组 |
| `.local/` | 个人密钥、临时验证材料 | 只在自己电脑，不提交 |

旧文档里的 `briefing/` 就是早期提案材料；最新 main 已将这些文档放在 `docs/`，不是你需要另建的代码目录。不要把真实 `.sqlite` 数据库文件当源码提交。

## 本地先跑起来

在 `backend/` 按 [README](../../backend/README.md) 依次安装、迁移、导入样例和启动。打开 <http://127.0.0.1:8787/>，现在会进入可操作的本地验收页面。若旧页面仍只有几行文字，按 Ctrl+F5 刷新。`/api/health` 另用于检查服务状态。

按页面上方的身份选择器走一遍：学生甲发布问题 → 学生乙回答 → 数学教师在“课程加分”中启用奖励 → 回到问答采纳 → 查看加分流水。还可测试评论、赞踩、举报、下架与恢复。所有结果实际写入本地数据库，原演示文字不会代替业务请求。

这个页面属于组员3的本地验收工具，只在本地运行时出现，便于单独演示后端功能。

本分支基于10月22日的旧main；当时使用组员2的 `2-dev` 忽略副本验证了代理。最新main现已合入前端、账号和共享数据库，需要先做适配。本分支的独立验收页可以验证业务，但还没有接入最新版主站。

想先确认你的业务流程能运行，在 `backend/` 执行 `pnpm demo`：它会真实演示学生提问、回答、教师采纳加2分、重复采纳不再加分、下架后撤回2分。

## 怎么交给组长

本地分支已经叫 `3-course-discussion`，符合组内规则。本次按“先提交”的要求，将现有本地版本归档到个人分支，并以草稿PR供组长审阅。当前尚未适配最新main，不能直接合并；适配后继续更新同一个分支和PR。

终端示例，先回到仓库根目录：

```powershell
git status
git diff
git add backend database docs/member3 README.md
git diff --cached --stat
git diff --cached
git commit -m "feat(discussions): 实现课程与问答互动后端"
git push -u origin 3-course-discussion
```

确认暂存内容不含 `.local`、CSV 密钥、本地数据库、`node_modules` 和运行缓存，再执行 commit。推送后在 GitHub 将 `3-course-discussion` 向 `main` 发起 PR，说明“组员3后端、45项定向测试、共享表和加分规则仍需协调”。不要直接覆盖 main。

旧 `coursestack-management` token已撤销，过去的只读检查只是10月22日的历史结果，不能代表当前权限。当前member凭据按组长要求仅通过当前终端会话环境变量使用，不写入文件、PR或聊天。提交源码不需要提供Cloudflare token。

本地已有的私有配置、CSV和数据库不会进入提交。涉及共享表、账号权限和加分规则的适配见[提交状态](./提交状态.md)。
