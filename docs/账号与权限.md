# 账号与权限

账户基本信息统一保存在 `accounts`，普通成员只有 student 或 teacher 一种身份，admin 独立且全库至多一个。没有公开注册；管理员通过[运维命令](./管理员操作.md)初始化，再建立师生账号。

## 账户字段与隐私

ID 是不透明 UUID，切换身份时生成新 ID；学工号不能用作公开 ID。

| 数据库字段 | 约束与用途 | HTTP 字段 |
| --- | --- | --- |
| `id` | TEXT 主键，不复用旧身份 ID | id |
| `nickname` | 可空；有值时去首尾空白后 1–80 字符，公开昵称 | nickname |
| `role` | student / teacher / admin | role |
| `status` | active / disabled / deleted | status |
| `school_number` | 非管理员登录标识；去首尾空白，保留前导零、区分大小写；未删除账号间唯一；CHECK 要求未删除的学生、教师非空，管理员为 null | schoolNumber |
| `password` | PBKDF2 散列；null 表示未开通登录或身份已删除 | 不返回 |
| `must_change_password` | 默认 false，要求登录后先改密 | mustChangePassword |
| `credential_version` | 正整数，默认 1；用于会话准入 | 不返回 |
| `name` | 可空，最多 80 字符，学生也可不填 | name |
| `department`、`major` | 可空，各最多 120 字符 | department、major |
| `grade` | 可空，最多 40 字符 | grade |
| `avatar_key` | 可空，当前头像 R2 键 | avatarUrl，使用 Worker 地址 |
| `created_at`、`last_login_at` | 创建时间非空，最近登录时间可空 | createdAt、lastLoginAt |

昵称、姓名、院系、专业、年级的空字符串保存为 null。完整账号详情包含上述可返回字段，仅本人和管理员可读取；公开 DTO 只包含 `id`、`nickname`、`avatarUrl`、`isDeleted`，展示时应处理昵称为空。不收集邮箱，学籍信息直接保存在 `accounts`；教学班名单接口只向本人当期教师和管理员提供班内学生的必要学籍信息，见[课程与成员](./课程与讨论.md#课程学期与成员)。

其他表引用 `accounts.id`。公开作者使用 `getPublicProfile` 字段白名单；不能把管理端响应直接用于公开展示。已删除作者显示“已删除”、无头像、不再显示教师标识。

## 教师公开主页

仅 `role=teacher` 且 `status=active` 的账号提供主页；不存在、禁用、已删除及非教师账号统一返回 `404 TEACHER_NOT_FOUND`。游客可读取，头像仍通过原公开头像入口提供，不公开姓名、学工号、院系、班级名单、积分或存储键。

| 方法、路径 | 返回与行为 |
| --- | --- |
| `GET /api/teachers/:id` | `id`、可空 `nickname`、可空 `avatarUrl`、`isTeacher=true`、`isDeleted=false` |
| `GET /api/teachers/:id/counts` | `courses`、`materials`、`questions`、`answers`、`comments` 五个非负整数；课程跨学期去重，资料按内容计数而非文件版本数 |
| `GET /api/teachers/:id/activity` | `kind=course|material|question|answer|comment`，默认 course；`page=1–10000`、`pageSize=1–50`，默认 1 和 20；返回 `kind`、`items`、`page`、`pageSize`、`total` |

课程项为 `{kind: "course", id, name, introduction, terms: [{id, name, current}]}`，按本学期授课优先、课程号升序排列；学期当前优先、ID 降序。每门课程只出现一次，不附带学生关系。其余项复用公开 Content DTO，资料附带 latestVersion，按 createdAt 降序、ID 升序稳定分页，编辑不会改变发布顺序。

内容项额外返回 `courseName`、`root: {id, kind, title}` 与可空 `quote`；root 为所属问题或资料。评论回答、回复评论时，quote 为 `{kind, available, author, excerpt}`，只引用直接回应的一层，纯文本摘要最多 160 字加省略号。原对象不可公开时 available=false，author 和 excerpt 均为 null；原对象仍公开但作者已删除时只返回公开作者占位。回答提供 isAccepted。

计数、分页和引用都使用公开内容视图，即使访问者为作者或管理员也不放宽；祖先下架或删除的内容不计入，删除评论的占位不计入。回复引用不构成所属父子关系，原评论不可用不隐藏仍公开的回复。计数和分页分别反映请求时的当前状态，不提供跨请求快照。

这些接口由 `src/teachers/` 汇总现有账号、授课和内容数据，无数据结构迁移。组员 1 的账号与教学班权限不变；组员 3、4 的公开内容、采纳及版本状态直接影响计数和分页；组员 2 按此契约展示和定位。规范已纳入 OpenAPI。

## 登录与会话

账号接口的 JSON 请求体上限 8 KiB，CSV 导入预检例外为 2 MiB。响应格式与同源要求见[请求与联调](./架构与开发.md#请求与联调)。

| 方法、路径 | 输入 | 成功返回 |
| --- | --- | --- |
| `POST /api/auth/login` | schoolNumber、password | id、nickname、role、mustChangePassword，并设置 Cookie |
| `POST /api/auth/admin/login` | password | 同上 |
| `GET /api/auth/me` | 有效会话，允许待改密状态 | 当前身份 |
| `POST /api/auth/logout` | 可重复调用 | loggedOut，撤销当前会话并清除 Cookie |
| `POST /api/auth/password` | oldPassword、newPassword | passwordChanged，撤销全部会话并清除 Cookie |

会话有效期 7 天，不滚动续期，允许多设备并存。256 位随机令牌通过 `coursestack_session` Cookie 传递，数据库仅存 SHA-256 摘要。Cookie 为 HttpOnly、SameSite=Strict，HTTPS 下加 Secure，不设置 Domain。普通业务不接受 Bearer 用户身份。

同一浏览器的标签页共用这个 Cookie，不支持同时登录多个账号。前端的写请求携带 `X-Expected-Account: <页面显示的账号 ID>`，它与 Cookie 对应的账号不一致时返回 `409 ACCOUNT_CHANGED`，操作不执行；读取请求、登录接口和不带此请求头的调用不做比对。登录、退出或改密成功后，前端通过 BroadcastChannel 通知其他标签页重新读取 `GET /api/auth/me`：账号未变时页面不受影响；已无有效会话时转为未登录；从一个账号直接换成另一个账号时重新挂载当前页面，尚未提交的内容随之清除，避免以新账号提交。

密码使用 WebCrypto PBKDF2-HMAC-SHA256、30000 次迭代和 16 字节独立随机盐，存为 `pbkdf2-sha256$<迭代次数>$<盐>$<散列>`，校验时按记录的迭代次数计算，调整次数不影响已有散列。迭代次数受 Workers 免费计划每次请求 10 ms 的 CPU 上限约束：本机实测 30000 次约 4.3 ms，50000 次约 7.5 ms 已接近上限，100000 次（Workers PBKDF2 的最大值）约 16 ms 与纯 JS bcrypt cost=12（约 230 ms）均超限。账号不存在时仍执行一次派生，使响应耗时一致。

用户自行设置的新密码为 8-64 个 Unicode 字符（按码点计数），界面提示“8-64 字符”；管理员建号、初始化及重置允许非空短密码，最多 64 个字符。前后端采用相同计数方式，不裁剪密码空白。登录与旧密码校验同时兼容旧规则下 UTF-8 不超过 72 字节的已有密码，避免长度规则调整阻断登录；新建和重置密码不适用该兼容范围。密码散列格式、接口字段及数据库结构不变，前后端须同步更新校验规则。

登录每 15 分钟按来源 IP 最多 50 次，成功与失败均计数，在校验密码之前检查。同一账号（学工号或管理员入口）在同一来源 IP 失败满 10 次后，该来源 15 分钟内不能再登录这个账号；只统计失败，登录成功即清零，其他来源不受影响，他人因此无法通过反复输错密码锁定账号。改密每账号每 15 分钟最多 10 次。local 共用本地来源桶。限流键摘要化保存，不记录原始 IP 或学工号；过期计数在成功登录时清理。CPU 耗时与限流仍待在生产环境验证。

账号接口的常见错误：401 未登录或凭据无效，403 来源或权限不足，405 方法不支持（附 Allow），413 请求体过大，415 非 JSON，429 限流；未知数据库错误返回通用 500，不泄露 SQL、散列或内部异常。

## 账号管理接口

以下接口仅管理员可用，JSON 对象拒绝未声明字段。

| 方法、路径 | 输入与行为 |
| --- | --- |
| `GET /api/admin/accounts` | page、pageSize、role、status、q；排除已删除身份 |
| `GET /api/admin/accounts/:id` | 返回未删除账号完整详情 |
| `POST /api/admin/accounts` | role、schoolNumber、password；nickname、name、department、major、grade、mustChangePassword 选填；201 返回完整详情；支持 Idempotency-Key |
| `POST /api/admin/accounts/import/preview` | rows 数组，1–500 项，每项为 line 和 values；只校验并返回逐行状态，不创建账号 |
| `PATCH /api/admin/accounts/:id` | 至少一个 nickname、status、role、schoolNumber、name、department、major、grade；仅修改提交字段，role 改变时替换身份 |
| `DELETE /api/admin/accounts/:id` | 标记删除身份，返回 id、deleted: true |
| `POST /api/admin/accounts/:id/password` | 可选 newPassword、mustChangePassword；重置成员密码 |

分页默认 page=1、pageSize=20，最大 100；role 可筛选 student / teacher / admin，status 可筛选 active / disabled。q 搜索昵称、学工号、姓名、院系、专业、年级，按创建时间倒序、ID 升序排列。

不能通过 HTTP 新增管理员，或禁用、删除、改变唯一管理员身份、为其设置学工号。学工号冲突返回 `409 SCHOOL_NUMBER_EXISTS`，账号事务整体回滚。

同字段并发修改按最终写入顺序生效，不同字段不互相覆盖。状态、学工号更新及密码重置提升 `credential_version` 并撤销全部会话，仅修改个人资料不影响登录。

## CSV 批量创建账号

管理员在 `/manage/accounts` 下载 UTF-8 BOM、仅含表头的 CSV 模板，再通过“CSV导入”上传并预检。每个文件不超过 2 MiB、500 条非空数据，支持带引号的逗号、双引号和换行；表头可以调序，可选列可以省略，空列、未知列、重复列、缺少必填列或列数不一致时拒绝整份文件。学工号列须以文本填写，保留前导零。

模板表头：`身份,学工号,姓名,院系,专业,年级,昵称,初始密码`。身份只接受学生/教师（也接受 student/teacher），学工号必填、最多64字符；姓名和昵称最多80字符，院系和专业最多120字符，年级最多40字符。除密码外去除首尾空白，可选字段留空存 null；姓名不会用作公开昵称。密码保留全部空白，最多64个 Unicode 字符；留空由浏览器为每个新账号独立生成随机初始密码。导入默认勾选首次登录改密，单账号 API 省略 mustChangePassword 时仍默认 false。

预检请求的 `values` 包含 role、schoolNumber、name、department、major、grade、nickname、password 八个字符串（省略的 CSV 列由前端补空），`line` 为原文件中该记录开始的物理行号。响应为 `{ items: [{ line, status, message }] }`，不回传密码：

- `ready`：字段有效，可创建。
- `existing`：同身份的学工号已存在（含禁用账号），跳过，原资料和密码不变；另一身份占用时为 invalid。
- `duplicate`：文件中同学工号的规范化内容完全相同，只保留首行。
- `invalid`：字段错误或同学工号内容冲突；冲突组中的所有行均需修正。

用户确认后仅提交有效行，浏览器最多同时发起两个单账号创建请求，显示进度和逐行结果。每行生成固定请求键和密码，30秒超时、网络错误、429 或 5xx 时暂停继续派发，已发送的另一请求可以完成；“重试并继续”复用相同请求键、密码和改密要求。提交时再次出现学工号冲突会重新预检，不覆盖已存在账号。已删除身份的学工号允许建立新 UUID，不继承历史业务。

`Idempotency-Key` 可选，格式为 8–100 位字母、数字、下划线或连字符。同一操作者和请求键的成功重试返回原账号；不同请求内容返回 `409 IDEMPOTENCY_CONFLICT`。账号创建和 `account_creation_requests` 记录在同一 D1 batch 中提交，该表只保存操作者、请求键、账号 ID、非密码字段摘要和创建时间，不保存密码明文或密码的快速摘要；重试用账号现有的带盐密码散列校验。账号已删除、切换身份、修改学工号、状态或凭据后，旧请求返回 `409 CREATED_ACCOUNT_CHANGED`，不会重新创建或重置密码。

完成后可下载仅含本次确认创建成功账号的凭据，以及带原行号、错误原因的失败/待确认/未处理记录。初始密码只保留在当前弹窗内存和用户主动下载的文件中，不写日志或浏览器存储；未下载凭据时关闭须确认。待确认行应优先在原弹窗重试，关闭后重新上传只会按已存在账号跳过，不能恢复该次随机密码。失败 CSV 可修改后再上传，识别并忽略“原行号”“错误原因”列；该格式为所有非空文本添加单引号保护，重导时还原一层前缀。凭据文件对可能触发表达式或丢失前导零的文本也添加保护前缀，该前缀不属于原始学工号或密码。

数据结构由 `0009_account_creation_requests.sql` 追加，部署前先应用迁移。组员1维护创建、预检与幂等记录；组员2使用共享 CSV 字段约定与导入弹窗；组员3、4的课程关系、内容和历史身份归属不受影响。预检契约已同步 OpenAPI，原单账号创建仍由账号处理器提供。

## 删除账户与切换身份

管理员在“账号管理”中打开该师生账号的“更多”，选择切换身份或删除账号。确认窗口显示目标学工号和对历史数据的影响。操作成功后刷新列表，后续操作使用返回列表中的账号 ID。

两者都保留全部业务记录，包括课程、历史关系、内容与文件版本、投票、采纳、积分流水、举报和内容审查；后续关注、收藏、通知也须遵守。不会因作者删除自动下架内容、取消采纳或冲销积分。

旧账户保留 ID、原角色、创建时间和凭据版本，作为历史外键占位；设为 `status=deleted`，清空昵称、学工号、密码、受控资料、头像引用及最近登录时间，不允许登录或出现在账号列表。公开 DTO 将其昵称显示为“已删除”。

切换师生身份在一个 D1 batch 内创建新 UUID、复制基本信息（新身份先以自身 ID 作临时学工号以满足 CHECK），将旧身份标记删除并提升凭据版本、撤销会话，释放并转交学工号，再清空旧身份基本信息。任一步骤失败则整体回滚。

新账号保留昵称、姓名、院系、专业、年级、头像、密码、改密要求、创建／最近登录时间及 active / disabled 状态，本次提交的字段修改同时生效。返回完整新账号及 `previousId`，前端须使用新 ID，原会话重新登录。旧课程权限、修读资格、内容所有权及加分仍属于旧 ID，不转给新身份，也不按相同学工号继承。

删除账户不创建替代账号，并尝试立即清理无引用头像。旧学工号可以用于之后的新账号；历史授课、修读关系允许引用已删除身份，但不授予权限，新关系不能指向已删除账号。

## 请求准入与权限

请求入口校验会话、到期时间、凭据版本、active 状态、改密要求及角色，并保存服务端身份快照。普通退出、禁用、重置密码或会话到期阻止后续请求，不取消已经获准的请求。

业务写入 SQL 核对服务端身份 ID 仍存在且状态不是 deleted；身份标记删除后，旧请求不能继续写入。账户修改还要核对目标未删除，冲突返回 `409 ACCOUNT_DELETED`。不要接收客户端提供的操作者 ID 作为身份依据。

后端使用 `requireSession` 或讨论认证中间件取得身份，再在业务语句内用 `permissions.ts` 的 SQL 判断核对具体课程、学期和内容状态。`administration` 要求管理员身份。`coursePublication` 允许本学期修读或教授该课程的师生及管理员提问和首次上传资料。`management` 允许本学期课程教师或管理员管理共享内容。`classManagement` 允许教师管理本人当前学期教学班，管理员可跨班操作。`editPermission` 校验作者身份。

## 本人资料与头像

| 方法、路径 | 权限与行为 |
| --- | --- |
| `GET /api/me/profile` | 登录，返回本人完整资料 |
| `PATCH /api/me/profile` | 登录，仅接受 nickname |
| `GET /api/profiles/:id` | 匿名，返回公开 DTO；禁用或不存在为 404 |
| `PUT /api/me/avatar` | 登录，上传图片原始二进制并替换头像 |
| `DELETE /api/me/avatar` | 登录，清除头像 |
| `GET /api/profiles/:id/avatar` | 匿名，读取当前有效头像；无头像、禁用或已删除为 404 |

头像支持 PNG、JPEG、WebP，最多 2 MiB，Content-Type 须匹配文件签名；不接受 SVG、远程 URL 或客户端 R2 键，不需要 If-Match。每次独立存储，只保留当前头像；角色切换保留正在使用的头像。

个人设置先在浏览器打开裁切界面，再上传裁切后的 512×512 PNG；原图不会上传。选择范围为 PNG、JPEG、WebP，不额外限制原图的字节数和像素数，2 MiB 上限仅校验实际上传文件。浏览器解码后将工作图最长边缩至不超过 2048 像素，固定当前帧，支持拖动、滚轮缩放和双指开合缩放。取消裁切不产生写请求，上传失败保留裁切状态供重试。输出使用 Canvas 2D 与 PNG `toBlob`，不要求 WebP 编码或服务端图像处理。无法解码或缺少所需能力时提示重新选图／更换浏览器。前端的正方形裁切是交互约束，直接调用接口仍沿用上述格式和大小校验。

上传或移除成功后，前端按账号同步当前头像并更新图片地址版本，刷新导航栏、设置页及已挂载的内容作者头像；无头像或图片加载失败时使用默认展示。内容作者 DTO 同步提供可空 `avatarUrl`，见[课程与讨论](./课程与讨论.md)。

引用更新与读取被替换键在同一事务中完成，删除对象前复查已无账户引用。上传、更新和即时清理登记到 `waitUntil`，清理最多尝试三次；失败写入尝试删除新对象，清理失败不回滚已成功更新，接受少量残留对象。没有头像登记表、历史恢复或定时清理任务。头像通过 Worker 读取私有 R2，禁用缓存并设置 nosniff 与受限 CSP。

## 成员密码重置

普通成员忘记密码时，由管理员在系统外核实身份、重置并交付新密码；唯一管理员使用[外部恢复](./管理员操作.md)。

- `newPassword` 省略或空字符串时生成 24 位十六进制密码，仅在本次成功响应的 `generatedPassword` 返回；null 或非字符串为 400。明文不进入列表、审计、日志或前端持久存储。
- `mustChangePassword` 默认 false；管理界面的“要求用户重置密码”默认勾选。
- 登录与 me 返回该标记；为 true 时允许查询登录状态、退出和改密，受保护接口返回 `403 PASSWORD_CHANGE_REQUIRED`，课程讨论中间件同样拦截，前端进入 `/settings/password`。
- 强制改密不能沿用临时密码。当前密码错误返回 `400 INVALID_CURRENT_PASSWORD`，保留会话供纠正输入；成功后清除改密要求，注销全部会话。
- 重置与改密原子更新散列、凭据版本、改密标记和会话。重置同时清理该成员在所有来源上的登录失败计数及改密限流，保留共享 IP 限流，不保存密码明文。
