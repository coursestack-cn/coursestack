# 分工方案

本方案面向四人团队，作为组内提案，具体成员待分配。分工以主责范围为基础：一人统筹数据库与账号权限后端，一人负责全部前端，两人承担主要业务后端。

## 总体分工

| 成员 | 方向 | 主要职责 |
| --- | --- | --- |
| 组员 1 | 数据库架构与账号权限后端 | 数据库总体设计；账号、身份、授课与修读关系、权限后端；管理端所需的人员、名单、学籍与权限接口 |
| 组员 2 | 全部前端与交互 | 公共布局和组件；登录、个人设置、课程、资料、问答、收藏、搜索、通知等主站页面；课程管理与管理端页面 |
| 组员 3 | 课程与互动业务后端 | 课程信息、问题、回答、评论、赞踩、采纳、课程加分，以及相应的内容管理 |
| 组员 4 | 资料与信息服务后端 | 资料、文件、版本、预览下载、关注、收藏、搜索、站内通知，以及相应的资料管理 |

## 组员 1：数据库架构与账号权限后端

- 汇总各模块的数据需求，协调表结构、关联关系、约束、索引和数据库结构变更。
- 实现账号建立、登录会话、身份与权限校验、个人资料和受控学籍维护。
- 实现教师授课关系、学生名单导入、修读关系及学期归档等成员管理功能。
- 提供管理员和教师管理人员、名单、学籍与权限所需的接口，页面由组员 2 实现。

数据库负责人统一设计与审核，各业务负责人承担自己模块的数据访问和业务校验。账号相关页面和管理端页面由组员 2 对接相应接口。

## 组员 2：前端与交互

- 统筹公共布局、路由、公共组件、页面状态和交互风格。
- 实现登录与个人设置、三类课程入口、课程详情、资料及版本、问答讨论、个人空间、搜索和通知页面。
- 实现教师的课程管理页面，包括名单导入、授课教师和加分配置，以及管理员使用的管理端。
- 实现文件上传与进度、文件预览、内容编辑与预览、筛选分页、权限状态和异常反馈。
- 对接组员 1、3、4 的接口，完成前端功能验证。

全部前端页面由组员 2 实现，包括主站、课程管理和管理端；后端接口仍按业务归属由组员 1、3、4 提供。

## 组员 3：课程与互动业务后端

- 实现课程名称、简介等课程信息与课程内容入口。
- 实现问题、回答及资料、问题、回答下的评论，处理发布、编辑、删除和文件版本关联。
- 实现赞踩、排序、采纳与取消采纳、解决状态和课程加分，按确定后的规则处理加分撤回或调整。
- 实现问题、回答和评论的举报、审查、下架和恢复。
- 向搜索、通知和个人空间提供所需的课程与讨论数据及业务事件。

这一部分主要负责课程中的讨论与教学互动，重点是权限、状态变更、重复操作和数据一致性。

## 组员 4：资料与信息服务后端

- 实现资料信息、分类、文件上传、版本、预览、下载和相应的访问控制。
- 处理文件与数据库记录的一致性，以及资料和文件版本的举报、审查、下架和恢复。
- 实现课程关注、资料与问题收藏、搜索，以及相关的个人动态查询。
- 实现通知保存、列表、已读、去重和订阅关系变化处理。
- 配合网络运维完成 R2 文件联调配置，并负责上传访问流程的验证。

这一部分主要负责资料管理、内容查找、收藏和更新通知。将关注、收藏和搜索放在这里，可以分担组员 3 的业务范围。

## 交叉功能的边界

| 功能 | 协作方式 |
| --- | --- |
| 课程与学期 | 组员 1 负责统一 enrollments、terms.current 和成员管理；每个课程实例恰好一位教师且只能在当前学期新建；组员 3 建课时同步写入教师关系；组员 4 负责主动关注关系 |
| 正文引用文件 | 组员 2 在 Markdown 正文提供资料或版本链接；组员 4 提供相应文件页面所需接口，不保存问题与版本的数据库关联 |
| 资料评论 | 评论功能与评论内容管理归组员 3；资料本身及文件状态归组员 4 |
| 搜索 | 组员 4 实现检索与结果组织；其他后端负责人共同明确各类内容的字段、权限和可见状态 |
| 通知 | 各业务负责人明确触发条件与接收对象，组员 4 实现统一保存、查询、已读和去重 |
| 举报与下架 | 资料本身归组员 4，问题、回答和评论归组员 3；组员 1 提供身份与权限基础 |
| 内容管理页面 | 主站中的资料、问答和内容审查入口，以及管理端的全站内容管理页面，均由组员 2 实现；对应接口由组员 3、4 提供 |

## 工作量与协作安排

组员 1 的压力集中在前期数据设计和账号权限后端，组员 2 负责全部前端，压力贯穿页面与交互实现。组员 3 的采纳加分等规则较密集，组员 4 的文件、检索和通知也需要处理失败与一致性问题，工作量不能只按功能名称数量比较。

全部前端由组员 2 统一实现，包括管理端以及文件上传、上传进度和预览组件。组员 1、3、4 优先完成业务后端并提供接口约定，前端按接口进度联调。

开发前共同列出页面清单、后端功能清单和接口约定，明确每项的负责人、输入输出、权限、分页和错误反馈。各成员负责自己模块的实现、文档与验证，联调发现接口问题时由对应后端负责人处理。

全组共同验证完整流程：建立账号、导入学生、上传资料、通过正文链接引用文件提问、回答与采纳、记录加分、接收通知、发布新版本以及学期归档。网络运维由我负责，统筹 Cloudflare 项目配置、开发与测试环境、部署及运行维护。备份恢复、联调、测试和演示准备的具体安排在组内确认成员后补充。
