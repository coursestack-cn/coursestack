# 收藏与动态

课程关注统一为课程收藏。课程、整份资料、整个问题讨论共用收藏入口，收藏仅本人可见，跨学期保留；不建立修读或授课关系，也不改变浏览、发布、下载、管理和加分权限。

## 当前实现

- 课程、资料和问题详情提供收藏按钮；访客点击后先登录并返回原页，不自动执行写入。
- 我的收藏按全部、课程、资料、问题分类，可筛选所属课程；每页 20 项，按收藏时间、收藏记录 ID 倒序。
- 重复收藏和重复取消幂等；重复收藏保留原时间，取消后重新收藏生成新记录。
- 资料收藏不固定版本，默认进入最新可用版本；问题收藏包括其回答与评论。收藏资料或问题不自动收藏课程。
- 内容下架或删除后保留通用“内容不可用”占位，不返回标题或正文，不提供公开链接，仍可取消。恢复公开后重新显示。
- 首页课程分类为本学期、历年和收藏；课程动态在下方独立展示。

## 首页动态

动态来源为本学期修读或授课课程与收藏课程的并集，按课程去重。只展示新问题、新资料和资料新版本，按事件发生时间、事件 ID 倒序分页；资料信息编辑、回答、评论、采纳变化不进入课程动态。学期切换或取消课程收藏后，下一次读取重新计算来源；仍在正式关系中的课程不会因取消收藏消失。

读取时通过公开内容视图检查根内容，资料版本事件还检查版本仍存在。课程收藏只影响首页动态，不把课程内每项更新投递到通知中心。动态可展示课程以前已发布的事件，新增收藏不会补发历史通知。

## 通知规则

| 收藏对象 | 产生收藏通知的变化 | 不产生收藏通知 |
| --- | --- | --- |
| 课程 | 无，更新进入课程动态 | 课程内容逐项更新 |
| 资料 | 新版本 | 标题、介绍、标签编辑，资料评论、赞踩及原样重复保存 |
| 问题 | 新回答、采纳或取消采纳 | 问题或回答下的评论、任何内容编辑、赞踩及原样重复保存 |

通知接收者在业务事务中确定，不向操作者本人发送该事件通知。同一接收者同时命中直接互动和收藏时，只保存一条，优先使用回答、评论、回复、采纳或取消采纳的直接互动类型。取消收藏不撤回已有通知；重新收藏只接收之后的新事件。隐藏分支中的私下编辑不发布事件；上下架和删除仍走所有者审查通知。

通知列表重新检查内容可见性。收藏更新指向回答或评论时使用其定位入口，资料进入当前详情；目标不可公开时隐藏标题与跳转。已读状态由服务端保存，跨设备一致；账号切换丢弃旧账号的在途展示结果。

## 接口

以下均带 `/api` 前缀，要求登录，账号从会话取得，客户端不能指定其他接收者。

| 方法与路径 | 约定 |
| --- | --- |
| `GET /me/favorites` | `type=all|course|material|question`、可选 `courseId`、`page`、`pageSize`；默认每页 20，最大 50 |
| `GET /me/favorites/status` | `targets` 为 `{type,id}` 数组的 JSON，1–50 项；返回本人状态及收藏时间 |
| `PUT /me/favorites/:type/:targetId` | 幂等收藏公开对象，不可用时 404 |
| `DELETE /me/favorites/:type/:targetId` | 幂等取消，包括不可用对象 |
| `GET /me/feed` | 本人课程发布动态，分页规则同收藏 |
| `GET /notifications` | `status=unread|read|all`，默认未读；`beforeId` 游标、每批最多 20 条 |
| `GET /notifications/count` | 本人未读数与 viewer |
| `GET /notifications/state` | `ids` 为逗号分隔的 1–20 个通知 ID，同步当前页状态 |
| `PUT /notifications/:id/read` | 仅接收者可幂等标为已读 |
| `PUT /notifications/read` | 通过 `throughId` 将此前通知标为已读，保留更晚通知 |

收藏列表返回 `viewer`、`items`、分页信息、`counts` 和 `courses`。类型计数受课程筛选约束，不受当前类型约束；课程选项来自本人全部收藏。列表项包含 `favoriteId`、`type`、`targetId`、`createdAt`、`available`、可空 `title/description`、`courseId/courseName`。状态查询按类型与目标 ID 匹配，课程号保持原值，内容 ID 使用 API 格式。

完整字段与参数校验见 [OpenAPI](../openapi/openapi.json)。通知保留既有数字 ID 与游标契约，新增 `favorite` 类型、`eventType`、`oldAnswerId/newAnswerId` 及资料版本信息。

## 数据与协作

`favorites` 以账号关联课程或内容外键，两者恰有一个非空；各对象按账号唯一，只允许收藏问题和资料，不允许直接收藏回答或评论。关系行不允许 UPDATE，取消和重新收藏分别删除、新建。

`content_events` 保存不可变事件及操作者、根内容、事件对象、课程、版本或采纳答案变化。新内容和版本使用稳定来源键去重；实际编辑与采纳变化各自产生独立事件。`content_roots` 为讨论找到根对象。业务写入、事件记录和接收者通知由数据库触发器在同一事务完成，失败一起回滚。`notifications(account_id,event_id)` 唯一约束保证同一事件对同一账号最多一条，既有审查和积分来源保持独立。

- 组员 3 的问答、评论与采纳写入沿用现有事务，触发器记录事件；新增发布入口须保留操作者与可见性校验。

## 升级与验证

`0010_favorites.sql` 在 `0008_notifications.sql` 和 `0009_account_creation_requests.sql` 之后执行。升级保留旧通知 ID、来源和已读时间；旧通知 `event_id` 为 null。只回填当前公开问题、资料发布和仍存在的后续资料版本，保留原时间；回填发生在通知投递触发器安装前，不向用户补发历史通知，不推断已丢失的编辑或采纳历史。

定向回归覆盖隐私、幂等、类型隔离、分页和失效恢复，课程并集与学期切换，直接互动与收藏去重、自操作过滤、取消后停止投递，迁移保留已读和不投递历史。可运行 `backend/tests/favorites.test.mjs` 与 `backend/tests/favorites-migration.test.mjs`；仓库静态检查使用前后端 `check`、`db:check` 和 `openapi:check`，不需要完整构建。
