# 架构与开发

`frontend/` 与 `backend/` 是两个独立工程，各自安装依赖。实际版本以各自 `package.json` 和锁文件为准。

## 技术栈与入口

| 部分 | 技术与代码入口 |
| --- | --- |
| 前端 | Svelte 5、TypeScript、Vite；`frontend/src/` |
| 后端 | Cloudflare Workers、Hono、zod；`backend/src/index.ts` |
| 关系数据 | Cloudflare D1、Drizzle；`backend/src/db/schema.ts` |
| 数据库规则 | 视图和触发器；`backend/src/db/rules.sql` |
| 文件 | 私有 R2，绑定名 `FILES`；D1 保存文件元数据 |
| 工具 | Node.js、pnpm、Wrangler；命令与环境配置见各工程配置 |

后端启动、管理员初始化、演示数据、检查和数据库命令统一见[后端开发说明](../backend/README.md)。前端在 `frontend/` 执行 `pnpm install --frozen-lockfile`，日常启动用 `pnpm dev`，静态检查用 `pnpm check`；页面实现见[接入约定](../frontend/src/pages/README.md)。

后端按 `auth`、`accounts`、`courses`、`discussions`、`materials`、`moderation`、`integration` 划分。账号、头像和登录处理器仍由 Hono 入口转发；完整改写为 Hono 路由属于后续工作，须保留现有 Cookie、错误码、请求体限制和回归行为。

## 请求与联调

- 浏览器使用同源 `/api/...`。本地 Vite 代理到 `http://127.0.0.1:8787`，保留 Host、Cookie、Set-Cookie 和路径，`changeOrigin: false`。
- 普通接口成功返回 `{data: ...}`，失败返回 `{error: {code, message}}`，禁用缓存；`X-Request-Id` 放在响应头。
- 普通用户使用 `coursestack_session` HttpOnly Cookie；写请求要求 `Origin` 与请求地址同源，不接受用户 Bearer 身份。内部服务凭据另见[课程与讨论](./课程与讨论.md#搜索与内容供数)。
- ID 是不透明字符串，时间为 Unix 秒，数据库字段用 snake_case，HTTP 字段用 camelCase。分页上限、请求体限制及并发约定以对应主题接口为准。
- 云端由同一 Worker 提供前端资源和 API。`/api` 及其子路径交给后端，其他未知页面路径回退到 `index.html`，见[部署与运维](./deploy-dev.md)。

## 数据结构

| 数据 | 当前模型 |
| --- | --- |
| 账户 | `accounts` 保存单一身份、凭据、可空昵称及受控基本信息；会话单独保存，不设账户审计表 |
| 学期与成员 | `terms.current` 标记唯一当前学期，`enrollments(course_id, term_id, account_id)` 统一授课和修读，按账户角色区分 |
| 内容 | `contents` 统一资料、问题、回答和评论，body 保存可空 ProseMirror JSON 文本；`target_id` 记录直接父级，父级类型查询父记录的 kind |
| 版本 | `file_versions` 以 material_id＋version 为主键，保存内部存储键和文件元数据；公开文件名来自资料 title，`material_next_versions` 保存下一可用版本号；版本只可删除，可见性由资料内容控制 |
| 上传 | `material_upload_sessions` 保存票据状态、处理租约和幂等发布结果，`creation_draft` 暂存首次发布的资料介绍 |
| 课程积分规则 | `course_bonus_rules` 以 id 引用 `courses.id`，单独保存六项非负整数分值，默认均为 0；资料首次上传与后续版本分别计分 |
| 采纳 | `acceptances` 保存问题当前采纳答案，奖励记录独立存入积分流水 |
| 操作记录 | `moderation_actions` 保存审查原因，`bonus_ledger` 保存积分和可选说明，自动积分说明由来源及抵消关系推导 |

所有业务表统一为 SQLite `STRICT`，由 SQL 生成器添加。列类型交给数据库检查，CHECK 保留数值范围、状态枚举和 JSON 等业务约束，不再重复检查存储类型。

只有问题和资料可保存非空标签数组，空数组归一化为 null。课程编号非空且唯一，创建人、修改人及更新时间必填；课程、内容创建均需 `request_key/request_hash`。具体身份与课程约束见[账号与权限](./账号与权限.md)和[课程与讨论](./课程与讨论.md)。

schema 与 rules 维护当前目标结构，`backend/migrations/` 保存按编号追加的 SQL 和 `meta/` 快照。保留既有 `0000_schema.sql`，结构变化通过新迁移升级；Wrangler 按 `d1_migrations` 跳过已应用文件，空库从头应用完整历史。不得改写已应用迁移，也无需删除本地 D1、R2 或迁移记录。完整流程见[数据库结构与迁移](../backend/README.md#数据库结构与迁移)。

删除账户或切换身份时保留业务记录是现行业务规则，与是否支持旧库升级无关。涉及采纳、加分和课程成员的写入需在同一事务保持一致，并验证重复请求、并发和失败回滚。

## 文件、搜索与通知

R2 用于头像和课程资料。资料已实现统一内容列表、上传、版本管理及受控文件访问，具体见[资料与文件](./资料与文件.md)：

1. 后端校验权限并生成短时预签名 URL，浏览器将一个文件上传到私有 R2 临时对象，不查重。
2. 后端核验文件、封存正式对象，再通过 D1 事务发布版本。临时文件和已无版本引用的正式文件由定时任务清理，确认失败可重试。
3. 游客可查看资料介绍与版本信息；预览、下载经 Worker 校验登录、资料状态及版本是否存在。资料标题是跨版本统一的下载文件名。

云端直传需另行配置 S3 凭据和桶 CORS，签名目标与 FILES 绑定必须指向同一桶。本地使用模拟资源，共用上传与发布业务流程，PUT 由仅本地开放的传输接口接收。真实云端验证仍需明确目标桶并配置凭据，见[部署与运维](./deploy-dev.md)。

搜索首版覆盖数据库中的文字及文件名，并验证中文效果；通知先保存数据库记录，通过轮询刷新。当前后端提供当前可见文档分页和内容可见性查询，不维护业务事件表或增量重放协议；收藏、搜索与通知及其同步方式仍待实现。

## 环境与维护

| 环境 | 用途 |
| --- | --- |
| local | 本地 Worker、D1、R2 模拟；回归测试使用临时隔离资源 |
| production | 唯一云端环境，main 更新即自动部署，与本地开发数据、凭据和资源隔离 |

真实密钥、个人数据、本地数据库和运行缓存不入库。云服务费用按实际套餐核对，测试文件和历史文件版本均计入存储；运维统筹资源与部署，各模块负责人配合验证，见[协作分工](./协作分工.md)。

原账号路由的 Hono 改写仍待进行。资料文件、独立采纳与整数积分已同步 schema、业务路由和 OpenAPI，并有隔离 D1/R2 回归测试；资料前端和真实云端文件联调仍待完成。
