# 架构与开发

`frontend/` 与 `backend/` 是两个独立工程，各自安装依赖。实际版本以各自 `package.json` 和锁文件为准。

本文的数据结构与接口说明反映当前实现。2026-11-02 确认的课程号主键、管理员开设课程学期、多教师教学班和独立积分规则尚待迁移，见[课程与教学班目标设计](./课程与讨论.md#课程学期与教学班目标设计)。

## 技术栈与入口

| 部分 | 技术与代码入口 |
| --- | --- |
| 前端 | Svelte 5、TypeScript、Vite；`frontend/src/` |
| 后端 | Cloudflare Workers、Hono、zod；`backend/src/index.ts` |
| 关系数据 | Cloudflare D1、Drizzle；`backend/src/db/schema.ts` |
| 数据库规则 | 视图和触发器；`backend/src/db/rules.sql` |
| 文件 | 私有 R2，绑定名 `FILES`；D1 保存文件元数据 |
| 工具 | Node.js、pnpm、Wrangler；命令与环境配置见各工程配置 |

后端启动、管理员初始化、演示数据、检查和数据库命令统一见[后端开发说明](../backend/README.md)。前端在 `frontend/` 执行 `pnpm install --frozen-lockfile`，日常启动用 `pnpm dev`，静态检查用 `pnpm check`；页面实现见[接入约定](../frontend/src/pages/README.md)。

后端按 `auth`、`accounts`、`courses`、`discussions`、`materials`、`moderation`、`integration` 划分。账号、头像和登录处理器仍由 Hono 入口转发到原处理器，改写为 Hono 路由待进行，改写时保留现有 Cookie、错误码、请求体限制及 405 / Allow 行为。

## 请求与联调

- 浏览器使用同源 `/api/...`。本地 Vite 代理到 `http://127.0.0.1:8787`，保留 Host、Cookie、Set-Cookie 和路径，`changeOrigin: false`；代理配置见[前端联调](../backend/README.md#前端联调)。
- 普通接口成功返回 `{data: ...}`，失败返回 `{error: {code, message}}`，禁用缓存；`X-Request-Id` 放在响应头。
- 普通用户使用 `coursestack_session` HttpOnly Cookie，见[登录与会话](./账号与权限.md#登录与会话)；写请求要求 `Origin` 与请求地址同源，不接受用户 Bearer 身份。内部服务凭据见[搜索与内容供数](./课程与讨论.md#搜索与内容供数)。
- ID 是不透明字符串，时间为 Unix 秒，数据库字段用 snake_case，HTTP 字段用 camelCase。分页上限、请求体限制及并发约定以对应主题接口为准。
- 云端由同一 Worker 提供前端资源和 API。`/api` 及其子路径交给后端，其他未知页面路径回退到 `index.html`，见[部署与运维](./部署与运维.md)。

## 数据结构

| 数据 | 当前模型 |
| --- | --- |
| 账户 | `accounts` 保存单一身份、凭据、可空昵称及受控基本信息；会话单独保存，不设账户审计表 |
| 学期与成员 | `terms.current` 标记唯一当前学期，`enrollments(course_id, term_id, account_id)` 统一授课和修读，按账户角色区分 |
| 内容 | `contents` 统一资料、问题、回答和评论，body 保存可空 ProseMirror JSON 文本；`target_id` 记录直接父级，父级类型查询父记录的 kind |
| 版本 | `file_versions` 以 material_id＋version 为主键，保存内部存储键和文件元数据；公开文件名来自资料 title，`material_next_versions` 保存下一可用版本号；版本只可删除，可见性由资料内容控制 |
| 上传 | `material_upload_sessions` 保存票据状态、处理租约和幂等发布结果，`creation_draft` 暂存首次发布的资料介绍 |
| 课程积分规则 | `course_bonus_rules` 以 id 引用 `courses.id`，单独保存六项非负整数分值，默认均为 0；资料首次上传与后续版本分别计分 |
| 采纳 | `acceptances` 保存问题当前采纳答案，奖励记录独立存入积分流水 |
| 操作记录 | `moderation_actions` 保存审查原因，`bonus_ledger` 保存积分和可选说明，自动积分说明由来源及抵消关系推导 |

字段约束见[账号与权限](./账号与权限.md)、[课程与讨论](./课程与讨论.md)和[资料与文件](./资料与文件.md)。所有业务表统一为 SQLite `STRICT`，结构通过按编号追加的迁移升级，生成与应用流程见[数据库结构与迁移](../backend/README.md#数据库结构与迁移)。

涉及采纳、加分和课程成员的写入需在同一事务保持一致，并验证重复请求、并发和失败回滚。

## 文件、搜索与通知

R2 用于头像和课程资料。资料上传由后端签发短时预签名 URL，浏览器把单个文件直传私有 R2 临时对象；后端核验文件、封存正式对象后在 D1 事务中发布版本。预览和下载经 Worker 校验登录、资料状态及版本。协议与清理见[资料与文件](./资料与文件.md)，云端凭据与桶 CORS 见[部署与运维](./部署与运维.md#域名与-r2-cors)。

搜索首版覆盖数据库中的文字及文件名，并验证中文效果；通知先保存数据库记录，通过轮询刷新。两者尚未实现，当前可通过[内部供数接口](./课程与讨论.md#搜索与内容供数)分页读取可见内容。
