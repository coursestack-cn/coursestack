# 管理员初始化与恢复

管理员密码继续以 bcrypt 散列保存在 D1 的 `accounts.password` 字段中。Worker 不读取 `ADMIN_PASSWORD` 或 `ADMIN_PASSWORD_HASH`。网站不发送邮件，也没有邮箱找回；管理员能登录时使用网站内改密。本文件描述首次初始化，以及管理员忘记密码或网站不可用时的外部恢复。普通成员的密码由管理员通过[管理接口](./组员1-账号管理与资料接口.md#成员密码重置)重置。

运维命令是本机 Node.js 程序，位于 `backend/scripts/`，不新增 HTTP 接口，不部署临时管理页面或维护 Worker。操作对象始终是目标数据库中的唯一管理员，不接受指定普通成员 ID。

## 本地操作

以下命令在 `backend/` 的交互终端执行。首次使用先运行 `pnpm db:setup:local`。

| 命令 | 行为 |
| --- | --- |
| `pnpm admin:init:local` | 首次设置管理员密码；已初始化时拒绝覆盖 |
| `pnpm admin:status --local` | 查询管理员 ID、状态、凭据版本及最近的运维审计 |
| `pnpm admin:reset:local` | 重置已有管理员密码并撤销旧会话 |

也可使用 `pnpm admin:init --local`、`pnpm admin:reset --local`。本地命令固定使用 `backend/wrangler.json` 的 `local` 和 `backend/.wrangler/state/v3`，与日常开发使用同一数据库，并显式关闭远程绑定。

密码输入两次且不回显，允许非空短密码，UTF-8 不超过 72 字节；网站内用户自行设置的新密码至少 8 个字符。初始化最后需输入 `INIT local`，重置需输入 `RESET local`；输入错误或取消时不写入。命令不读取或更新此前保存的本地测试密码文件。

## 生产或其他远程环境

先准备目标 D1 并应用仓库全部迁移，迁移维护方式见[后端开发说明](../backend/README.md#数据库结构与迁移)。运维命令不自动创建数据库、执行迁移或导入本地种子。仓库的日常 Wrangler 配置目前仍只有 local，以下运维目标独立配置。

1. 在 Cloudflare 获取目标账号的 Account ID 和 D1 的 Database ID。
2. 准备允许写入目标 D1 的 Cloudflare API Token。按当前 API 权限使用目标账号的 `D1 Write`，不需要把 Token 配置到网站 Worker。只有查看权限的人员不能进行初始化和重置。
3. 把 `backend/scripts/admin-target.example.json` 复制到被 Git 忽略的 `backend/.local/admin-production.json`，填入真实的两个 ID。配置文件只允许这两个字段，不放 Token、密码或个人资料。

```json
{
    "accountId": "目标 Cloudflare 账号的 32 位 ID",
    "databaseId": "目标 D1 数据库的 UUID"
}
```

先查询状态，再按需要运行一次初始化或重置：

```sh
pnpm admin:status --remote --config .local/admin-production.json
pnpm admin:init --remote --config .local/admin-production.json
pnpm admin:reset --remote --config .local/admin-production.json
```

`admin:init` 和 `admin:reset` 是不同场景的命令，不应在首次初始化后照抄执行重置。

命令会显示 Cloudflare 账号 ID、目标数据库 ID 和管理员状态。API Token 在终端隐藏输入，也可由调用进程的 `CLOUDFLARE_API_TOKEN` 提供；不会自动读取凭据文件或 Wrangler 登录缓存。密码仅支持交互输入，不支持命令行参数、管道、环境变量或写入 SQL 文件。

写操作最后要求输入 `INIT <数据库 ID>` 或 `RESET <数据库 ID>`。核对的 ID 必须对应目标环境。远程模式直接访问 Cloudflare 的 D1 REST API，不会退回本地数据库；缺少目标配置、参数冲突或仍使用本地占位 ID 时会拒绝执行。

生产与测试各自使用一个目标配置文件，例如 `.local/admin-production.json`、`.local/admin-staging.json`。命令不默认选择生产，也不从当前 Worker 部署猜测目标。

## 初始化与重置的保证

初始化在同一 D1 batch 中建立 role=admin 的 accounts 行、密码散列和 `admin.initialize` 审计。已有管理员凭据时拒绝覆盖；已有唯一管理员身份但尚无凭据时补齐凭据。并发初始化通过现有唯一约束保证最多一个成功，不留下多余账号。

外部重置不要求原密码或网站 Cookie；执行权限来自本地文件访问权或 Cloudflare D1 权限。它使用操作开始时读取的管理员 ID 和凭据版本，在同一个 batch 内：

- 再次确认该账号仍是 active 的唯一管理员，且凭据版本未改变。
- 写入新密码的 bcrypt 散列并递增凭据版本。
- 撤销该管理员全部会话。
- 清理该管理员的登录入口及改密限流记录。
- 保存 `admin.password.reset` 审计，返回审计 ID。

账号 ID、昵称、头像、姓名、院系、专业、年级和 data_generation 保持不变；普通成员账号和会话不受影响。来源 IP 的共享限流不会被清除，触发该限流时仍需等待窗口结束。禁用状态或异常的管理员数据不会被命令自动修复。

操作期间若发生正常改密或另一次外部重置，旧版本的外部重置会失败，不覆盖新密码。这里检查的是运维人员确认过的 credential_version，与已删除的 accounts.revision 无关。普通已获准业务请求仍允许完成。任一步骤失败时整批回滚，密码、会话撤销和审计不会部分完成。

应用审计记录 actorId 为 null，表示外部运维，而非伪装成网站管理员操作；不记录原密码、新密码、散列或 Cloudflare Token。运维人员应保留返回的审计 ID，应用本身不会将 Token 对应的 Cloudflare 个人身份写进账号审计。

重置后使用新密码从管理员登录入口重新登录。外部命令不自动登录，也不绕过应用的登录限流。

## 出错与结果不确定

- 已初始化：`admin:init` 拒绝覆盖；确需恢复时改用 `admin:reset`。
- 尚未初始化：`admin:reset` 拒绝创建账号；改用 `admin:init`。
- 凭据或状态变化：重新运行 `admin:status`，核对后重新发起操作。
- Cloudflare 拒绝访问：检查两个目标 ID、Token 有效期和目标 D1 权限。
- 连接中断或响应异常：命令不自动重试。先用 `admin:status` 核对凭据版本、运维审计和操作时间，并尝试新密码，避免在结果不确定时重复重置。

终端只输出受控错误说明，不输出 Cloudflare 返回的 SQL、参数、原始异常或 Token。没有真实云端写入授权时，只在隔离本地 D1 和模拟传输中验证流程，不能将这类测试描述为生产联调成功。
