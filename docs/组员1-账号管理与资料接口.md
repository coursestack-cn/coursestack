# 账号管理、个人资料与学籍维护

本轮承接[账号与权限基础](./组员1-账号与权限基础.md)，实现组员 1 的账号管理和资料维护后端。操作人已明确：通过邮箱验证找回密码；学工号、真实姓名和邮箱统一由管理员维护，用户只修改公开名称与头像；已有任何学期授课或修读记录的账号不直接切换师生身份。唯一管理员继续使用密码登录，不需要学工号，首次登录不强制改密。

## 已完成及范围

- 管理员分页查询账号、查看详情、禁用／恢复、维护师生身份及私有资料。
- 本人查询资料、修改公开名称、上传／删除头像；匿名读取公开资料及头像。
- 教师在当前授课与修读范围内，通过 HTTP 读取指定学生必要学籍。
- 邮箱归属验证、普通成员及唯一管理员的邮箱找回密码。
- 并发修改检查、会话撤销、修改审计、头像失败清理和本地邮件验证工具。

本轮提供后端与联调约定。登录、个人设置、邮箱验证及重置密码页面归组员 2；管理员和教师的管理页面仍由组员 1 后续实现。授课管理、名单导入和学期管理不在本轮范围内。

## 管理接口

所有接口沿用 `{data: ...}` / `{error: {code, message}}`。写请求要求同源 Origin。JSON 对象拒绝未声明字段；修改前读取详情取得 `revision`，成功后使用返回的新值，409 时刷新资料再编辑。

| 方法、路径 | 输入 | 行为 |
| --- | --- | --- |
| `GET /api/admin/accounts` | page、pageSize、role、status、q 查询参数 | 管理员账号列表 |
| `GET /api/admin/accounts/:id` | 管理员会话 | 账号详情及私有资料 |
| `POST /api/admin/accounts` | 原有建号字段；新增可选 email，教师也可填写 realName | 原子建号，记录审计；邮箱初始未验证 |
| `PATCH /api/admin/accounts/:id` | revision；至少一个 status、role、schoolNumber、realName、email | 受控修改；并发或字段冲突整体回滚 |
| `GET /api/admin/accounts/:id/audit` | page、pageSize | 查询该账号的修改记录 |

分页默认 page=1、pageSize=20，pageSize 最大 100；返回 items、total、page、pageSize。role 支持 student / teacher / admin，status 支持 active / disabled。q 按公开名称、学工号、真实姓名、邮箱做文字子串查询；该查询仅管理员可用，不是公开用户搜索。排序按创建时间倒序、ID 升序。

账号详情字段：id、publicName、avatarUrl、roles、status、revision、createdAt、lastLoginAt、schoolNumber、realName、email、emailVerifiedAt。密码散列、会话和邮箱令牌均不返回。仅管理员详情与本人资料允许返回私有字段，不能复用为公开作者组件的数据源。

维护约束：

- 不允许禁用唯一管理员、改变其身份或为其设置学工号；不提供删除账号和新增管理员接口。管理员可以维护自己的真实姓名和邮箱。
- 学工号全局唯一，保留前导零、区分大小写，去掉首尾空白；修改学生学号时，登录凭据和学籍表同步更新。
- 邮箱可设为 null 清除；非空邮箱去掉首尾空白并统一小写后全局唯一。修改邮箱取消原验证状态，旧邮件链接全部失效。
- realName 为非空字符串、最多 80 个字符；学生必须保留真实姓名和学号。当前仅维护姓名、学号这些已明确的必要学籍，不擅自扩展身份证号、住址等字段。
- 身份只能在 student / teacher 之间切换，且账号不得已有任何授课或修读记录，也不得是多重身份；历史关系不会被删掉来迁就身份变更。
- 改变身份、状态、学工号或邮箱时撤销该账号所有会话及邮件令牌。禁用后再恢复，不会使旧 Cookie 重新有效。管理员修改自己的邮箱后也需要重新登录。
- 两个请求使用同一 revision 时最多一个成功。账号修改、学籍同步、会话撤销和审计在同一 D1 batch 内完成，并重新验证操作者会话。

种子中的演示人员没有登录凭据，不能作为正式账号直接修改学工号；正常账号由建号接口建立。种子数据的用途仍是课程关系和权限开发验证。

审计保存操作者 ID、目标 ID、动作、变更字段名称、时间，不保存密码、令牌、邮箱或学籍字段的旧值／新值。邮件验证和找回记录的 actorId 为 null，表示通过邮箱证明完成的操作，不冒充管理员。

## 个人资料与学籍

| 方法、路径 | 权限及输入 | 返回／行为 |
| --- | --- | --- |
| `GET /api/me/profile` | 登录 | 本人完整资料，包含自己的私有字段和 revision |
| `PATCH /api/me/profile` | 登录；revision、publicName | 只修改公开名称，未知字段拒绝 |
| `GET /api/profiles/:id` | 匿名 | 仅 id、publicName、avatarUrl；禁用或不存在返回 404 |
| `PUT /api/me/avatar` | 登录；图片原始二进制；If-Match 请求头 | 上传本人头像 |
| `DELETE /api/me/avatar` | 登录；If-Match 请求头 | 删除本人头像 |
| `GET /api/profiles/:id/avatar` | 匿名 | 当前有效头像；无头像或账号禁用返回 404 |
| `GET /api/courses/:courseId/students/:studentId/academic-record` | 当前学期该课程教师 | 仅 accountId、studentNumber、realName |

头像请求示例头：`If-Match: "3"`，其中 3 为本人当前 revision。支持 PNG、JPEG、WebP，最大 2 MiB，Content-Type 必须匹配文件签名。不接受 SVG、远程 URL 或客户端指定 R2 键。这里做类型和大小检查，不进行图片重编码或恶意内容扫描。前端应在上传前裁剪和压缩图片。

头像仅存私有 R2，通过 Worker 读取当前数据库引用；响应禁用缓存并设置 nosniff 和受限 CSP。失败上传、未引用对象记录在 `avatar_objects` 中；正常替换或删除立即清理旧对象，清理失败不把已完成的更新误报为失败。运行 `pnpm avatars:cleanup:local` 可清理超过一小时的未引用对象，每次最多 100 个；云端清理调度属于部署任务。

学生不能借助指定他人 ID 读取学籍；教师也不能读取历年学生或其他课程学生，权限不足和目标不存在统一返回 404。该接口不返回邮箱，不授予教师编辑学籍的权限。管理员通过账号详情维护学籍。

## 邮箱验证与密码恢复

| 方法、路径 | 输入／权限 | 行为 |
| --- | --- | --- |
| `POST /api/auth/email/verification` | 登录；无请求体 | 向本人由管理员设置的未验证邮箱发送验证邮件 |
| `POST /api/auth/email/verify` | token；无需登录 | 验证邮箱，一次性消费链接 |
| `POST /api/auth/password/forgot` | email；无需登录 | 符合条件时发送重置邮件，统一返回 202 |
| `POST /api/auth/password/reset` | token、newPassword；无需登录 | 重置密码、撤销所有旧会话，清除当前 Cookie |

管理员先设置邮箱，用户登录后请求验证并完成邮箱验证，之后才能用该邮箱找回密码。**唯一管理员也必须在能够登录时给自己设置并验证邮箱**。没有已验证邮箱时不能使用邮件恢复；本轮不增设绕过邮箱验证的匿名入口或离线重置命令。

重置请求对不存在、未验证、已停用和符合条件的邮箱返回相同 202 文案；发送失败也不通过该公开接口暴露邮箱是否存在。202 表示收到请求，不保证实际投递。管理员需在邮件服务侧排查真实投递情况，客户端可在限流窗口后重试。邮箱验证接口在发送失败时返回通用 503。

邮件令牌为 256 位随机值，数据库只存 SHA-256 摘要；30 分钟过期、只使用一次。令牌同时绑定用途、邮箱版本和凭据版本，不能把验证邮箱链接用于重置密码。重发后以最新签发链接为准。邮箱变更、账号禁用、主动改密或成功恢复后，旧链接失效；并发使用同一重置链接最多成功一次。恢复后正常登录，不引入首次登录强制改密。

邮件链接为 `${PUBLIC_ORIGIN}/verify-email#token=...` 或 `${PUBLIC_ORIGIN}/reset-password#token=...`。token 放在 URL fragment 中，不进入 HTTP 访问日志或 Referer；前端读取后应立即移除 fragment，通过 JSON POST 提交，禁止写入日志、分析事件或 localStorage。相关页面尚未包含在当前仓库，直接打开路径暂不会出现恢复页面；后端测试通过对应 POST 接口完成流程。

限流：邮件相关接口同一来源每 15 分钟最多 30 次；请求验证邮件每账号最多 3 次；请求找回每邮箱最多 3 次。local 共享一个来源桶。密码仍采用已有至少 12 字符、UTF-8 不超过 72 字节的技术策略。

## 本地邮件与云端边界

local 使用模拟 R2 的私有 `local-mail/` 前缀存放邮件，不发送真实邮件，也不把邮箱、正文或令牌输出到终端。执行：

```sh
cd backend
pnpm db:migrate:local
pnpm mail:local
```

模拟邮件导出到被 Git 忽略的 `backend/.local/mail/`，文件权限为 0600，可在本机查看邮件内容并用前端或本地测试调用确认接口。目录可能含可用的测试重置令牌，不上传、不提交、不复制到公共日志；按需自行清理。

云端适配当前使用 [Resend 发送接口](https://resend.com/docs/api-reference/emails/send-email)，实现与业务流程分离。需要 `RESEND_API_KEY` Secret、`EMAIL_FROM` 已验证发件地址，以及与前端一致的 HTTPS `PUBLIC_ORIGIN`；不从请求 Host 构造链接。不配置这些值时邮件发送入口返回 503。local 仅需 PUBLIC_ORIGIN，默认后端地址，前端初始化后可调整到其同源访问地址。

本轮未配置真实邮件服务、域名或 Secret，未发出真实邮件、未部署云端。适配器的失败处理通过测试替身验证；实际投递、发件域名及云端配额需单独联调。参考 [R2 Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)。

## 数据与模块影响

新增迁移 `0003_account_management.sql`，旧迁移保持不变。accounts 新增 revision、avatar_key；新增 account_private、account_audit、email_tokens、avatar_objects。迁移会补齐现有账号的私有资料，并从原学生表复制姓名。

`credentials.school_number` 与 `student_records.student_number`、`account_private.real_name` 与 `student_records.real_name` 是需要同步维护的字段，组员 1 的管理接口以同一事务维护它们。其他模块不要直接更改这些字段。

组员 2：新增账号管理／本人资料 DTO、修改版本参数、头像二进制上传，以及两种邮件确认页。原 `/api/auth/me` 的字段保持不变。公开资料助手增加 avatarUrl，不增加私有字段。

组员 3、4：仍引用 accounts.id，继续由服务端会话取得操作者；不将管理员账号详情或本人资料作为公开作者数据。账号被停用后，原会话不再通过认证。资料文件的上传、版本、下载及审核规则由组员 4 实现，不复用头像入口代替资料接口。
