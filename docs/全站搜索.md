# 全站搜索

全站搜索通过 `GET /api/search` 读取 D1 中当前公开的课程、资料、问题和回答，前端入口为 `/search`。不需要登录；登录用户、所有者与管理者使用相同的公开可见性，不在搜索中混入私有维护或审查数据。

## 搜索范围

| 类型 | 关键词匹配字段 |
| --- | --- |
| 课程 | 课程号、名称、简介 |
| 资料 | 标题（即公开文件名）、简介、标签 |
| 问题 | 标题、正文、标签 |
| 回答 | 回答自身正文 |

回答展示所属问题标题，并继承问题标签用于标签筛选；问题标题、标签不参与回答的关键词召回。一个资料无论有多少文件版本都只返回一项。评论、历史版本名、PDF/Office 内文、OCR、图片地址、链接地址和公式源代码不在本版范围内。

关键词去除首尾空白，将连续空白合并为一个空格，最多100个 Unicode 字符、8个空白分隔词。多个词取交集，可以分别命中不同字段；每个词按连续子串匹配，支持单个汉字与中文短词，ASCII 字母忽略大小写，`%`、`_` 为普通字符。空关键词返回空列表，不列出全站内容。

## 接口与排序

`GET /api/search?q=积分&type=question&course=MATH101&tag=复习&sort=relevance&page=1&pageSize=20`

| 参数 | 规则 |
| --- | --- |
| q | 关键词，规则见上文 |
| type | all（默认）、course、material、question、answer |
| course | 精确课程号，格式与课程接口一致 |
| tag | 去首尾空白，最多30个 Unicode 字符，按标签子串匹配；不兼容 type=course |
| sort | relevance（默认）或 updated |
| page | 1–10000，默认1 |
| pageSize | 1–50，默认20 |

不合法的关键词或筛选返回400。所有筛选在统计与分页前执行。相关度先比较完整查询是否恰好等于课程号或标题；之后按每个词的最高命中字段累加权重：课程号/标题100、标签10、正文1。同分按 updatedAt 倒序，再按类型和 ID 排序。updated 模式仅按更新时间、类型、ID 排序，结果具有稳定的分页顺序。

成功响应为 `{ data: { items, total, page, pageSize, q, type, sort } }`。每项包含类型、ID、标题、摘要、标签、课程、所属问题 ID、更新时间、公开作者和高亮区间；不返回完整正文 JSON、真实姓名、学号或邮箱。删除账号的作者只显示“已删除”。摘要围绕最早命中正文截取最多160个 Unicode 字符，前后省略号另计；没有正文命中时使用开头。高亮区间是原字符串的 UTF-16 半开区间，前端使用普通文本与 `mark` 渲染，不使用 HTML 注入。

## 数据与可见性

课程简介直接检索；资料、问题、回答的 ProseMirror 正文提取到 `contents.body_text`。提取器连接行内文本、在块间保留词边界，只读取实际文字，不把 JSON 属性或合成标签当成正文。保存全文，摘要在查询时生成。

发布问题/回答、确认首次资料上传和编辑正文时，在同一次内容写入中维护 body 与 body_text；仅改标题不会覆盖正文派生值，资料发布新版本不会新增搜索条目。评论的 body_text 保持为空。删除触发器同时清空派生正文，包括上级删除引起的级联删除；上下架保留派生文字，由查询可见性控制召回。

内容来源是 `public_contents`，自身或祖先隐藏、删除的结果不出现，管理者和所有者也不能通过搜索读取；恢复后重新按当前分支状态参与搜索。搜索返回后内容仍可能发生变化，详情与文件入口继续独立检查可见性。计数和结果查询不提供跨请求或跨页快照。

## 升级与历史数据回填

`0011_global_search.sql` 增加 body_text，默认空字符串，并安装删除清理规则。它不在 SQL 迁移中转换旧正文。已有数据库的上线顺序是：

1. 对目标库应用完整待执行迁移。
2. 启动包含正文同步写入逻辑的新后端，停止旧版本写入。
3. 对同一目标运行回填，再运行只读检查；检查通过后开放搜索入口。
4. 若检查发现并发旧数据或不一致，重新回填并检查。不要通过清库或重建演示数据完成升级。

在 `backend/` 执行：

```sh
pnpm db:migrate --local
pnpm search:backfill --local
pnpm search:backfill --local --check
```

本地命令可以添加 `--persist-to <隔离状态目录>`。远程命令必须显式选择配置文件，沿用[后端目标参数](../backend/README.md#命令与目标参数)，不会自动推断生产目标：

```sh
pnpm search:backfill --remote .local/remote.json
pnpm search:backfill --remote .local/remote.json --check
```

回填按 ID 每批50条读取未删除的资料、问题和回答，包含下架内容。只更新 body_text，不修改更新时间、作者、积分或流水；更新条件包含读取时的原始 body，保留并发正文编辑。重复运行安全，遇到不符合正文契约的数据会中止，已完成批次保留。输出 scanned、mismatches、updated；`--check` 不写入，有不一致时退出码为1。回填尚未结束时旧内容的标题、标签可以命中，但正文召回不完整。

本次实现只在隔离测试库应用迁移和回填，未操作日常开发库或远程库。

## 验证与后续扩展

搜索集成测试覆盖中文短词、多词、字面特殊字符、长正文、富文本提取、高亮、权限、级联删除、编辑和资料版本，以及回填幂等和并发保护。迁移测试验证旧库数据保留及结构一致性。前端使用 URL 保存查询状态，复用 Tabs、分页、课程接口和回答定位路由，覆盖加载、无关键词、无结果、失败重试与过期响应取消。

本地探针每个场景预热后采样20次：10000条合成内容中，单字、双字、多词、无结果和课程/标签筛选的完整 API P95 为225–294 ms，第40页查询为395 ms；两条 SQL 合计 rows_read 约9万–15.6万。该样本含5%下架内容，约10%的正文接近1万字，其余约400字。

首版采用 D1 子串扫描，没有引入独立搜索服务。性能探针使用本地 Miniflare、1000/10000条合成内容、短词/多词/筛选/深分页，记录完整 API 延时和 D1 rows_read；本地结果不能代表远程并发、网络或账单表现。随着数据和访问量增长，应依据实际 rows_read 与延时评估分词索引或独立引擎，保留当前 API 与公开可见性契约。
