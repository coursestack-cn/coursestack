# 技术栈和开发

本方案承接技术栈讨论，用于组内提案。团队主要熟悉 JavaScript，项目要求至少使用一个关系型数据库，当前方向为 TypeScript 与 Cloudflare Workers、D1、R2，并使用 Drizzle 访问数据库。仓库尚未初始化应用工程，框架和工具的具体版本在组内确认后确定。

## 技术方向

| 部分 | 当前方向 | 作用与状态 |
| --- | --- | --- |
| 开发语言 | TypeScript | 前后端统一语言，按 Workers 运行环境选择后端依赖 |
| 应用运行 | Cloudflare Workers | 执行后端接口、身份权限校验和业务逻辑 |
| 关系型数据库 | Cloudflare D1 | 保存账号、课程、修读关系、问答、加分、通知及文件元数据 |
| 文件存储 | Cloudflare R2 | 保存 PDF、图片、Office 文档等实际文件，使用私有桶 |
| 应用框架 | SvelteKit，或前端框架配 Hono | 两条候选路线，尚未最终选定 |
| 数据访问 | Drizzle | 已确定，用于 D1 数据访问 |
| 开发工具 | Node.js 工具链、Wrangler、适合所选框架的 Vite 集成 | 团队统一版本、包管理器和启动方式 |

D1 使用 SQLite 的 SQL 语义，承担关系型数据存储。文件本体保存在 R2，D1 只记录文件名、大小、所属资料、版本和存储键等信息。[D1 官方介绍](https://developers.cloudflare.com/d1/)

应用框架仍有两条路线：

- SvelteKit 统一承担页面和服务端接口，按其 Cloudflare 适配方式开发。[SvelteKit 适配器](https://svelte.dev/docs/kit/adapter-cloudflare)
- Vue、React 或 Svelte 配合 Vite 构建前端，Hono 提供 Workers 后端接口，通过明确的接口协作。[Hono Workers 文档](https://hono.dev/docs/getting-started/cloudflare-workers)

当前分工要求前后端明确接口边界，但不据此直接确定框架。数据访问确定使用 Drizzle，围绕 D1 验证关键业务流程的一致性。[Drizzle D1 文档](https://orm.drizzle.team/docs/sqlite/connect-cloudflare-d1)

## 数据与文件流程

### 关系型数据

- 数据库总体设计统一协调，各业务负责人实现自己的查询、数据修改和接口校验。
- 账号、授课关系、修读关系、课程与学期需要共同支持权限判断。
- 采纳、取消或更换采纳、加分调整需要按最终业务规则保持一致，并防止重复计分。
- D1 的 `batch()` 支持多条语句的事务批处理，失败时整体回滚；仍需验证并发、重复操作及业务条件，不能仅凭使用批处理就认定流程正确。[D1 批处理文档](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)

### 文件上传与访问

- 后端检查上传权限，为浏览器生成短时有效的预签名 URL。
- 浏览器直接上传到 R2，后端核验上传结果后再发布资料版本；浏览器直传需要配置桶的 CORS。[R2 预签名 URL 文档](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)
- 每个文件版本使用独立的存储键，D1 维护版本关联，旧问题始终指向原版本。
- 预览与下载由 Worker 检查用户权限和内容状态后提供文件，私有桶不直接作为公开下载入口。
- 上传失败、未完成上传和数据库记录不一致的情况，需要有明确的清理或恢复方式。

## 开发环境

| 场景 | 运行与存储 | 用途 |
| --- | --- | --- |
| 日常业务开发 | 本地 Worker、本地 D1；需要时使用本地 R2 模拟 | 账号、课程、问答等功能开发 |
| 文件联调 | 本地 Worker、本地 D1、独立的云端开发 R2 桶 | 验证真实上传、预览、下载、签名和 CORS |
| 云端测试 | 测试环境 Worker、独立的测试 D1 和 R2 | 多人联调和上线前验证 |
| 正式运行 | 生产 Worker、独立的生产 D1 和 R2 | 实际用户使用 |

Wrangler 和 Cloudflare Vite 插件提供本地 Workers 开发环境，可使用本地模拟资源，也可按绑定连接远程资源。开发入口依据最终框架确定。[本地开发文档](https://developers.cloudflare.com/workers/local-development/)、[Wrangler 与 Vite 的选择](https://developers.cloudflare.com/workers/local-development/wrangler-vs-vite/)

文件联调沿用正式的浏览器直传流程。预签名配置和 Worker 的远程 R2 绑定需要指向同一个开发桶；浏览器访问签名 URL 与 Worker 访问存储绑定是两条路径，设置 `remote: true` 不会自动修改签名目标。这个开发安排是针对项目的选择，首版暂不另设一套离线上传流程。

团队共享数据库结构、迁移和初始化数据脚本，各自生成本地开发数据。配置中明确区分开发、测试与生产资源，本地运行数据和真实密钥不提交到仓库。初始化工程时统一依赖版本、绑定类型、兼容日期、环境配置示例和开发命令，并准备日志及 Workers 运行环境下的功能验证方式。

网络运维由我负责，统筹 Cloudflare 资源、开发与测试环境配置、部署及运行维护。各模块负责人配合接口和资源联调。

## 搜索与通知的首版实现

搜索先覆盖功能列表中列出的数据库文字内容，并验证中文搜索效果。站内通知先保存为数据库记录，通过轮询更新列表，后续再按实际需要调整。

## 费用考虑

**省流：不用花钱，除非你们的 Agent 搞砸了，请求了一个晚上的东西，正常使用的话就算花了钱也很少，我自己给就行了。**

本地模拟与云端联调分别计算用量：本地模拟不消耗云端存储，连接云端开发桶则按正常规则计费。[远程绑定与计费](https://developers.cloudflare.com/workers/local-development/#important-considerations)

截至 2026-10-21，R2 Standard 每月包含 10 GB-month 存储、100 万次 A 类操作和 1,000 万次 B 类操作免费额度；超出后的单价分别为 0.015 美元/GB-month、4.50 美元/百万次和 0.36 美元/百万次。R2 出网流量免费，读取请求仍计数，计费单位向上取整。[R2 官方定价](https://developers.cloudflare.com/r2/pricing/)

四人团队开发时可以先以控制在免费额度内为目标，定期清理测试文件，并把保留的历史版本计入存储量。实际预算还需包含 Workers、D1 及其他使用的服务，部署前按选定套餐和预计用量核对。
