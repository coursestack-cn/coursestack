# CourseStack

CourseStack 是一个面向校内课程的资料共享与问答平台。师生围绕课程整理资料、提出问题、分享解答，让资料和讨论跨学期积累；教师通过内容管理、答案采纳和可配置的课程加分参与教学。

**项目目前处于需求设计阶段，尚无应用代码。** 本简介以最近的项目讨论为主，汇总当前方向；早期需求文档中的自行注册、课程名单导入和学籍信息公开规则尚待同步。

## 账号、课程与学期

系统面向一所学校，由管理员统一建立教师和学生账号，取消用户自行注册。管理员账号在初始化时预置，师生身份与学籍信息由受控的账号管理流程维护。

教师可以新增课程或加入已有课程，一门课程可以由多名教师共同教授。教师通过学生名单批量建立本学期的修读关系，这是核心功能。学生的课程入口分为三组：

| 分组 | 含义 |
| --- | --- |
| 本学期课程 | 学生在本学期正式修读、通过课程学生名单加入的课程 |
| 历年课程 | 学生过去修读的课程；每学期结束后，系统自动将对应的本学期课程归入此处 |
| 关注的课程 | 学生没有修读、但主动关注并希望查看动态的课程 |

课程本身长期存在，学期归档针对学生的修读关系，资料和讨论可以持续复用。关注用于组织个人学习入口，不等同于正式修读，也不是访问站内共享内容的前提。

## 公开身份与学籍隐私

公开讨论中的名称与真实学籍信息分开，减少学生因实名顾虑而不愿提问的情况。

- 学生之间不能互相查看学籍信息，邮箱和学号不作为默认公开名称。
- 教师只能查看自己本学期所授课程中、本学期修读学生的学籍信息。仅关注课程、历年修读或其他课程的学生，不在该权限范围内。
- 学籍查看权限随当前学期的授课与修读关系生效；教师身份本身不赋予全站学生信息的查看权。

登录凭据、首次登录、忘记密码及邮箱绑定的具体流程仍待确定。内部账号标识等实现细节留到数据设计阶段。

## 资料与问答如何协作

- **资料支持版本。** 一份资料是一个文件组，可以持续上传新版本并保留更新说明和历史文件。收藏以文件组为对象，问题可以关联其中某个具体版本；发布新版本不会改变旧问题的文件关联。
- **围绕课程讨论。** 学生和教师都可以分享资料、提问、回答和评论，支持 Markdown/富文本内容及赞踩。教师资料和回答显示身份标识。
- **教师负责采纳。** 每个问题同时至多有一个采纳答案，采纳后置顶并标记已解决；其他回答按赞数减踩数排序。教师回答不会因身份自动被采纳或置顶，学生提问者没有采纳权限。
- **采纳可以带来课程加分。** 教师按课程配置是否启用及加分值，系统记录学生获得的加分和采纳来源。赞踩本身不产生课程加分，同一次采纳不能重复计分。
- **更新能够被追踪。** 用户可以搜索课程、资料和问题，收藏资料或讨论，通过站内信接收内容更新、回答、评论和采纳等通知。
- **内容由师生共同维护。** 用户维护自己的内容并可举报问题内容；课程教师负责本课程的审查、下架和恢复，管理员负责账号、权限与全站管理。

典型流程是：管理员建立师生账号，教师组织课程并导入本学期学生名单；学生使用资料并关联具体版本提问，师生共同回答讨论，教师采纳并按配置计分；资料更新后通知收藏者，学期结束后修读课程自动归入历年课程。

## 按九个板块推进需求

| 顺序 | 板块 | 主要内容 |
| --- | --- | --- |
| 1 | 用户账号与身份 | 统一建号、登录、个人信息、学籍维护、身份与隐私权限 |
| 2 | 课程组织与管理 | 课程信息、多人授课、学生名单导入、学期与修读关系管理 |
| 3 | 课程资料与文件版本 | 上传、分类、浏览、预览、下载、版本记录和教师资料标识 |
| 4 | 提问、回答与评论 | 内容发布与维护、具体文件版本关联、回复、编辑与展示 |
| 5 | 投票、答案采纳与课程加分 | 赞踩、排序、采纳与取消、解决状态、加分配置和记录 |
| 6 | 搜索与个人学习空间 | 搜索筛选、三类课程入口、收藏、动态及自己发布的内容 |
| 7 | 站内通知 | 更新与互动通知、已读状态、内容跳转、去重和订阅变化 |
| 8 | 举报、内容审查与站点管理 | 举报处理、审查、下架与恢复、账号权限及全站管理 |
| 9 | 系统通用要求 | 分页、异常反馈、防重复提交、权限校验、数据一致性与备份恢复 |

每个板块按“用户能做什么、条件和限制、异常或撤销时如何处理”展开。需求使用 `CS-USR-<id>` 编号，每个板块在 `用户需求/` 下单独维护一个 Markdown 文件。
